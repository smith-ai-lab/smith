# smith run and smith test

This skill ships in the smith plugin, from `.agents/skills/smith-run-test/SKILL.md` in https://github.com/smith-ai-lab/smith. Change it there. Writing tests is the smith-test skill; writing `build.c` is smith-build.

`smith run` and `smith test` act on what the project's `build.c` declares: the program is the default's, the tests are `smith_tests`'. There is no task to write and no list of files or programs anywhere else. A project with no build file (a `main.smith` or `main.c` at the root, `*_test.smith` and `*_test.c` files beside the modules they test) builds by convention: `smith run` runs `build/debug/<folder>`, and `smith test` runs every `*_test.smith` and `*_test.c` file below the root (the smith-build skill, "No build file").

## smith run

`smith run [<arguments>]` builds `smith_default` and runs the one program it names on the terminal (a `smith_program` output; other things in the default, such as links, are built but not run). Its arguments go to the program, so `smith run level2 --fast` runs `<program> level2 --fast`. `-D` options belong to the build (`smith run -DFONT=x`); `--` ends them, so `smith run -- -Dx` gives the program `-Dx`. When the default names no program or more than one, it says so and lists the default's targets: make `smith_default` name the one program (`smith build <other>` builds the rest).

## smith test

`smith test [<options>]` builds the test runner and runs it. It prints one line (`smith test: ok (4 passed, 0.2 s)`); a failure shows the runner's report (the failing test with its values) and `the full output is in .smith/log/test.log`; `-v` (the runner's `--verbose`) prints every test as it runs. `-k` (or `-k N`, ninja's keep-going: `-k` alone is `-k 0`, any number of failed compiles) is the build's: `smith test -k` compiles every test file and prints every compile error in one run, not the first file's. The other options are the runner's own:
- `--test <substring>` runs one test, or every test whose name contains it (a test in a `.smith` module is named as written, `geometry::box_test::area`, and `--test geometry::box_test` runs the module's tests; the source's `test_area` works as well); `--seed <n>` runs a property test on that one seed; `--seeds <n>` sets the keys per property test (100).
- `--jobs <n>` (default: the cores; `--jobs 1` is easier to follow), `--timeout <seconds>` (10 of CPU time per test, so load never fails a test), `--wall-timeout <seconds>` (the backstop for a blocked test, 10 times `--timeout`), `--idle-timeout <seconds>` (180: a test whose processes use no CPU time that long is killed and the report names the command it waited for; 0 for none), `--shrink 0|1`, `--shuffle <seed>`, `--shard <i>/<n>` (only part i of n, a test file whole in one part; `--costs <file>` of `cpu<TAB>seconds<TAB>name` lines balances the parts, the CI split, and starts the heaviest tests first; `--cheapest` the cheapest first), `--macos-only` / `--skip-macos` (only the tests that need macOS, or all the others; a test needs macOS when the word `macos` is in its name: `test_macos_kqueue_wakes`, or a `..._macos_test` module; Metal, Objective-C, the debugger, Mach-O), `--isolate` (a process per test), `--in-process` (no fork at all, for `smith dbg build/tests -- --test name --in-process`), `--full` (heavy checks at full size), `--trace`, `--color`, `--list`, `--fail-fast` (no test starts after one has failed; those running finish, and the rest are counted as not run), `--verbose`, `--stats` (the forks, then a line `cpu<TAB>seconds<TAB>name` for each test).
- A failure ends with the line to rerun it, such as `rerun: smith test --test name --seed 123`.

To debug one test: `smith dbg -- build/tests --test <name> --in-process` (the runner is the `runner` line of `.smith/build.info`; in Neovim with nvim-dap, start a session with the cursor in the test function; skill smith-debug).

In Neovim, the `neotest-smith` adapter ([neovim](../../../knowledge/neovim.md)) runs the nearest test as `smith test --test <name> --verbose`, a `.smith` module's file as `--test <module>::`, a `.c` file and the suite as `smith test`, and shows a failure at its check's line; the dap strategy debugs the nearest test as above.

- `--changed [--base <ref>] [--dry-run]` runs only the tests a diff reaches: the test files that changed or import (or include) something changed, and what the records say (below); a changed `.md` selects the tests whose source names `.md`; a few files (`smith.c`, `runtime/lang*`, `build.c` outside a task that no test runs), and any changed path no test names, no record names and nothing imports run everything (a changed data file, such as a workflow or a fixture, selects the tests whose source names it or its folder). It prints the tests it selected and why. `--dry-run` lists them and runs none. `--cheapest-first` starts the selected tests in order of the cpu seconds their records hold (a test with no record first; runner option `--costs <file>` of `cpu<TAB>seconds<TAB>name` lines, which `--stats` prints), so a timeboxed run with `--fail-fast` meets the cheap failures first. `--list [<base> [<head>]]` prints only the selection on stdout (and a summary on stderr; no `-v` needed; a selection of any size is printed whole), one entry per line (a test name, `module::` for a module's tests, or `*` when every test runs), runs nothing, and with a `<head>` compares `base..head` instead of the working tree (imports and records are still read from the working tree). `--base` is the ref to compare with (default: where the branch left `origin/main`). `--test a::,b::` takes several comma-separated names.
- **Records.** `--changed` builds the tests and the programs they start with line counters (the debug profile with `-fprofile-instr-generate -fcoverage-mapping`; a plain `smith test` or `smith build` is not instrumented, so switching between them rebuilds the debug objects). Each test it runs leaves `.smith/records/<test>.rec`: the functions it ran in every process it started, with a hash of their source, its headers and `build.c`, and whether it passed. The first run, with no records, runs every test once. After that, besides the tests the imports reach, a test runs when it failed last time, a function it ran changed, its headers or `build.c` changed, or it has no record, so an end-to-end test that starts your program is found though nothing imports its code. A record also lists the files a test opened through `io::files_read`, `files_map` and `files_list` (in the runner and in the smith it starts) (a test that gives a process a repository file copies it with `scratch::copy_tree`, which opens through `io`): a changed file selects the tests that opened it and no other (a file added to a folder a test listed selects that test), in place of the whole test file that names it. Git is needed only for the diff. A `coverage-fetch` task in `build.c` may bring records from elsewhere (CI).

Examples: `smith test --changed --dry-run`, `smith test`, `smith test --test v3`, `smith test --test prop_v3 --seed 8022860619270860748`, `smith test --full`.

## When it goes wrong

- `smith run: the default of build.c names no program` / `more than one program`: `smith_default` must name exactly one `smith_program` output (aliases are opened); it lists what it names.
- `smith test: the build declares no tests`: the build calls no `smith_tests`; add it (the smith-test skill). A task of your own that should run with `smith test` sets `.test = true`.
- `this verb was given arguments, but build.c does not read them`: `smith test` was given arguments and build.c calls no `smith_tests` (the runner reads them through `smith_args(b)`).
- `build.c: task 'run' is named after a verb`: no task or alias is named `run`, `test`, `check`, `fmt`, `lint`, `docs` or `prove`; the verb does it, or name the task another way and run it with `smith build <name>`.
- `test is a verb, not a target of smith build`: `smith build run|test|check|fmt|lint|prove|docs` are refused. Use the verb.
- `no build.c in this folder, and no main.smith or main.c to build by convention`: run it from the project's folder, or add a `main.smith` or `main.c`.
- The old `-DTEST=`, `-DSEED=`, `-DJOBS=`, `-DFULL` options are gone; use the runner's options.
