# Effects

A function does something to the world or it does not. smith works out which from the body and every function the body calls, and checks what you promise:

```smith
module stats;
import <stdlib.h>;
import <string.h>;

export [[std::pure]] i32 length(const char *text) {   // strlen touches nothing: pure holds
    return (i32)c::strlen(text);
}

export [[std::effects(alloc)]] void *grab(u32 size) { // may allocate, and nothing else
    return c::malloc(size);
}

export void *plain(u32 size) {                          // no attribute: inferred (it allocates)
    return c::malloc(size);
}

i32 main() {
    return length("abc") - 3;
}
```

A function with no attribute is inferred and never an error. `[[std::pure]]` says it does nothing at all, `[[std::effects(alloc, net)]]` that it may do those and nothing else; a call that brings in an effect past the promise is an error at the call, with the chain:

```text
stats.smith:9:5: error: smith-effect: `bad` is [[smith::pure]], but it has the effects console, globals: bad -> log_it (stats.smith:9) -> printf (stats.smith:6)
```

## Rules

- **The effects**: `fails` (below), `alloc` (malloc, free, mmap), `files`, `net`, `console`, `clock` (time, sleep), `process` (fork, exit, threads), `env` (getenv, uname), `entropy` (arc4random), `globals` (writing a global or a function-local `static`), `code` (making memory executable: `mmap` or `mprotect` with a constant protection that has `PROT_EXEC`, which also keeps its `alloc`) `tasks` (starting a task; its handler is the scheduler, so a `[[smith::pure]]` function cannot spawn; a declaration says it with `[[smith::effects(tasks)]]`, no libc call carries it) and `unknown` (what smith cannot see into: a call through a function pointer, an unknown system function, a symbol nobody defines). Allocation is an effect.
- **`fails`**: a function has it when it contains a failure point or calls a function that does: a checked slice index or bound, `contract::assert` and the other contracts' run-time checks, an arena out of capacity, `abort`, `__builtin_trap`, any `smith_failure*` call. Most functions have it; its value is where it is forbidden: `[[std::pure]]` and `[[std::effects(alloc)]]` reject it (write `[[std::effects(fails)]]`, or `alloc, fails`), `effects::within(f, effects::none)` rejects it, and the error names the chain (`mix -> lookup (audio.smith:30) -> smith_failure`). It is also inferred across files. Arithmetic traps of a sanitizer are not found (they are not in the source). A checked index or cut, `contract::assert`, `ensures` or `invariant` that `smith prove` proved (smith-prove) adds no `fails` in any build, debug and the editor included (a ceiling's verdict never depends on the build: debug keeps the check, under a name that is no failure point); a `requires` always counts. `smith prove`'s own compile does not judge `fails` ceilings (it keeps every check to prove them); every build's compile still does, after the proofs are known.
- **Across files**: each compile leaves a summary of its object (in a project under `.smith/effects/`, otherwise `main.o.fx` beside it) and the link of objects that have one (`smith-cc a.o b.o`, so `smith build` too) checks the calls that cross files, in C and in modules: an unannotated function of another file is inferred, and a function no file defines is `unknown`. A call to a function declared in your project with no body in the file adds nothing at compile time and is judged at the link; an error found only then names the chain through the files and stops the link.
- **What a body reaches**: the calls of the file and the headers it includes, followed to a function of libc or libSystem (a table of smith's gives each its effects) or to a call the file cannot see into: a call through a function pointer and an Objective-C message are `unknown`, and so is a function declared in a system header that the table does not know. **Inline assembly is read by LLVM's assembler** (the host target's; a block it cannot read is `unknown`): no system call and no call or jump out of the block is no effect (SIMD, atomics, a counter, a barrier); a system call (`svc`, `syscall`) has the effects of the libc function its number names in the table of that OS and CPU (Linux x86-64 and AArch64, macOS arm64), the number being a constant the block loads, a register variable (`register long x8 asm("x8") = 64;`) or an operand holds, and `unknown` when it is not a constant or not in the table; a call or jump to a named symbol has that symbol's effects, through a register `unknown`.
- **The promise is what a caller sees**, not the inferred set. Recursion is no effect (it is an error, below). On a declaration with no source (a prebuilt library's header) the same attribute is a promise smith trusts: `[[std::effects(alloc, net)]] int curl_perform(void *handle);`.
- **The fix**: an effects error carries a fix-it (a quick fix in the editor, `(fix available)` in `smith lsp --check`) that replaces the function's effects or pure attribute with `[[smith::effects(...)]]` (the message and the fix-it still say `smith::`; `std::` is the same attribute) holding the whole set it needs (declared and inferred), never adding a second.
- **Names are as written**: the link's error names functions as the source writes them (`bad`, `fx::lib::noisy`, a module's private `shout`), never as the lowering named them (`main_bad`): each summary carries the written name.
- **In the editor**: `smith lsp` judges the calls between files too, with the summaries the build made (`.smith/effects/`): an open file shows the link's error and chain at the call. Saving a file writes its summary in the build's place and has the other open files parsed again (clangd's `forceRebuild`, no text is sent), and a first pass in the background makes the summaries that are missing or older than their source, one at a time, then parses the open files again. While that pass runs a function no summary defines is not judged yet. The editor may briefly be out of date; the link decides.
- **libc's hidden state is `globals`**: `strtok`, `localtime`, `getenv`, `setlocale`, `rand`, `dlopen` and all of stdio (the buffers) have it, and so does a printf-family call (`printf`, `snprintf`, `fprintf`...) whose format is not a literal or has a float conversion (`%f %e %g %a`): `snprintf(b, n, "%d", i)` stays pure, `snprintf(b, n, "%f", x)` is `globals`.
- **A returned libc pointer has an idiom** in smith's table (`shim/effects_table.h`): `owned:free` (`strdup`, `malloc`), `owned:fclose` (`fopen`), `borrowed:1` (`strchr`: points into argument 1) or `internal` (`strerror`, `getenv`: never freed). In a module, calling a system-header function that returns a pointer and has no entry is `error: smith-ownership: 'f' returns a pointer and the C library table gives it no idiom`; the fix is a line in the table.
- **Null-keyed idioms**: `owned:<f>:<n>` calls `f` with the pointer and then argument `n` of the call (`mmap`: `owned:munmap:2`). `getcwd`, `realpath`, `tmpnam`, `ctermid` allocate or return static memory when the buffer is null: in a module pass an array, `&x` or a literal (the buffer form) or `nullptr` (the null form), else `error: smith-ownership: 'getcwd' allocates when its argument 1 is null ...`.
- **Where it is checked**: in the compile of a file, whenever a function carries an attribute (in a module, in a `.smith` file with no `module` line and in C), and in the editor.
- **No recursion in a module**: a call on a cycle of the module's functions (`fib` calling itself, `is_odd` and `is_even` calling each other) is a compile error naming the cycle, `fib -> recursion::fib (recursion.smith:7)`. Write a loop, with an explicit stack when you need one. A cycle whose every call is `[[clang::musttail]] return f(...);` is allowed: a jump is a loop. A call through a function pointer, or into code with no source, is not followed. C and a `.smith` file with no `module` line are left alone.
- **Proof code is exempt** (no attribute, no name): a function with internal linkage that is called only inside the argument of a check `smith prove` proved, or by other such functions, has no effects on the checking function and may recurse, so a proof can use a recursive helper. A check that is not proved runs, so the function it calls keeps its effects and its recursion error; so does one that running code also calls.
- **Worst-case stack**: linking objects compiled by smith (`smith build`, or `smith cc a.c b.c -o p`) writes `<program>.stack` beside the program: one tab-separated row a function, `name`, its stack and the deepest path (`f -> h -> g`). Frames are the backend's own (the numbers of `-fstack-usage`, which smith asks of every compile to an object and removes after reading). A cycle of musttail calls takes no more; any other recursion (C allows it) and a frame that grows at run time (`alloca`, a variable-length array) are `unbounded`. A call into code with no source (printf, a pointer call, a prebuilt library) cannot be measured: the row says `at least N + unknown (calls: printf, qsort)`, and a runtime decides what an unknown is (no number is added, and nothing in the build reads an environment variable). The header lines say the build the numbers are for (`opt=0 address undefined`): a runtime reads the file of the build it runs.
- **Asking about a function you are given**: a generic that takes a function (`constexpr auto f`) states what it allows with `import std::effects;` and `static_assert(effects::within(f, effects::alloc), "gradient: f may only allocate");`. The masks (`effects::none`, `alloc`, `files`, `net`, `console`, `clock`, `process`, `env`, `entropy`, `globals`, `unknown`, `fails`) are `u32`, so `effects::alloc | effects::files` is a set. That is the only way to ask, and only inside a `static_assert`: there is no `effects::of` and no `effects::pure` (`within(f, effects::none)` says pure), and anywhere else `within` is true and checks nothing. The effects exist only after the file is read, so smith judges the assertion then: a function of the file at once, one of another file at the link. The error shows your message, the effects and the chain (`viaNoisy -> noisy (a.smith:23) -> printf (a.smith:18)`), with a note at the call that instantiated the generic. A function with no source and no attribute is `unknown`, so `within` rejects it.
- **Promises**: what smith trusts and does not check is a function with an effects attribute and no source (a prebuilt library's header) and a function that calls `contract::trusted()`. `smith check` ends with `smith check: promises: N`, and `smith check -v` lists each as `file:line name`. `smith check` builds first if it must, so the summaries (`.smith/effects/`) are fresh; a header's promise counts once, and smith's own generated files under `.smith/` are left out.
- **What a returned pointer means** (#720): `[[std::returns_owned(free)]] char *strdup(const char *s);` (the caller frees it with `free`, a declared function of one pointer), `[[std::returns_borrowed(1)]] char *strchr(const char *s, int c);` (points into parameter 1, a pointer or a slice), `[[std::returns_internal]] char *strerror(int e);` (never freed). On a function that returns a pointer or a slice, one per declaration; on a function pointer's typedef write it first (`[[std::returns_internal]] typedef char *(*Describe)(int);`) or as `[[clang::annotate_type("std::owns:internal")]]` after the parameters. A bad use is `error: smith-ownership: ...`. Today it is recorded (`O` and `T` lines of the `.fx` summary) and nothing is judged. In a module write `free`, not `c::free`.
