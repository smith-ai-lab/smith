# Write Smith, not C renamed

A `.smith` file is C, so a renamed `.c` file compiles and means what it meant. That is the first step of a port and never the last: a module that still has the standard C types, an `#include`, a `#define` or a `sizeof`/`alignof` passed to a function is not done. The libraries `lib/std/arena.smith`, `random.smith`, `text.smith` and `build.smith` in smith's repository are the reference; read one before writing a module.

## The rules

Each rule says what enforces it today. "Review" means nothing checks it: you and the reviewer do, with the counts below.

1. **Sized types.** `u8 u16 u32 u64`, `i8 i16 i32 i64`, `usize`, `isize`, `f32`, `f64`, `bool`; `char` stays `char` (`smith-lang-sized-types`).
   - Not `uint32_t`, `size_t`, `ptrdiff_t`, `unsigned`, `float`, `double`.
   - Enforced by: `smith lint` and the editor, through the clang-tidy check `smith-sized-types`, which reports each C spelling (`uint64_t`, `size_t`, `unsigned long`, `double`, `int`...) with the sized type to write; `char` stays, and `main` is `i32 main(i32 argc, char *argv[])`, with no exception. The compiler accepts both spellings, so a `.c` file renamed to `.smith` with `int main(int argc, char **argv)` still builds and the check reports it, since they are the same types.
2. **Import C headers, never include them.** `import <math.h>;` and write `c::sqrt(x)`, `c::EOF`, `struct c::stat` (`smith-lang-c-interop`).
   - A `c::` name that is a C **macro** (`c::assert`, `c::SIZE_MAX`, `c::isfinite`, `c::INFINITY`) is the preprocessor too. The module that wraps the C API provides it as a function or a constant: `contract::assert(c)`, `math::max(usize)`, `math::is_finite(x)`, `math::infinity(f64)`, `math::nan(f32)`, `math::sqrt(x)` and `math::abs(x)` (`smith-contract`, `smith-math`). A macro of a library that has no module yet is written as the function the library has (`__builtin_snprintf`) or waits for the module. In the macOS SDK `c::snprintf` and `c::vsnprintf` are macros (the fortified versions): write `__builtin_snprintf` and the like. Memory is `mem::copy(dst, src)`, `mem::move`, `mem::zero(xs)`, `mem::fill(xs, v)` and `mem::equal(a, b)` on slices, never `memcpy` and its kin: the check `smith-mem` reports them in a module (`smith-mem`).
   - Enforced by: `smith lint` and the editor, through the clang-tidy check `smith-preprocessor` (rule 5), which reports an `#include` and every `c::` name that is a macro, with what to write; and the compiler for a bare name that an `import`ed header declared (`` `sqrtf` is a C name; write `c::sqrtf` ``).
3. **Modules import modules.** A library that is a module is used with `import std::arena;` and `arena::push(...)`, not with its C header (`smith-lang-modules`). A project's own `.smith` files are modules too: `module rolls;`, `export`, `import rolls;`, with no header written by hand (`smith build` writes it for C callers).
   - Enforced by: the compiler for private names (`is private; export it`) and for import cycles; `smith lint` and the editor, through `smith-module-library`, for a library that is a module used through its C header (`import <smith/arena.h>;`, `c::smith_arena_push`, `c::SmithArena`), with `import std::arena;` and the module's name to write (a named instance of a generic, `c::smith_check_equal_i32`, also points to the generic: `test::check_equal(a, b)`).
   - **Name a type by its tag.** In a module `struct Point {...};` is the type `Point`, also inside its own body and after `struct Node;`; write no `typedef struct {...} Point;` of the same name (`smith-lang-modules`). Enforced by: review.
   - **Every `.smith` file is a module**: `module main;` in `main.smith`, `module primes;` in `primes.smith`, `module primes_test;` in `primes_test.smith`, beside `primes.smith` (tests are `export`ed, since a private function is static and the runner calls them from outside), `module build;` in `build.smith` (`export void build(build::Build *b)`). Write the type argument of a generic call, `test::check_equal(a, b)`, as the templates do. `smith lint` and the editor, through `smith-module`, name the line to write from the file's path; the compiler never refuses a file with no module line, so renaming a `.c` file to `.smith` still compiles.
4. **Generics where C passes a type as `sizeof` and `alignof`.** `arena::push(&a, Foo)`, not `smith_arena_push(&a, sizeof(Foo), alignof(Foo))`; your own `export T *make(arena::Arena *a, constexpr type T)` when a function of yours takes a type no argument carries, and `export typeof(x) half(auto x)` when an argument does (`smith-lang-generics`).
   - Enforced by: review and the `sizeof/alignof` count. The raw functions (`arena::push_raw`) exist for C, which cannot call a generic.
5. **No `#define`; `constexpr` for constants.** `constexpr usize capacity = 1 << 20;`, and `export constexpr` when others use it. An enumeration or a function does what a macro of several lines did. Checks, contracts and `expect_abort` are functions (rule 8), never macros.
   - **No preprocessor at all:** no `#if` (a fact of the target is `target::`, a choice is `if constexpr`; `arena.smith` shows the way: ordinary code behind a `constexpr bool`, so every branch type-checks), no `#pragma` (a flag a library needs is declared by its row of `smith_libraries` and added by the build), no `#error` (`static_assert(false, ...)`), no `#line`, no `#embed`, no `_Pragma`.
   - Enforced by: `smith lint` and the editor, through the clang-tidy check `smith-preprocessor`, which reports every directive and `_Pragma` of a `.smith` file with what to write instead; it is in smith's default `.clang-tidy` and in `smith check`. A `.c` file is left alone, and a line that must keep one says `// NOLINT(smith-preprocessor)`.
6. **Effects are inferred, not passed down.** A program calls the C library and smith's direct modules (`files`, `process`, `net`, `clock`, `console`, `env`) from anywhere; effects are inferred from what a function calls (#207), and tests and arenas control them through handlers (#239); no `io` value is passed down from `main`. Print with `console::print`, read a file with `files::read_file`; a test replaces a module with its `set_handler` or fake, so a signature stays free of the world.
   - Enforced by: effect inference (`smith-lang-effects`): `[[std::pure]]` and `static_assert(effects::within(f, mask))` are errors where a promise breaks; there is no lint for a call.
7. **No globals, no `malloc`.** Memory is an arena passed in (`smith-arena`); state is a value passed in.
   - Enforced by: `smith-mem` reports `malloc` and `free`; review for a mutable global.
   - **`void *` does not become `T *` silently.** In a module an assignment, initialization, argument or `return` that would convert `void *` (or `const void *`) to `T *` is a compile error that names the cast: `(Ball *)data`. `T *` to `void *` and `nullptr` stay implicit; a typed API (`mem::view`, a lambda) is the end of the cast. Enforced by: the compiler (`void *` doesn't convert to `Ball *` silently); a file with no `module` line keeps C's rule.
8. **Checks, contracts and `expect_abort` are plain functions.** `test::check_equal(a, b)`, `contract::requires(low <= high)`, `test::expect_abort()`: a failure's report is read from the call stack, which is why they are not macros (`smith-test`, `smith-contract`, `smith-trace`). Write a check you need as a function too.
   - Enforced by: the libraries: `std::test` and `std::contract` define no macros (the `SMITH_CHECK` macros are gone), and `smith-preprocessor` rejects one in a `.smith` file; review.
9. **Module-local names are short, and `[[std::c_name]]` only where a C API must stay.** Inside `module std::arena` the type is `Arena` and the function is `push`; the module's name is the prefix, so `arena_push` in `arena.smith` is wrong. `[[std::c_name("SmithArena")]] export struct Arena {...};` is for a library whose C callers must not change; a project's own module gets none.
   - Enforced by: review. `readability-identifier-naming` in `smith lint` judges the case of a name as written, not its length or a repeated prefix.
10. **Loops end.** A loop has a count to bound it, so no `for (;;)`, `while (true)` or `do ... while (1)` outside `main`; `main` owns the program's life and calls the rest each step. The count is a constant, or a parameter that a `contract::requires(count <= ...)` bounds: that bound is the function's worst case, and `smith prove` says which `requires` to write when a loop has none.
    - Enforced by: `smith lint` and the editor, through `smith-bounded-loop` (also in C).
11. **C23 spellings.** `nullptr`, `bool`, `{}`, `[[noreturn]]`, `[[maybe_unused]]`, `[[nodiscard]]`, never `NULL`, `_Bool`, `<stdbool.h>`, `{0}`, `__attribute__((noreturn))` or a `(void)` parameter list (`main()`, in C23 `()` means no parameters); a constant is `constexpr`, not a file-scope `const` with a constant initializer.
    - Enforced by: `smith lint` and the editor, through `smith-c23` and `smith-constexpr` (also in C).
12. **A `switch` over a payload enum has no `default:`.** Name every variant, so a variant added later is an error at each switch instead of falling into a default (`smith-lang-enums`). A success is returned as the value (`return a / b;`, not `return {.ok = a / b};`), for a `result` or an `option` converts it; errors and absence stay explicit (`{.error = e}`, `.none`).
    - Enforced by: review; the compiler already requires every variant to be named, `default:` or not.
13. **A lifetime is a scope, closed by `defer`.** What a stretch of code makes, it gives back on every exit: an arena scope (`arena::scope_begin`, then `defer arena::scope_end(scope);`), a file or lock with its close in a `defer`. Nothing a scope made outlives it (owner: "we should be primarily thinking about arenas and wait groups").
    - Enforced by: review.
14. **A loop over a slice or an array is `for (T x : xs)`**, or `for (usize i, T x : xs)` when it needs the position; C's `for (usize i = 0; i < countof(xs); ++i)` is for a step, a reverse walk, two slices or a changing bound. Over a generic's `rest` or `fields(T)`: `for constexpr (auto x : rest)` (`smith-lang-for`).
    - Enforced by: review.
15. **No jumps, no run-time-sized stack arrays.** `setjmp` and `longjmp` skip every `defer`, so return a `result`; `i32 xs[n]` and `alloca` overflow the stack unchecked, so `arena::push_slice(&a, i32, n)`, or a fixed array when `n` has a maximum. An array parameter keeps its size (`i32 xs[4]`, checked), and one the lowering cannot check (`i32 a[n]`, `i32 a[const 4]`, a typedef'd array) is a slice `i32 a[:]` instead.
    - Enforced by: `smith lint` and the editor, through `smith-unsafe` (modules only).
16. **Unused on purpose is `_`.** A parameter or local you do not read is `_` (several may repeat) or `_name` when the name documents it; a value you drop is `_ = f();`, never `(void)f();` (`smith-lang-unused`).
    - Enforced by: the compiler: reading a name that starts with `_` is an error in a module; the choice between `_` and a name is review.
17. **An array's brackets say what it is.** `i32 xs[3]` (size written), `i32 xs[_] = {1, 2, 3}` (size from the initializer), `i32 xs[:]` (a slice); a bare `[]` is an error in a module, also as a compound literal `(T[_]){...}`, an `extern` and a flexible member (`smith-lang-arrays`).
    - Enforced by: the compiler.
18. **Report friction.** When a skill was wrong, unclear or contradicted another, or something was hard to find, say so in one line at the end of your report, as smith's own agents do.
