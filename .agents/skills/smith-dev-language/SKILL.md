# smith-dev-language

The language is in [smith-language](../../../knowledge/smith-language.md), its lowering in [smith-lowering-internals](../../../knowledge/smith-lowering-internals.md); the plugin's smith-lang skills teach it.

- `patches/clang-format-smith.patch` (issue #25) makes clang-format read a `.smith` file as C plus `::` and the file-scope `module`/`import` lines (`Format.cpp`, `UnwrappedLineParser`, `TokenAnnotator`); `tests/smith-fmt.sh <smith>` tests it (the corpus formatted to `tests/smith-fmt/corpus.expected`, `UPDATE=1` rewrites it; every `.c` of smith and the test beds the same as `.c` and `.smith`; `throw` and `import`; `smith fmt` with no arguments in a scratch project). `scripts/llvm.sh` applies every `patches/*.patch` and keeps the applied copies in `$cache/src/.patches/`: a patch that changed is taken out (with the ones after it) and put back, so a rebuild is incremental. To iterate on a Format patch, edit the cache sources and `ninja -C ~/.cache/smith/llvm/23.1.3-r4/build clang-format` (seconds), then turn the edit into the patch.
- The clang side is `patches/clang-token-hook.patch` (the `Preprocessor`'s `TokenHook`), applied to the LLVM sources by `scripts/llvm.sh` in its marked step, and `shim/hook.cpp`. The lowering is plain C in `runtime/lang*.c` (`runtime/lang.h` is its whole interface), so changing it does not rebuild LLVM; changing the patch does. `build.c` builds the hook only when the install's headers have it (`setHookMode`).
- `tests/smith-lang.sh <smith>` runs the corpus in `tests/smith-lang/cases` (`UPDATE=1` rewrites the expectations: read the diff), and `tests/smith-lang-c.sh <smith>` compiles smith's own sources as `.c` and as `.smith` and compares the code. Both skip themselves for a smith without the hook.
- `smith cc --smith-lower x.smith` prints the lowering of the text as written, `smith cc --smith-header x.smith -o x.h` a module's header (the helpers are under `smith cc`; the top level is only verbs). `smith build` runs the header steps itself (`smith_object` of a `.smith` source, `runtime/build_runtime.c`, "`.smith` sources" in knowledge/build-file.md); `tests/build.sh` section 15 tests it. `SMITH_LANG_ASK=Name,struct Tag` prints what the parser answers about those types at the end of a file (`?const char *` asks about a type written as tokens, the question generics use).
- Cost: a plain `.smith` file must compile as fast as the `.c` (the host is offered only watched identifiers). Compare with alternating runs, at least 20 each, and note the load.
- **What the hook offers the lowering:** identifiers it watches, and braces or every token only in the modes that ask for them. Keywords (`if`, `else`, `constexpr`) are never offered as such, and the hook's fast path handles file-scope keywords without calling the lowering; a feature that must see a keyword asks for every token in the file (as `if constexpr` does for a file whose text has it).
- **`smith_lang_keep_aside` holds one saved state:** reading another module's interface while one is set aside corrupts the caller. Read imported modules first (`smith_raw_prefetch`), never nested.
- **A smith-lang corpus case is read by three tests:** after adding or changing one, run `UPDATE=1 sh tests/smith-lang.sh <smith>` and `UPDATE=1 sh tests/smith-fmt.sh <smith>` and read both diffs, and run `test-tree_sitter`: the editor's grammar must parse every case, so new syntax may need `tree-sitter/grammar.js` (then `sh scripts/tree-sitter.sh corpus`).
- **Generics today:** an instance is compiled where it is called, outside its module's file, but `smith-effects` counts it as its generic's module (a raw call in a capability module's generic is the module's own); an exported generic's body names only exports; an instance's tokens begin the lines the generic's did (a braceless `if` in a generic is fine under `-Wmisleading-indentation`). An exported enum's constants are `<CType>_<Value>` in C (`SmithTestKind_Equal`), passing C's `Type_Value` naming rule, when the enum has a C name (`[[smith::c_name]]` or a tag).
- **A module the bootstrap lowers writes its generics' types out** (`arena::push_array(arena, f64, n)`): the header pass and `--smith-lower` have no parser, so they cannot type an argument (a bootstrapped module calls no `auto` function: random calls the builtins), and the error ("the raw lowering has no compiler to type it") means exactly that.
- **The tests include the bootstrap lowering** (`tests/random.c` includes `bootstrap/lib/smith/random.c`), so a change to what a module imports can break a test's compile: run `smith lint`, which compiles them.
