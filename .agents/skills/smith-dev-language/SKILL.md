# smith-dev-language

The language is in [smith-language](../../../knowledge/smith-language.md), its lowering in [smith-lowering-internals](../../../knowledge/smith-lowering-internals.md); the plugin's smith-lang skills teach it.

- `patches/clang-format-smith.patch` (issue #25) makes clang-format read a `.smith` file as C plus `::` and the file-scope `module`/`import` lines (`Format.cpp`, `UnwrappedLineParser`, `TokenAnnotator`); `tests/smith-fmt.sh <smith>` tests it (the corpus formatted to `tests/smith-fmt/corpus.expected`, `UPDATE=1` rewrites it; every `.c` of smith and the test beds the same as `.c` and `.smith`; `throw` and `import`; `smith fmt` with no arguments in a scratch project). `scripts/llvm.sh` applies every `patches/*.patch` and keeps the applied copies in `$cache/src/.patches/`: a patch that changed is taken out (with the ones after it) and put back, so a rebuild is incremental. To iterate on a Format patch, edit the cache sources and `ninja -C ~/.cache/smith/llvm/23.1.3-r5/build clang-format` (seconds), then turn the edit into the patch.
- The clang side is `patches/clang-token-hook.patch` (the `Preprocessor`'s `TokenHook`), applied to the LLVM sources by `scripts/llvm.sh` in its marked step, and `shim/hook.cpp`. The lowering is plain C in `runtime/lang*.c` (`runtime/lang.h` is its whole interface), so changing it does not rebuild LLVM; changing the patch does. `build.c` builds the hook only when the install's headers have it (`setHookMode`).
- `tests/smith-lang.sh <smith>` runs the corpus in `tests/smith-lang/cases` (`UPDATE=1` rewrites the expectations: read the diff), and `tests/smith-lang-c.sh <smith>` compiles smith's own sources as `.c` and as `.smith` and compares the code, then builds and runs the programs of `tests/smith-lang-c/` both ways (the C rule, AGENTS.md: add a program there for each construct whose meaning a feature could touch). Both skip themselves for a smith without the hook.
- `smith cc --smith-lower x.smith` prints the lowering of the text as written, `smith cc --smith-header x.smith -o x.h` a module's header (the helpers are under `smith cc`; the top level is only verbs). `smith build` runs the header steps itself (`smith_object` of a `.smith` source, `runtime/build_runtime.c`, "`.smith` sources" in knowledge/build-file.md); `tests/build.sh` section 15 tests it. `SMITH_LANG_ASK=Name,struct Tag` prints what the parser answers about those types at the end of a file (`?const char *` asks about a type written as tokens, the question generics use). `!expr` asks `value_query` and prints the value tree (`!grid.cells`, `!f(3)`; no commas in it).
- Cost: a plain `.smith` file must compile as fast as the `.c` (the host is offered only watched identifiers). Compare with alternating runs, at least 20 each, and note the load.
- **What the hook offers the lowering:** identifiers it watches, and braces or every token only in the modes that ask for them. Keywords (`if`, `else`, `constexpr`) are never offered as such, and the hook's fast path handles file-scope keywords without calling the lowering; a feature that must see a keyword asks for every token in the file (as `if constexpr` does for a file whose text has it).
- **`smith_lang_keep_aside` holds one saved state:** reading another module's interface while one is set aside corrupts the caller. Read imported modules first (`smith_raw_prefetch`), never nested.
- **A smith-lang corpus case is read by three tests:** after adding or changing one, run `UPDATE=1 sh tests/smith-lang.sh <smith>` and `UPDATE=1 sh tests/smith-fmt.sh <smith>` and read both diffs, and run `test-tree_sitter`: the editor's grammar must parse every case, so new syntax may need `tree-sitter/grammar.js` (then `sh scripts/tree-sitter.sh corpus`).
- **Generics today:** an instance is compiled where it is called, outside its module's file, but `smith-effects` counts it as its generic's module (a raw call in a capability module's generic is the module's own); an exported generic's body names only exports; an instance's tokens begin the lines the generic's did (a braceless `if` in a generic is fine under `-Wmisleading-indentation`). An exported enum's constants are `<CType>_<Value>` in C (`SmithTestKind_Equal`), passing C's `Type_Value` naming rule, when the enum has a C name (`[[smith::c_name]]` or a tag).
- **A module the bootstrap lowers writes its generics' types out** (`arena::push_array(arena, f64, n)`): the header pass and `--smith-lower` have no parser, so they cannot type an argument (a bootstrapped module calls no `auto` function: random calls the builtins), and the error ("the raw lowering has no compiler to type it") means exactly that.
- **The tests include the bootstrap lowering** (`tests/random.c` includes `bootstrap/lib/smith/random.c`), so a change to what a module imports can break a test's compile: run `smith lint`, which compiles them.
- **Where a new kind of compile-time parameter goes** (`constexpr type T`, `auto x`, `constexpr auto f`, `auto... rest` are the four): `runtime/lang_generic.c` is in the sections its `// ----` headings name, and a kind touches these, in this order. (1) `SmithLangSlot` in `runtime/lang.c` and `smith_lang_param_is_*` plus `smith_lang_generic_params` (the classification, "Seeing that a declaration is generic"). (2) `smith_lang_generic_scan` ("Recording the definition": it fills `type_kind[]`, `type_token[]`, `type_position[]`) and the record in the header ("The record in a module's header", written and read back: a new kind is a new line in every generated header, so `smith build headers` and the corpus' `expect/header` change). (3) What an instance takes from an argument ("The types an instance was asked for", `smith_lang_infer_*`, "The type of an `auto` parameter, from its argument"; the conversion check of the later arguments is `smith_lang_converts_to` and `smith_lang_convert_ok`, "A later argument converts to..."). (4) What the instance's signature and call write ("Writing a signature and a call", "Writing the instances", `smith_lang_call_types` and `smith_lang_call_arity` for reading a call). (5) What the body may use (`runtime/lang_constexpr.c`, included in the middle of the file: `if constexpr` queries; "Lists and `for constexpr`" for lists). Messages for each step are in the same sections: `grep -n 'smith_lang_error' runtime/lang_generic.c` lists them.
- **`fields(T)`** is `runtime/lang_fields.c` (included by `lang_constexpr.c`, listed in `build.c`), asked at each token of an instance's body by `smith_lang_fields_replay` and in `smith_lang_pack_expand_range`, and in conditions through `smith_lang_fields_typeof_end` (a type), `smith_lang_fields_countof_at` (a number) and the host's `type_field`. A new construct on it needs both write paths, the condition and `smith_lang_fields_begins`. Corpus: `generic-fields`, `generic-fields-error`.
- **The hook's text gating** (`shim/hook.cpp`): a file with the words `if constexpr` or `for constexpr` (`hasIfConstexpr`, a scan of the buffer for `constexpr` after `if` or `for`) is offered every token of a body, as `tryFastSparse` says; any other file only braces and watched names. A new construct that needs to see a keyword the hook does not offer must extend that scan (or add its own word to it), or the lowering never sees it, with no error: it fails as the construct "not working in plain files". The corpus case that covers it needs a file whose only use of the construct is in a body.
- Private names in an exported generic's body (issue #75) are `runtime/lang_private.c`: the header pass tees each private declaration (`private_active`, routed in `smith_lang_header_token`), `smith_lang_priv_resolve` marks what the exported generics reach, and the header's `#ifdef SMITH_INSTANCES` section, `// smith-linked:` and `// smith-hidden:` lines come from it; the module's own compile reads `smith-linked` at its `module` line (`smith_lang_linked_read`). A call in a call's arguments inside an instance is typed from captured tokens by the replay's `TypedStart`/`TypedFinish` frames (no recursion). Corpus: `generic-private-names`, `generic-private-generic`, `generic-nested-argument` and the two `error-generic-private-*` cases.
- **Tuples** (`runtime/lang_tuple.c`, skill `smith-lang-tuples`): `smith_lang_tuple_begin` runs in `smith_lang_process` at a `struct` token and rewrites the queue (the tokens up to the `}` become the tag, the braces and `A _0;` fields), so no state of the lowering knows tuples; the tokens it makes are `synthetic` (a token counted as source made clangd hang), and a head holds a tuple's braces as parentheses (`tuple_brace`). `t[0]`, `countof(t)` and `return {...}` ask the compiler (`expr_type`, `return_type`), so they exist only where the host has a parser and the token goes through `smith_lang_process` (not in a generic's replay); a token the lowering takes from a generic call's arguments sets `advance_skip` so the call's depth stays balanced. The hook offers every token of a file with a tuple in its text (`hasTuple`, `maybe_tuple`) or whose import's header has `// smith-tuples`. The spelling rule is one function used by every pass (`smith_lang_tuple_spell`): change it and every header and `expect/lowered` changes, and an old header disagrees with a new compile.
- **Type values** (`runtime/lang_type.c`, skill `smith-lang-type-values`, issue #99): `smith_lang_ty_token` is the first thing `smith_lang_process` does for a token of a file with `maybe_type_value` (the hook sets it, `hasTypeValue`; it also turns off the hook's fast path for sized names and `smith_lang_fast`'s, since a type name is read with its neighbours). It rewrites the queue like the tuples do (the tokens it makes are `synthetic`; the tokens it copies from the source, a `sizeof(t)`'s chain, are skipped by `passthrough`), and it follows the file's shape in `SmithLangTy` (static, reset in `smith_lang_new`: frames, names, regions). A handle is a 64-bit number (`smith_lang_ty_pack`); a generic's `if constexpr` writes `T` as one in `smith_lang_cx_text`. The generic scan (`smith_lang_generic_ahead`) takes a bare `type t` as a type parameter only when the head uses `t` as a type (`smith_lang_bare_type_used`); `decl.generic` keeps the hook out of a generic's head. A `.smith` corpus case that uses `kinds[1] x;` does not parse in the tree-sitter grammar: write `constexpr type k = kinds[1]; k x;`. `host->constant` reads a variable's value with `evaluateValue()` and crashes on a declaration whose initializer is not attached yet: use `value_query` for a name just declared.
