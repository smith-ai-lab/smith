# smith's own front end

Plan: #1112 (the plan of record is its first comment). Today's `.smith` files are lowered to C through a token hook in clang; the new front end reads `.smith` itself and emits LLVM IR through LLVM's C API, with no patches on LLVM. It lives in `front/` (modules `front::ast`, later `front::lex`, `front::parse`, `front::types`, `front::emit`, `front::cimport`), is not wired into `smith cc`, and shows its work through tests (`tests/front_*_test.smith`, run by `smith build test-front`, golden files under `tests/front/`). Later front tickets each add a section here.

## front::ast (`front/ast.smith`, #1116)

The syntax tree. Plain data: every type is exported with all its fields. `TypeExpr`, `Expr`, `Stmt` and `Decl` are a `span` and a `kind`, a payload enum with its data in the variant (`e->kind.binary.left`, read where `e->kind == .binary` held). An absent child is a null pointer, a list of children is a slice, a string is a `Str` into the source or the current allocator. `Module` is a name, a file and the declarations.

- **Constructors** copy into the current allocator, so a caller that sets an arena as the allocator frees a tree at once: `new_expr`, `new_stmt`, `new_decl`, `new_type`, and short helpers (`name`, `integer`, `binary`, `call`, `named`, `block`, `function`, `variable`, `record_decl`, `enumeration`, `type_alias`, `import_module`, `import_c`, `new_module`, ...). A constructor that takes a list copies it, so a stack array can be passed.
- **`ast::dump(module)`** is an S-expression, a node per line, two spaces a depth; a node with no statement under it and under 16 nodes is written on one line. Spans are not dumped. The layout is documented at the top of the file; the goldens in `tests/front/ast/` are what parser tickets compare against.
- **For track C**: `Decl.from_c` (read from a C header, reached as `c::name`), `record.opaque` (an incomplete struct), and the `TypeExpr` kind `unsupported_c { spelling }`. A function pointer is `applied Fn(function {...})`; smith has no function-pointer syntax.
- **Anonymous records**: the `TypeExpr` kind `record { fields, is_union }` is an anonymous struct or union used as a type (a payload variant `struct { I32 a; } one;`); its dump line is `(struct (field ...))` or `(union ...)`.
- **Tuple types** (A7h): `struct { I32, F32 }`, braces holding types with no field names, is the `TypeExpr` kind `tuple { elements }` (dump `(tuple (named I32) (named F32))`), read by `parse_type` wherever a type is read (a field, parameter, local, return type, `typedef`, another tuple). `parse_type::tuple_ahead` decides by a scan of the tokens, with no speculative parse: at the braces' own depth, a `,` or the `}` before any `;` makes a tuple, a `;` a record (`struct {}` is a record). A name after a type in a tuple, or a type with no name in a record, is an error naming both forms. `front::types` does not type a tuple yet.
- **No recursion**: a walk of the tree uses an explicit stack (a module may not recurse).

**Names that differ from the ticket**, forced by today's smith (accepted on #1136):
- `Field` is `FieldDecl`: a parameter of type `Field` makes a function a compile-time one (reflection's `Field`).
- `Identifier { Str text; Span span; }` for lists of words (`Path.segments`, a lambda's captures): `Str xs[:]` is a two-dimensional block, not a list of texts.
- Slices of children are slices of `ExprRef`, `StmtRef`, `DeclRef`, `TypeRef` (typedefs of the pointers): `Expr *xs[:]` in a field or parameter writes a broken C header.
- `Text` (`typedef Str Text`) for strings inside an inline struct of a payload enum's variant, which breaks the lowering with `Str`.
- `make_type` and `record_decl`: `type` and `record` as function names are compile-time functions. There is no generic list builder (`arena::slice_of` fails with a type from another module).

**Limits of today's smith found building it.** A string literal inside a nested initializer of a payload enum is not converted to `Str` across modules (pass names as arguments); a braced initializer is not accepted as an element assignment (`xs[i] = {...}`), only in a declaration, argument or return.

**A limit for importers.** In a module that imports `front::ast`, a `case .name:` label on an ast payload enum makes the compiler read ast's body files ([body-files](body-files.md)), and that fails today (a private `typedef ExprRef ExprRefList[:]` loses its `;`, and a `mem` body says `smith_mem_allocator_name` is undeclared). Importers dispatch with `if (x->kind == .k)`. smith-enum narrowing is also lost once the node pointer is passed to a call, so read the payload fields into locals first.

## front::emit (`front/emit*.smith`, #1119)

Turns a `front::ast` module into an LLVM module through LLVM's C API: `emit::module(context, &m, options)` returns the verified module or an `Error` with a span. Today it emits one function with integer arithmetic (literals, names, locals, `+ - * / %`, shifts, comparisons, assignment); signed `+ - *` and negation use `llvm.*.with.overflow`, division and remainder check zero and `MIN / -1`, a shift checks its width, all branching to one `trap` block per function; unsigned wraps. `Target` and `Options` pick the triple and the layout; symbols are the module path joined with `::`, exported is external, the rest internal. The tests run the result in LLJIT (`emit_jit.smith`) and compare golden IR (`tests/front/emit/`).

- **Control flow** (`emit_control.smith`, #1131): `if`/`else`, `while`, `do while`, `for` (an init variable is scoped to the loop), `break` and `continue` (through `Emitter.loops`; outside a loop an Error), comparisons (signed or unsigned by the operands' type, an `i1` `Bool`), `&&` and `||` (short circuit: blocks and a phi), `!`, `?:` (only the chosen side runs) and `true`/`false`. A condition is a `Bool`: an integer condition or `&& || !` operand is an Error, "a condition is a Bool; write `x != 0`". A function whose end is reached without `return` branches to the `trap` block. `switch`, `goto`, labels and `defer` are still `not emitted yet`.
- **Memory** (`emit_memory.smith`, #1133): pointer (`T *`), array (`T[N]`, N an integer literal) and record types (`Decl.record` becomes an LLVM named struct `<module path>::<name>`, declared before use and kept in `Emitter.records`; a union, a bit-field and an unknown record are Errors). Every lvalue is a place (address plus stored type): `&x`, `*p`, `a[i]`, `s.f`, `p->f` and the targets of `assign` are places, a read is the place plus a load, and a base that is no lvalue is spilled to a temporary. An array's index is checked against its count (out of range reaches `llvm.trap`; a constant index in range needs no check), a pointer's is not. `(Point){.x = 1}` and `{0, 0}` for an array fill a zeroed temporary (fields left out are zero), casts are integer to integer (by the source's signedness) and pointer to pointer, `null` takes the pointer type expected, and `sizeof`, `alignof` and `countof` read the target data, never the host (`sizeof(expr)` types the expression without emitting it). A file-scope variable is a global with a constant initializer (an integer, `true`, `null` or a compound of them), external when exported. Pointer arithmetic and comparison, slices, unions and function pointers are later tickets. A name that is no local is tried as a global (`memory::is_global_name`) before it is reported unknown, so a global is read and assigned by its bare name. `emit::module` calls `memory::release`, which frees the record table and every `Ty.element` block (chained from `Emitter.owned`).
- **Zero is initialization** (`emit.smith` `declare_zero`, K3, #1330): a local `T t;` with no initializer stores the zero of `T` (`LLVMConstNull`) at the declaration, in the current block, so a loop zeroes it again each iteration; only the alloca is in the entry block. This covers every type the emitter has (integers, `Bool`, pointers, arrays at any depth, records); `auto t;` is an Error. A plain store is right: LLVM's dead-store elimination drops it when the variable is written before it is read, and `T t = undefined;` is the opt-out (K3b, #1334): the checker (`types_expr::is_undefined`, `types_decl::local_variable`) takes `undefined` only as a local's whole initializer, with the declared type (`Auto x = undefined;` and any other use are errors), and the emitter makes the slot with no store. The emitter has no debug/release switch, so there is no fill pattern yet; tests: `tests/front_undefined_test.smith`. Floats, slices, unions, enums and `Option` are not emitted yet and get their zero when they are. Tests: `tests/front_emit_zero_test.smith` (golden IR per kind, and a run test where `dirty()` fills the stack and `T t;` in a loop still reads zero).
- **`Char` and character literals** (`emit_state.smith` `scalar_type`, `emit.smith` `character_literal`, K4, #1345): `Char` is the checker's 8-bit character type, an unsigned `i8` in the IR with the layout of `U8` (told apart from `U8` only by the checker), and a character literal is that constant whatever the hint says (the parser decoded its escapes). Tests: `tests/front_emit_char_test.smith` (golden IR, and a run test of `c == ' '` and a literal returned). `lib/std/ascii.smith` going end to end through `smith cc --front-end=new` waits for the join test (J2, #1342); it is not checked here.
- **Checked casts** (`emit_memory.smith` `cast`, `check_fits`, K2, #1329): `Options.checked` is the checker's `types::Checked` of the module (null: no cast is checked, as for a tree built by hand). `cast` asks `types::cast_checked(checked, expr).needed`; for a marked integer cast `cast_finish` converts, converts back and compares (`icmp ne`, skipped when the widths are equal), adds `icmp slt x, 0` of the source for signed to unsigned and of the result for unsigned to signed, and branches to the function's `trap` block with `arith::trap_if`, the path of a failed index. A cast the checker did not mark (widening, same width and sign, `Bool`, pointers) gets no check. Today a failed check is `llvm.trap` like every other check of the emitter: the report that names the value and the target type needs the failure handler (the `trap` block's TODO above) and is not built; float to integer waits for floats in the emitter. Tests: `tests/front_emit_cast_test.smith` (source text through `parser`, `types_decl::check_module` and the emitter: IR per kind, and a run test in which values that fit return and values that do not kill a forked child).
- **Files and owners**: `emit.smith` (passes and the walk), `emit_state.smith` (shared types, `Emitter`, stacks, helpers; a file of its own to break the import cycle), `emit_arith.smith` (this ticket's expressions), `emit_control.smith`, `emit_call.smith`, `emit_memory.smith`, `emit_debug.smith` (debug info, below; one file per later ticket, no two tickets share a file), `emit_jit.smith` (test helper).
- **The protocol** is the top comment of `front/emit.smith`; its rules in a line each: no recursion, so a work stack and a value stack; a handler pops operands and pushes one value; a node that needs a child first pushes a `then` continuation; pass 1 declares, pass 2 emits bodies; allocas go in the entry block.
- **Calls** (`emit_call.smith`, #1132): `f(a, b)` names a function of the module or a prototype in it (a `Decl.function` with no body, an external declaration); a path is joined by `::` (`geometry::area`), and a prototype named with a `::` is its own symbol, standing for a function of another module. Arguments run left to right with the parameter as hint; their number and types must match exactly (an `Error` at the argument). A prototype is not added to `e->functions` (pass 3 walks that table in step with the bodies); `Void` is an LLVM `void` type (a prototype's or a bodied function's result, also when the result is left out); a `Void` function's reachable end emits `ret void`, any other function's traps. Not yet: extern C, variadic; recursion is emitted like any call.
- **Handlers** dispatch with `if` chains, never `case .name:` ([#1153](body-files.md)); read payload fields into locals before any call.
- **No arena around LLVM**: LLVM allocates with `malloc`, which smith routes to the allocator in force, so a test must not hold an arena while it emits or runs the JIT.

**Debug info** (`front/emit_debug.smith`, B5, #1135): with `Options.debug_info` set, `emit::module` makes a DIBuilder, a C11 compile unit (producer `smith`) and file from `Module.file`, the flags `Debug Info Version` and `Dwarf Version` 5, a `DISubprogram` per function (name as written, linkage name the symbol, a subroutine type of the basic types `I32`/`U8`/`Bool` and pointers to them), a `DILocalVariable` with a declare record per parameter and local, and a `DILocation` (line and 1-based byte column of `Span.start` in `Options.source`) on every instruction; with it off nothing is emitted. A name or literal keeps the location of the statement or operator around it; a continuation gets the location of the node that pushed it (`debug::then_location`, called by `run` before every `then` item, from the item's `span`), so the add of `a + b` is the binary expression's, not the last operand's. The line table is `Emitter.line_starts` (one scan, a binary search per lookup) and the parameter counters are Emitter fields too: no file-level state, so two emits can run at once. `emit::module` calls `debug::release` on every exit, which disposes the DIBuilder an emit error left open. Tests: `tests/front_emit_debug_test.smith`, which also writes an object file with `emit_object::write` and looks for the `.debug_info` section.

## front::lex and front::parse (`front/lex.smith`, `front/parse.smith`, #1128)

**The tokenizer** reads the text of a file and gives all its tokens at once, ending with an `end_of_file` token. A `Token` is a `kind` and a `span`; its text is `source[span.start:span.end]` (`lex::text`), never a copy. `lex::tokenize(source)` is a `Lexed` (`Result(Tokens, LexError)`), the first error stopping it; `lex::dump(tokens, source)` writes one token a line, `line:column kind text`, which the goldens in `tests/front/lex/` hold.

- **Kinds** are a plain enum (`lex::plus`, `lex::kw_if`; the dot rule does not reach a struct field today). An identifier is `type_name` when its first character is an uppercase letter and `name` otherwise: the parser needs no symbol table. Each keyword has a kind (`kw_alignas` .. `kw_countof`: C23's, `_Atomic _BitInt _Complex _Decimal32 _Decimal64 _Decimal128 _Generic _Imaginary _Noreturn`, and smith's `module import export defer try countof`); C's type keywords stay keywords. Literals are `integer`, `floating`, `character` and `string`: the tokenizer checks the form (digit separators, suffixes, prefixes `U8 u U L`, escapes) and the parser decodes the value. Punctuators are C's without `#` and `##`, plus `::`; `[:]` is three tokens, `[[` and `]]` two each; there are no trigraphs and no digraphs.
- **Errors**: an unterminated string, character or block comment, a malformed number, a byte that starts no token, and any `#` (there is no preprocessor: the message names `constexpr` and `import`).
- **Comments and white space** make no tokens; doc comments are a later ticket's question.

**The parser core** is a `Parser` (the tokens, the source, a position, the errors, the hooks) and the cursor functions every parser file uses: `peek`, `peek_at`, `advance`, `at`, `accept`, `expect(p, kind, what)` (records `expected <what>, found <text>` and takes nothing), `text`, `error`, `span_from`. Expressions (A3), statements (A4) and declarations (A5) are parsed in three files that call each other only through `Parser.hooks` (`expression`, `type`, `statement`, `declaration`, function pointers) by way of `parse::expression(p)` and its three siblings, so each is tested with stubs before the others exist and A6 wires the real ones. A hook that is not set records an error and gives null. The errors are the current allocator's, as the tree is.

## front::parse_expr and front::parse_type (`front/parse_expr.smith`, `front/parse_type.smith`, #1145)

`parse_expr::expression(p)` and `parse_type::type(p)` are the hooks `Parser.hooks.expression` and `.type`; a nested construct is read through `parse::expression`, `type` and `statement`, never directly. Goldens: `tests/front/parse_expr/`, `tests/front/parse_type/`.

- **Expressions**: C's precedence and associativity with no comma operator (`(a, b)` and `xs[a, b]` are errors). No recursion: operators wait on two stacks. `try e` is prefix at unary precedence. A `c::` path is a value, never a cast. A lambda parameter needs a type (`[](a, b)` says to write `auto a`). `u8"..."` is a plain string; `u`, `U` and `L` strings and characters are errors.
- **Reflection and packs** (#1264): `parse_expr` reads these as postfix and argument forms. `x.[f]` and `x->[f]` are `reflect_member { base, field, arrow }` (`field` is any expression, such as `fields(T)[i]`); `pattern...` after a call argument or a braced-list item is `expand { pattern }` (`rest...` expands the name `rest`). `...` is read only after a call argument or a list item, never after another operand. A second `...` is an error (`an expansion does not nest: write one ... after the pattern`), and `x.[]` says to write `x.[fields(T)[i]]`.
- **`_Generic`** (#1285): C's `_Generic(control, T: value, default: value)` is `generic_select { control, assocs }`, each `GenericAssoc { type, value }` with a null type for `default`; the type is read by `parse::type` (a lowered tag such as `struct smith_array_restrict_u8_n` reads as a `struct` type, so `generic-slice-restrict/pair.smith` parses; whether that spelling stays is the open lowered-tag decision of #1112). `_Generic(x)` with no association is an error that says to write `, T: value` or `, default: value`.
- **Types**: qualifiers, paths, `auto`, keyword types, `struct X`, `typeof`, `*`, `[:]`, `[N]`, applied types `Option(I32)`. `T[:][3]` is a slice of arrays. `R (P...)` inside `Fn(...)` is a function type; `I32 (*f)(I32)` is an error naming `Fn(I32 (I32))`. A pointer to a slice is written with the slice type first, then the star (A7i, #1344): `Str *line`, `I32[:] *xs`, `const I32[:] *xs`, `I32[:] **pp`, `I32[:][2] *m` (a pointer type whose pointee is the slice type; `*p`, `(*p)[i]` and `countof(*p)` are unchanged). C's declarator `T (*p)[:]` is removed and is an error that says ``a pointer to a slice is written `T[:] *p`, not `T (*p)[:]` `` (`parse_type::at_slice_pointer_declarator` stops the type at the `(`, the declaration, parameter or field reports it); the corpus cases that still spell it are `[removed_b]` in the golden until the switch. A pointer to a fixed array follows the same rule (A7u, #1390): `I32[4] *p`, `const I32[4] *xs`, `I32[2][3] *m` are a pointer type whose pointee is the array type, in a variable, local, parameter, field, typedef and result, and C's `T (*p)[4]` is an error that says ``a pointer to an array is written `T[4] *p`, not `T (*p)[4]` `` (the same helper, `slice_pointer_error`, picks "a slice" or "an array" from the first bracket; a function pointer `T (*f)(args)` is untouched). Tests: `tests/front_parse_slice_pointer_test.smith`, `tests/front_parse_array_pointer_test.smith`.

## front::parse_decl (`front/parse_decl.smith`, #1147)

Declarations and whole files. `parse_decl::declaration(p)` is the hook `parse::Hooks.declaration`: it reads one declaration and consumes its own trailing `;` (a function with a body has none), so callers never expect one; it gives null after an error, with the parser past the bad declaration. `parse_decl::file(p, file)` reads an optional `module x::y;` (recorded in `Module.name` until the keyword is the switch) and declarations to the end of the file. Types come from `parse::type`, initializers from `parse::expression`, bodies from `parse::statement`.

- **Reads**: prefixes in any order (attributes, `export static extern inline constexpr thread_local`); a variable (a type, one name, array suffixes after the name, the first suffix the outermost, `= init`); a function (parameters with array suffixes and attributes, `constexpr Type T`, `auto... rest`, `...`, `()` or `(void)`); `struct`, `union` (bit-fields `U32 flags : 3;`), plain and payload `enum` (`typedef enum { Circle circle; empty; } Shape;`, `enum Small : U8 {...}`), `typedef`; `import` in its three forms; `static_assert`; and `if constexpr (c) { decls } else { decls }`, nested and chained, read with an explicit stack of open blocks (no recursion).
- **Anonymous records**: `struct { ... }` and `union { ... }` as a payload variant or the type of a variable are a `TypeKind.record`. One as a field (`struct Nested { struct { U8 x[4]; } in; }`, or C11's unnamed `union { I32 a; F32 b; };` with an empty field name) is read by `parse_fields` with an explicit stack of open records (16 deep, then an error), so a nest is a loop, not a recursion (#1286). The tuple form `struct { I32, F32 }` is not read yet (it waits on a language decision).
- **Errors that name the fix**: several names in one declaration, C's function-pointer declarator (`Fn(I32 (I32)) f`), K&R parameters, implicit `int`, an array with no size, and a tag spelled as C does. After one, the declaration is skipped to its `;` or closing `}` and the parse goes on.

**Statements** (`front/parse_stmt.smith`, A4): `parse_stmt::statement(p)` is the `statement` hook. It reads every statement form (blocks, `if` / `if constexpr`, loops, `switch`, jumps, labels, `defer`, `static_assert`) and a declaration-or-expression with no symbol table. Nesting is an explicit stack of frames, never recursion; after an error the rest of the statement is skipped and an `empty` placeholder stands in, so one mistake gives one error. Tests: `tests/front_parse_stmt_test.smith` with stub hooks and goldens in `tests/front/parse_stmt/`.

A type is used by its tag as a type name: `struct Pair a = {...};` as a local, a field, a parameter or a global is a variable of type `Pair` (the keyword is dropped; `struct words::Pair` and `struct c::stat` work the same), while `struct Pair {...};` and `struct Pair;` still declare the type by itself. A lone lowercase tag, `struct stat`, is C's and the error says `struct c::stat`. `constexpr Type Meters = F64;` names a type value like a type. A range `for (T x : xs)` and `for (Usize i, T x : xs)` are read by the statement parser with the declaration's help: `parse_decl` leaves the `:` (or the `,` and a type after an index) to it, `ast::StmtKind.for_stmt.range` holds `xs`, `init` the element and `index` the index declaration (null without one).
- **Slice qualifiers and `Lambda(F)`** (#1265): `T[const :]`, `T[restrict :]` and `T[const restrict :]` put the slice's own qualifiers on the slice node (the element's stay on the element); a qualifier in a later bracket, `[static :]` and `[volatile :]` are errors that say what to write. `parse_type::at_slice`, `take_slice`, `at_bad_slice_qualifier` and `bad_slice_qualifier` are exported for a declaration's brackets after a name. `Lambda(F)` (a lowercase name before `(`) is an applied type like `Lambda(F)`, and its argument is a function type like `Fn(F)`'s.
- **`typeof(T.[f])`** (#1284): when the argument of `typeof` is a path followed by `.[` or `->[`, it is read as an expression, so the type is a `type_of` whose operand is a `reflect_member` (`typeof(T.[fields(T)[i]])`); any other path that starts a type is still read as a type.
- **`Type T` without `constexpr`** (A7m, #1357): A parameter of type `Type` with no `constexpr` (`Type maybe(Type T)`, `static Type f(Type t)`) is read as an ordinary parameter of type `Type` with `is_constexpr` false, in a generic, a type function, a prototype and a definition (A7m, #1357): the parser raises no error for it, the checker does (N1, #1339: write `constexpr Type T`), and the corpus spells `Type T` until that switch. Tests: `tests/front_parse_type_param_test.smith`. The files that held `expected `)`, found `T`` now parse (`generic-bare-type`, `generic-slice`) or reach their next construct, the type function's `enum { T some; none; }` body (A7n) and a slice of a type value.

An enumerator that is a name alone, with or without a value, is a plain enum's value whatever its case: `enum { Red, Green }`, `Fib7 = f(7)`, `low = 2`. A variant is a payload only when a type comes before its name (`Circle circle;`, `struct {...} one;`), so `Red,` is never read as a payload type (#1267).

## front::parser (`front/parser.smith`, #1219)

`parser::parse(file, source)` reads a whole file into a `Parsed` (the `ast::Module` and the `parse::ParseError` list): it tokenizes, makes a `parse::Parser`, installs the four real hooks (`parse_expr::expression`, `parse_type::type`, `parse_stmt::statement`, `parse_decl::declaration`) and calls `parse_decl::file`. It never aborts: a lexer error is the one error with an empty module. The corpus run, `tests/front_parser_test.smith`, parses every `.smith` file of `tests/smith-lang/cases` and checks one outcome per file (`ok`, `error: <message> (line:column) [class]`, `C, out of scope` or `skipped: <issue>`) against the golden, which is one file a case, `tests/front/parser/cases/<case>.txt`, holding that case's lines (`path: outcome`) and nothing else (no total: the test prints them), so two changes to different cases touch different files (#1352). The class of a rejected file is written on its line (`gap_a1`, `gap_a2`, `removed_b`, `undecided_c`, `must_fail_d`, described at the top of the test): a rejected file with no class fails the test, as does a class on a file that now parses or is C, and a case file with no case behind it. `FRONT_UPDATE=1` rewrites only the case files whose text changed, keeps each class from the file on disk (a newly rejected file gets none, so a human adds one) and removes the file of a case that is gone.

## front::emit_object (`front/emit_object.smith`, #1134)

`emit_object::write(module, ObjectOptions, path)` writes an LLVM module to an object file and gives `path` back, or an `emit::Error`. The target is the caller's (`options.target.triple`, plus `cpu` and `features`, empty for the triple's defaults; `optimization` 0..3 only sets the code generator's level, no passes run); nothing reads the host. It registers every target the linked LLVM has (`LLVMInitializeAll*`), makes a PIC machine, and refuses a module whose data layout is not the machine's ("emitted for another target") before writing. LLVM's messages are copied into the current allocator. `tests/front_emit_object_test.smith` writes `add.o`, links it with a `main.c` through `smith cc` (lld in smith's process) and runs it; the C side names the symbol with `__asm__("front::test::add")`, with a leading `_` on macOS.

## front::types (`front/types.smith`, #1220 J1a)

The types of the front end and the checker's entry point; the API is the comment at the top of the file. J1b (expressions), J1c (conversions) and J1d (declarations, statements, calls) build on it.

- **`Ty` is interned** in a `Table` (named `Ty`, not `Type`, which is the type of types; the result is `Checked`, as a struct named `Result` reads as the type function `result`): two types are the same exactly when their `TypeRef`s are equal. A record and an enumeration are nominal (one per declaration); every other type is equal by structure. `const` on a pointee, array element or slice element is part of the type; `const` on a variable is the variable's `Symbol.is_const`.
- **Sizes belong to the target**: `layout(&target, t)` takes a `Target` (pointer width, largest alignment), never the host, so a GPU target has its own. `Usize` and `Isize` are the pointer's width and are their own types.
- **Names are resolved here**: `Scopes` is a stack of `Symbol`s (`declare`, `lookup`, `lookup_path`); a name from a C header is declared as `c::name`. Records and enumerations are declared first, then typedefs in order, then fields, signatures and variables, so use before declaration works for records only.
- **`types::check(module, options)`** returns a `Checked`: the table, the module's scope, the errors and a side table of expression types keyed by node (`set_type`, `type_of`; no field in `front/ast.smith`, the interface to the emitter is #1220's open question). `options.bodies` is the hook J1d fills to check function bodies, since J1a cannot import it. A construct J1 does not type is reported as `not yet typed: <kind>`.
- **No recursion**: `resolve` (a `TypeExpr` as a `TypeRef`), `layout` and `show` use explicit stacks. Tests: `tests/front_types_test.smith`, golden `tests/front/types/`.

## front::types_expr (`front/types_expr.smith`, #1220 J1b)

The type of an expression, up and down: `types_expr::infer(c, e)` from the expression alone, `types_expr::check(c, e, expected)` where a type is expected. Both return the type `e` has (the invalid type after an error, which silences the expressions around it) and record it, and every sub-expression's, with `types::set_type`. The API is the comment at the top of the file.

- **Down**: `expected` types an unsuffixed literal when it fits (`U8 small = 200;`; `U8 big = 300;` is "300 does not fit U8 (0 to 255); write a value from 0 to 255, or give it a wider type"), `null`, `.none`, an enumerator `.red`, a `{...}` list (record, array, `{.some = v}` for `Option`, `{.ok = v}` and `{.error = e}` for `Result`), a lambda (its parameters from the expected `Fn(F)`) and both branches of `?:`. Next to a typed operand (`x + 1`, `x < 10`) a literal takes the operand's type; any other pair of different types is an error that names the cast to write.
- **Typed**: every literal, names, unary and binary operators, assignment, `.` and `->`, `a[i]`, `a[i:j]`, calls (result from the callee's function type, count checked), casts (the written type only), `sizeof`, `alignof`, `countof`, `?:`. Not yet, reported as `not yet typed: <kind>`: `try`, a type as a value, a name from another module, a `c::` name (until front::cimport, #1124), nested designators, a lambda body with no `Hooks.lambda_body`.
- **Conversions are J1c's**: `Hooks.convert` (set with `types_expr::set_hooks`) is asked whenever a value of type `from` meets `to`, and reports its own error. `types_decl::install` (J1d) wires `types_convert::convert` in; with no hook set the default is exact type equality, plus `null` for a pointer and a function for its own `Fn(F)`.
- **No recursion**: a work stack of frames (node, expected type, stage); a node with children pushes itself at the next stage and then its children, and reads their types back from the side table. Tests: `tests/front_types_expr_test.smith`, golden `tests/front/types_expr/typed.txt` (rewritten with the runner's `--update`: `build/<OS>-<arch>/front-project/build/tests --update --test 'front_types_expr_test::*golden*'`).

## front::types_convert (`front/types_convert.smith`, #1220 J1c)

The conversion rules of a module (#414's baseline, #398) as pure functions over `types::Ty`; the rules are the comment at the top of the file. `convert(table, from, to, lit)` says whether a value of `from` may stand where `to` is expected, with `lit` (`no_literal()`, `constant(n)`, `constant_unsigned(n)`) letting `U8 small = 200;` pass and `U8 big = 300;` fail with "300 does not fit U8"; `cast_ok(table, from, to)` says whether `(to)x` may be written. Both return a `Verdict {ok, kind, message}`: `kind` is the `How` of the rule that allowed it (`widening`, `constant_fits`, `to_some`, `to_ok`, `array_to_slice`, `add_const`, ...), and `checked` says a cast needs the run-time check and a refusal's message names the expected type, the found type and what to write. J1b and J1d turn a refusal into an error at the expression's span.

- **Implicit conversions never lose a value or type information** (owner, 2026-11-01, #1328): same-sign widening, unsigned to a wider signed, `F32` to `F64`, an integer whose bits fit the float's mantissa (24 for `F32`, 53 for `F64`: `I16` to `F32`, `I32` to `F64`), an integer constant a float holds exactly (`F64 x = 0;`), `U64` to `Usize` only where the target's `Usize` is 64 bits (`target::`, never the host). Every conversion that could round (`F64` to `F32`, `I32` to `F32`, `I64` to `F64`), every float to integer, `Bool` to integer, enumeration and `void *` to `T *` conversion needs a cast; const is added, never dropped.
- **Arrays and text**: a fixed array never converts to a bare `T *` (write `&xs[0]`); it converts to a slice `T[:]` keeping its count, and to an array parameter of its own type. Only `Char[:]` (the checker's own 8-bit `Char`) converts to `Str`; `U8[:]` and `I8[:]` convert only by the cast `(Str)xs` (const or not; free: no run-time check, no UTF-8 validation; owner, 2026-11-01), and a `Str` converts only to a const `Char` slice.
- **Absence and errors stay explicit**: a value converts to `Option(T)`'s `.some` and `Result(T, E)`'s `.ok`; `Option(T)`, `Result(T, E)` and `null` do not convert to a `T` or an `Option` (`null` hint: `.none`).
- **A written cast that can lose a value asserts that it fits**, checked in every build: the task fails with a report naming the value and the target type, and `smith prove` removes the check when it proves it. That covers integer narrowing, a change of sign out of range and float to integer (out of range or NaN); widening, the same width and sign, a constant that fits, a written float cast (`(F32)x`, `(F64)n`: rounds to nearest), enumerations, `Bool` and pointers have no check. `cast_ok(table, from, to, lit)` returns `Verdict.checked`; `types_expr`'s `Hooks.cast` (wired by `types_decl::install`) calls it, reports a refusal and records the check in the side table (`NodeType`, no `ast` field): `types::cast_checked(r, expr)` returns `{needed, from, to}` for the emitter (K2). A constant cast that can never fit (`(U8)300`, `(U32)-1`, a float literal out of range such as `(I32)1e30`; there is no NaN literal) is a compile error naming the constant and the target type, with `wrapping::to(T, x)` suggested, not a check that always fails (owner, 2026-11-01: "anything that we can possibly make a compile time error, we should make a compile time error"). Deliberate truncation is `wrapping::to(T, x)` (#1102) and `checked::to(T, x)` returning `Option(T)` waits on #1085; neither is built. Casts between enumerations and integers, `Bool` and integers, and pointers (`void *` to `T *` included) are explicit; a pointer and an integer cast only at pointer width; dropping const, casting to `Void` (write `_ = x;`) and casts of functions or records are refused.
- Tests: `tests/front_types_convert_test.smith`, one per message.

## front::types_decl (`front/types_decl.smith`, #1220 J1d)

Declarations, statements and bodies, joining J1a to J1c; the API is the comment at the top of the file. `types_decl::check_module(module, target)` checks a whole module: it wires the hooks (`types_expr::Hooks.convert` is `types_convert::convert`, a refusal reported at the expression's span; `.lambda_body` is kept for later), runs `types::check` with `Options.bodies = check_body`, checks the module-level initializers and then the lambda bodies, and takes the hooks out again.

- **Statements**: blocks (a scope each), expression statements, locals (a written type, or `Auto` from the initializer), `if`, `while`, `do`/`while`, `for (init; cond; step)`, `return`, `defer`, labels, `break`, `continue`, `goto`. A condition is checked against `Bool`; a `return` value against the function's result type (a bare `return;` in a function with a result, and a value in a `Void` function, are errors). The walk has an explicit work stack of frames, so it does not recurse.
- **Lambdas** are checked after the body that holds them: the hook keeps a copy of the scopes at the lambda, and `drain` walks each body with the parameters declared from the expected `Fn(F)`; a lambda in a lambda is found by the same loop.
- **Not yet typed** (reported with a span): `switch`, `static_assert` in a body, `if constexpr` and `for constexpr`, a range `for`, a type or function declared in a body, and every `c::` name (`not yet typed: c:: name \`c::exit\``, until front::cimport lands, #1124). A function that falls off its end is not reported yet.
- **Spelling** (K5, #1347; owner, 2026-11-01: "we want all uppercase letters"): `Char` is a builtin 8-bit unsigned character type of its own (not an alias of `U8`; a `Char[:]` converts to `Str` by J1c's rules, and `Str` is `const Char[:]`). `char` and `bool` in a type position are errors, `` `char` is a C type: write `Char` `` and `` `bool` is a C type: write `Bool` ``, with no compatibility form. A character literal has type `Char` (`U32` above 255). `lib/std/ascii.smith` still says `char` until the N1 rewrite, so its test checks an in-memory copy with the word written `Char`.
- Tests: `tests/front_types_decl_test.smith` (the whole of `lib/std/ascii.smith` checks clean; one test per message), goldens `tests/front/types/decl_*.txt` (`locals_dump` plus `types::dump`), rewritten with `--update`.

## front::compile and front::roots (`front/compile.smith`, `front/roots.smith`, #1221 J2)

`smith cc --front-end=new` (experimental, off by default; without it a `.smith` file still goes through the token lowering) joins the pieces for the first time: each `.smith` file of the command line is read, `parser::parse`, `types_decl::check_module`, `emit::module` and `emit_object::write` make its object, and the other arguments go to clang as before with each `.smith` file replaced by its object (`-c` leaves only the objects). `compile::file(path, output, triple, roots)` does one file and gives a `Report` (ok, the diagnostics, the nanoseconds of each stage); `compile::run` (C name `front_compile_run`) is what the driver calls (`runtime/front_flag.c`, included by `smith.c`). A diagnostic is `file:line:column: error: message`, one per error, and a failing stage stops the next ones, so a type error writes no object. The target is the driver's: `--target=` or LLVM's default triple, the data layout is that machine's, and the checker's pointer width follows the triple; nothing reads the host's.

- **A module's name follows its path** (`front::roots`; owner, 2026-10-31): a file under a root is named by its path from the root, `/` becoming `::`, with no `.smith` (`src/game/replay.smith` is `game::replay`, `lib/std/ascii.smith` is `std::ascii`). The roots are the project's `src` and smith's `lib`, relative to the folder `smith cc` runs in; roots added in `build.smith` are a later ticket. A `module` line is accepted until the switch, but one that disagrees with the path is an error naming both; two files with one name are an error naming both files; a file under no root is named by its `module` line.
- **Linked into smith**: `build.c` compiles `front/*.smith` (all but `emit_jit` and `cimport`) into the smith program, with `ascii`, `format` and `clock` as plain compile steps beside their header steps. The units runner (`SMITH_CORE`) has no front end.
- **Gaps**: `lib/std/ascii.smith` itself stops in `front::emit`, which has no `char` type and no character literal ("unknown type char"); the demonstration test compiles the same module over `U8` and integer literals, written as the folder's own `lib/std/ascii.smith`. The temporary objects of a link (`<TMPDIR>/<name>.front.o`) are not removed yet. The header cache of C3 and `import <header.h>;` are not wired (`std::ascii` imports no header).
- Tests: `tests/front_join_test.smith` (in process and through `$SMITH_SELF`, with `std::process`; the goldens are `tests/front/join/`, the compile-time comparison is printed) and `tests/front_roots_test.smith`.

## front::cimport (track C)

Declarations read from C headers become these same nodes; its concept comes with #1117 (`c-header-import.md`), and links here once that file exists.
- **GNU spellings are errors** (#1363): in a `.smith` file an extended `__asm__` statement (`__asm__ volatile ...`, or a `:` inside its parentheses) is the error "extended asm is not part of Smith; use `hint::keep(x)`" (`parse_stmt`), and `[[gnu::x]]` is an error naming `[[std::x]]` where the std set has it (today `pure`), else "is not part of Smith and `[[std::x]]` is not available yet" (`parse_decl`). The name `hint::keep` is the proposal of the ticket (the effect of `__asm__("" : "+r"(x))`); the barrier function and the move of `lib/std` to it are #1375. File-scope basic asm is not touched. Tests: `tests/front_parse_asm_test.smith`.

A type value used as a type (A7o, #1360, draft): `name name` at the start of a statement is a declaration (`once x = 1.5;`), and `(x) operand` where the operand is `nullptr`, a literal or a name is a cast to a type value (`(t)nullptr`); `(x) - 1` and `(x)(y)` are unchanged. Whether the first name is a type is the checker's.
