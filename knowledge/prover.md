# smith prove checks LLVM IR with Alive2, Bitwuzla and Z3

**`smith prove` checks LLVM IR with Alive2, Bitwuzla and Z3, linked into every full smith.** Contracts are
the calls `smith_requires`, `smith_ensures`, `smith_invariant` and `smith_assert` of `<smith/contract.h>` (the module `smith::contract`). There is one LLVM configuration
(`~/.cache/smith/llvm/23.1.3-r11`): RTTI and exceptions on, which Alive2 needs, and the patches (`patches/*.patch`: the token hook #11, clang-format for `.smith` #25, debug names #27, XNU fast mmap, the editor's defaults (`smith-editor-defaults`), `.smith` as a source file in clang-format's main-include rule (`smith-format-source-extension`), the command hook for clangd and clang-tidy (`smith-command-hook`), clangd running `smith-*` checks (`smith-editor-fast-check`), C function bodies in the constant evaluator for `.smith` (`clang-constexpr-c`)); the compiler's
output is byte-identical with and without RTTI and exceptions (only the install path in debug info differs). `smith build
llvm` also builds, static and from packages pinned by hash, with nothing from Homebrew (Ninja, GMP, MPFR, Meson, CaDiCaL
and symfpu are among them): Z3 5.3.1, Alive2 (commit 01a5ec4, the newest that builds against 23.1.3) and Bitwuzla 0.9.1
(`build_prove_libs_make`, `build_bitwuzla_make` and `build_ninja_make` in `build.c`, no shell). Only the stage0 has no prover. Each function is proved in a process of
its own, which ends at its budget (SIGALRM) and when its parent dies. Bitwuzla decides the queries on every core, cheap query first and the full one only if that fails; Z3 only finds a counterexample's values, because on queries
with many stores through one array Z3 takes minutes where Bitwuzla takes a fraction of a second. Skill:
smith-contract.

**The prover's boundary is `smith_trusted()`, and there is no list** (issue #42, owner's decision: no proof file or
function list in build.c). `smith prove` proves every function with a contract of its own, minus the trusted ones;
`main` and functions with no contract are not proved. A function whose first statement is `smith_trusted()` (a call, so
it reads from the IR and works in C and `.smith` alike) is assumed: callers prove its `smith_requires` and assume its
`smith_ensures`, its body is never read, and it is memory-assumed to write only through the pointers it is given. The
report lists it as `trusted` and counts it apart from `proved`. A proved function that calls io, inline assembly or a
libc function with no contract fails with a message that names the call and the function to mark. Errors name their
cause (a `smith_requires` that reads after a write names both lines), and `--emit-ir=FILE` writes the IR the prover
checks. Skill: smith-contract.

**`__memcpy_chk` is `memcpy`, and Z3 running out of memory is the budget** (issue #94). Apple's headers make `memcpy` into `__memcpy_chk(dst, src, len, size)`, which has no body: `lower_memcpy_chk` in `shim/prove_ir.cpp` turns it into the memcpy intrinsic before the calls are resolved (the check against `size` aborts only where memcpy is out of bounds, which the proof of the memcpy reports). On a function whose queries are far over the budget Z3's allocator fails in several threads at once, and Alive2's handler printed "Severe Z3 error: out of memory" from each and exited; `z3_error` in `shim/prove_alive.cpp` replaces it: that error ends the process as the CPU budget does (SIGXCPU), so the parent prints its one over-budget line. Not measured on the real functions: they did not reproduce in a scratch copy of game, so the handler was exercised by raising the error by hand.

**What a caller's memory holds is a value on every path** (issue #187). The prover assumes each load of a parameter's or global's memory is not poison (C has none), but it assumed it only in the blocks that load dominates. An unrolled loop's phi after the loop takes values from the loads of every pass, including passes that did not run (`if (xs[i] > 0) hits++` becomes a select on the load), so the phi was poison for the solver and a true `ensures(hits <= 8)` failed with a counterexample that satisfied it. The fact is now `path of the load => not poison`, assumed in every block (`given_values` in `shim/prove_alive.cpp`). Test: tests/prove/geometry/counting.smith.

**A `smith_requires` that bounded unrolling stays a premise** (issue #117). `assume_requires` gives a parameter the `range` the premise says, for the unroller only (SCEV reads no `llvm.assume` of a parameter); the optimizer folds the premise itself to true, so `remove_loop_ranges` takes the attribute off and writes the range back as an `llvm.assume` at the entry. Without it a fact the proof needed later (an index after a loop that leaves by `break`) was gone. `smith prove --function=NAME` works in a project: every group of sources gets it with `--in-project`, a group that defines none of the names exits 4 and says nothing, and `smith_prove_project` fails when every group did.

**A loop with `smith_invariant` is unrolled or proved by induction** (issue #56). Alive2 has no induction, so the loop is cut in the IR before it reads it (`cut_loops` in `shim/prove_ir.cpp`). On entry, the invariant is a proof point: a copy of the blocks from the loop's header to the invariant (the test left out, the traps kept) evaluates it for the values the loop starts with. At the header, every value a pass changes is arbitrary: the phis become loads of a global nothing writes, and each object the loop writes (found from its stores, memory intrinsics and calls: a local, a parameter with a size, a global) is overwritten with the bytes of one; the invariant is assumed there, the traps in it assumed to pass. Then the loop is as it was, one pass, its own checks proof points and its exits seeing the invariant and the failed test. The back edge goes to another copy that proves the invariant for the next pass's values and returns. A loop costs one pass whatever its bound, and the invariant must carry the proof: the report of a failed step shows the pass's values and the names the body writes that the invariant does not mention. The invariant is read where the test is, so it is a loop-head invariant (true when the loop exits). The optimizer knows in a body what the test says (`i <= n` from `i < n`), so while the passes run the tests that lead to an invariant are read through a call of `smith.opaque` (`hide_loop_tests`), removed after the first clean-up, which keeps the invariant as written. Why this shape: unrolling kept an invariant per pass and cost 4096 copies for `n <= 4096` (over its budget); a cut needs the loop's write set (the same analysis `contract::modifies` will need). When induction fails on a function whose cut loops all have a count of at most 128 passes, the function is proved again with its loops unrolled, so nothing that unrolling proves is lost (an invariant like `count <= row * 8 + col` with no `col <= 8` is not inductive but holds on each unrolled pass: tests/prove/board.c). A loop that cannot be cut (a write the prover cannot trace to an object of known size, a call that writes memory it cannot name, a pointer loop variable) is unrolled, and `-v` says why. The default is unrolling up to 16 passes and induction above, or with no constant bound (`--induction-from=N`, `--induction`, `--unroll`): the measured numbers are in issue #56. Skill: smith-contract.

**A pointer a function returns under `smith_ensures` is a whole object of its type, aligned, or null** (issue #74). Smallest sound rule found: the function carries `dereferenceable_or_null(sizeof pointee)` and `align` on its return, so Alive2 proves it at each `ret` (a pointer one past the end, or to a local, is undefined behaviour there); its callers get the same as an assumption on the call's value (a null result is replaced, for the assumption only, by an object that is there, so it holds for both), and the loaded values are given memory, as a parameter's are. The caller still needs `smith_ensures(result != nullptr)` to load through it. A trusted function is assumed, never proved, so its result gets nothing. A pointer to `void`, or to a type with no size in the debug info, gets nothing. A pointer into memory that a later call frees is outside what smith has (it has no `free`). Trusted and edge functions are `nofree`, whatever pointers they are given.

**A `T xs[:]` parameter is `countof(xs)` objects** (issue #106). arm64 passes the struct as one `[2 x i64]`, so the body turns the address back with `inttoptr`, a pointer Alive2 knows no object for. The unit being proved gets a function of its own with the slice as two parameters (`ptr data`, `i64 count`; `split_slice_parameters` in `shim/prove_ir.cpp`), `data` is assumed `dereferenceable(count * sizeof T)` and aligned, and `count <= 2^32`: without that bound the symbolic size makes a one-element read take 6 s and `xs[skip:][n - 1]` over 20 s. The `inbounds` of the address arithmetic on `data` is dropped, since the slice's own checks (`a <= b <= count`, proved as points) keep it inside the object and the access itself is checked; kept, `xs[skip:][n - 1]` took 16 s, dropped 2 s. The bounds check is `smith_failure(4)`, which is a proof point (`an index or a slice is in range`), except in the contract library's own functions. Only the unit's slices are assumed valid; a callee's come from its caller. **A slice of rows (`f32[:][2]`, `[:][:]`, `[:][3][:]`)** is the same with more dimensions (issue #106): the struct is `smith_array_f32_n_n`, `{ T *data; usize count[k]; }` for the k `:`, and the fixed sizes in its name (`_n_2`: one count, 16 bytes, still the `[2 x i64]` with the fixed size folded into `sizeof`). With two or more counts it is 24+ bytes and arm64 passes it in memory (a pointer to the caller's copy), so `split_slice_parameters` takes `(ptr data, i64 count...)`, builds the struct in a slot of its own, forwards the body's loads of `data` and `count[j]` to the parameters, and assumes `dereferenceable(count0 * ... * fixed * sizeof T)`. The solver cannot prove `r * count1 + c` inside `count0 * count1` (nothing in 10 s, even for 8-bit counts: a product of two variables), so `assume_row_products` gives it facts instead of products: each prefix product `P_j` is an extra parameter of the unit (a free value) constrained only by what is true of the real product, and each multiplication of the body by a count is replaced by a free value `z` (one per distinct `x`) with `x < P_(j-1)` implies `z + count_j <= P_j`; every fact holds of the real product, so a proof from them is a proof for it, but a product the program takes itself (`rows * cols`) is not related to `P`. Every dimension and prefix is assumed below 2^20 (the time grows with the bound: 2 s at 2^20, 5 s at 2^28, 6 s at 2^32). An inner index is checked per dimension by the lowering (`smith_failure(4)`, a point), so `m[r][c]` with `c` past `countof(m[r])` is refuted at its line. A read through a row view (`f32 row[:] = m[r]; row[c]`) proves in about 8 s of CPU, at the edge of the budget. A contract's `smith_requires` may not index a slice of rows (`countof(m[0])`): the check is a call, which counts as a write before the load of the count. A slice stored in memory or built by `p[a:b]` has no assumption: its elements are checked against what `p` is known to point at when read. The slice at the `p[a:b]` itself needs a marker from the lowering (a follow-up). Skill: smith-prove.

**`restrict` is a proof point at each call** (issue #65). C's `restrict` is assumed in the callee (`distinct_pointers`) and nothing else checked it, so a caller could break it. A restrict slice's object is its data and count * sizeof T; the debug info keeps `restrict` on the `data` member of the struct (only the outermost bracket carries it), and a slice of rows, passed in memory, is read from the pointer the call passes (`slice_parameter`). `check_restrict_calls` (`shim/prove_ir.cpp`, in `program_load` before anything is inlined, which would lose the attribute) puts `smith_restrict(id, a, b, bytes_a, bytes_b)` before each call of a defined, not trusted function with a `restrict` parameter, for each pair of it and another pointer argument (not both only read): the Alive2 side (`SmithPoint`) says the two blocks differ or the offsets are apart, said about blocks, since a condition on `ptrtoint` addresses of two parameters took the whole budget. A pointer is one object of its type (the source's size); a pointer the callee indexes or does arithmetic on (`used_as_array`: not a struct pointer's members) has no range the prover knows, which is `smith.restrict_unknown`, an error at the callee's declaration, never an assumed call. The hidden result pointer of a struct returned in memory (`sret`, noalias in the IR) is no `restrict` of the source and is skipped (#122). A **`restrict` slice** (`u8 dst[restrict :]`, `[const restrict :]`; #126) is the way to give the range: it is passed by value as `[2 x i64]` with no `noalias` in the IR, so `slice_parameter` reads `DW_TAG_restrict_type` on the `data` member of its struct (`smith_array_restrict_*_n`) from the debug info, and the call's marker gets the slice's data (`inttoptr(extractvalue 0)`) and `count * sizeof(T)` bytes as values (`SmithPoint` takes a size that is a value, an empty range is apart from anything, and the sums are wider than the offsets so none wraps): `copy(b[1:5], b[0:4])` fails at the call, `copy(b[0:4], b[4:8])` proves, with no new contract and no error at the declaration. A slice is paired with every other pointer or slice argument; a slice that is not `restrict` is only a partner. A plain `restrict` pointer used as an array stays the error. Measured on checkers: 15 proved before and after, the slowest function 6.8 s charged before and 4.1 s after (noise between runs).
**A program's proof reads smith's libraries for their contracts** (issue #66, item 3's first part): `.smith/build.info` has a `library` line after each program's `unit` line, naming the library sources the program links (not io's, whose exports are `smith::edge`, nor contract's or test's), and `smith prove` passes them as `--library=FILE`, compiled with the program's flags and linked in, every function of them marked `smith.library`: used by callers through its contract (or read as a helper), never a unit, never listed as trusted. An `smith::edge` export loses its body there, so it stays the edge. Why not contracts in the generated headers: a contract is an expression over parameters that reads memory, and only the compiler's IR says what it means; the header would need a second, lossy copy of it. Libraries proved once and cached by content, and the cost of reading library bodies, are the rest of #66.

**`contract::modifies` is a write set the prover proves and its callers use** (issue #54). `smith_modifies(p, size)` is the call `smith_contract_may_write(p, size)` (its body is deleted when the program is read, or LLVM would delete the calls: it returns and touches nothing); `contract::modifies(&x, ...)` is the generic over it, `export inline`, so its calls belong to the function that wrote it, and with no argument it is one range of no bytes. In the body (`instrument_writes` in `shim/prove_ir.cpp`, after the calls are resolved) each store, memory intrinsic and callee gets a proof point `smith.write_check(inside)`: the address range is inside a named range, an object of the function's own, or the report names the line. A callee's contract slice carries its modifies calls (they are roots of its smith_requires slice), so at a call the ranges are evaluated in the caller; the call itself is given a scratch object for each pointer it may write through (Alive2 would let it change the whole object) and the named ranges are overwritten with the bytes of a global of their own (`havoc_ranges`), then `ensures` is assumed. The `T[:]` form (issue #54, after #119): `modifies_slice(auto xs)` is `modifies_range(countof(xs) ? &xs[0] : nullptr, countof(xs) * sizeof(xs[0]))`, a helper because a generic reads a slice only from a parameter, not from `rest[i]`; the range is evaluated in the caller like any other. A slice parameter of a function that writes memory gets `writable` and `dereferenceable(1)` on its `data` (`mark_slice_writable`: Alive2 takes the store only with the attribute; the size is the `dereferenceable` assumption of `split_slice_parameters`, so an empty slice is assumed to have a valid pointer), and so does a slice a `havoc_ranges` writes. A call that names ranges and returns void has its memory effects set to none: a slice goes in as two integers, so LLVM infers that the callee may write any memory, which Alive2 turned into undefined behaviour at the caller's next store (the note "may write memory it was not given" is not written for it).

Soundness is tested by running what was proved (random inputs satisfying each `requires`, under the sanitizers) and by a corpus of false claims that must fail: `tests/prove_sound_test.smith`, `tests/prove/sound/`, `tests/prove/unsound/` (issue #64). A local nothing has written holds a frozen value, not `undef`, so an uninitialized read is never proved to be what the contract wants.

**A proof removes the checks it proved, in an optimized build** (issue #221). `smith prove` records, per proved unit, the `smith_failure` points (kind Assert, text `an index or a slice is in range`) that the unit owns itself (none inlined from a helper, none of a generic's instance, which shares its lines with others) as `file<TAB>line` in a file its parent made; the children are separate processes. The parent writes `.smith/proved/<source>.pts` (`shim/proved.hpp`, shared with the lowering so they agree on name and key): `smith-proved <SHA-256 of prover version, lowering version, LLVM version and the source's bytes>` and the lines. A function that fails records nothing, so its lines are absent and its checks stay. The line is the key because the IR's debug location is the line of the lowered index, and the lowering asks `host->proved(location)` for the same line (`smith_lang_slice_check`, `runtime/lang_slice.c`); the hook (`shim/hook.cpp`) reads the file once, only when `__OPTIMIZE__` is defined, `SMITH_PROVING` (set by the prover's own compile) is not and the file is not in the editor. All checks on a proved line go, so a line with an unowned check next to a proved one is the only imprecision. `smith_object` (`runtime/build_runtime.c`) makes the file an implicit input of an `-O1`+ compile of a `.smith` source and adds `-DSMITH_PROVED=<FNV of its bytes>` to the command, so the executor rebuilds that object when its proof changes, and a debug object never depends on it. The file's key covers the source only: a callee's changed contract is not noticed (the owner's design; re-run `smith prove`). Decided against: running the prover in `smith build` (the proof-budget rule), removal in the prover's IR (the lowering is where the check is written, and a release build never reads IR of the prover). Test: `tests/prove_checks_test.smith`.

**`smith prove` says how much is proved, not only that the proofs passed** (issue #51). `program_load` counts, at the gate and before anything is flattened, the project's defined functions (not `smith.library`, not a snapshot, not a generic instance, which is always-inline) and those that are a unit or trusted: `Coverage` in `shim/prove.hpp`. Each group prints `N of M functions have contracts; smith prove -v lists the K without` after its counts (and after `nothing to prove`), `-v` the `without  name  (file:line)` lines sorted by file and line; the quiet `smith prove` and `smith check` read those lines of the log, add the groups up (`smith_quiet_detail`) and print `4 of 23 functions` under the verdict or in `smith check: prove ok (4 of 23 functions)`. A function is counted once per group of sources, so a header's `static inline` used by two programs counts twice. Nothing fails on low coverage: a threshold is a separate decision. Skills: smith-prove, smith-check, smith-contract.

**The check of an index is a proof point, not a body, and an instance is named as written** (issues #151, #155). A project links `trace.c`, whose `smith_failure` has a body; `inline_helpers` and the walk of what a unit reaches skip `is_assert_failure` calls, so the failure stays the proof point of #106 and `pthread_self` is never read. A generic's instance is `weak` in the IR, which LLVM never infers from, so a pure function was "may write memory"; `program_load` makes it an ordinary function before the inference. The note names what LLVM found (`why_it_writes`: a store to a global, a call), and `as_written` turns `clamp<int>` into `clamp<i32>` in every name smith prove prints. Tests: `tests/prove_smith_test.smith` (11d to 11f).
