# The shims that read clang's AST are compiled with a precompiled header

Measured in #639: `hook`, `tidy`, `affine` and `effects_infer` (`shim/*.cpp`) are the shims whose compile is much of clang's and LLVM's headers: their includes alone took 1.9 to 2.8 s of 6 to 13 s. A plain precompiled header saved a few tenths of a second; with `-fpch-instantiate-templates` (the templates' instantiations are made once, in the header) `hook.cpp` went from 5.9 to 3.7 s CPU, `affine.cpp` from 8.8 to 6.0 s, `effects_infer.cpp` from 7.1 to 4.2 s and `tidy.cpp` from 13.2 to 11.2 s; the header itself costs 6.5 s once. `lsp` and `clangd` got slower (2.3 to 3.1 s, 0.8 to 1.2 s: loading a 180 MB header costs more than their includes), so they stay out.

- `shim/pch.h` holds only system headers (clang's, LLVM's, the standard library's); a header of smith's own would make every shim depend on it. The shims keep their own `#include`s, which the guards make free.
- `build_shim_pch` in `build.c` compiles it as one more object (`<folder>/shim.pch`, in `build/<OS>-<arch>/`, so it goes with `smith build clean` and is no cache to cap) with the shims' own flags (`build_shim_flags`, the one list both use: a precompiled header must be made with the flags of the files that use it) plus `-fpch-instantiate-templates -x c++-header`, and `-Xclang -fvalidate-ast-input-files-content` there and where it is used: a header records the time of each file it read, and with the flag a `shim/pch.h` whose time changed and whose text did not (a checkout that rewrote it) still matches. The step cache serves a precompiled header and the shims that read it only because of that flag (#728: before it, a cache that served a folder its own old `shim.pch` after a checkout made the four shims fail with "has been modified since the precompiled header was built"; #1415 lifted the refusal for a compile that has the flag). A header also holds the absolute path of the file it was made from, and a worktree that is served another's header reads that file (clang stops with "could not find file" once it is deleted; `-fmodule-file-home-is-cwd` does nothing for a precompiled header, measured). So `build_shim_pch_source` writes `shim/pch.h` to `<cache>/smith/shim-pch/<hash of its text>/pch.h` at each graph and `build_shim_pch` compiles that copy: the header holds no worktree's folder, and a second worktree at the same commit with a warm step cache is served `shim.pch` and the four shim objects (measured on a Mac: user CPU of the first build in a fresh worktree 51 s to 29 s). As any object it depends on the compiler's file, its command holds the compiler's and LLVM's paths (the LLVM name, so a new LLVM or flags make it again; an LLVM is never edited in place) and its depfile lists `shim/pch.h` only, since the LLVM headers are system headers. Checked with `-d explain`: a change to `shim/pch.h` makes it again and then the four shims. It starts at once as the graph's first step, in parallel with every other compile.
- `build_shim` gives the four shims `-include-pch <that file>` and the file as an implicit input, so the graph makes it first and a change to it compiles them again. The other shims are small (0.4 to 2.3 s), and loading the header would cost them more than it saves; the prover's shims (C++20, RTTI) have other flags and would need a header of their own.
- A new shim that includes many clang headers is added to `build_shim_uses_pch`; a header it needs that the others do not is added to `shim/pch.h`.
