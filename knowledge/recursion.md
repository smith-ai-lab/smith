# Non-tail recursion

Owner, 2026-11-07: "I thought we were doing something where non tail recursive functions use our task system so we don't explode the stack?", then "Can we actually have the agent implement that now?" There is no annotation anywhere. Tail calls are loops ([#2709](https://github.com/smith-ai-lab/smith/issues/2709), `front/emit_call.smith` `mark_tail_call`); every other recursive call is allowed and is paid for in memory, not in stack.

- **The lowering** is `front/emit_recursion.smith`, run by `emit_call::check_recursion` on the finished module (the unoptimized IR). The module's call graph is read, its strongly connected components found, and each call that is not `musttail` and joins two functions of one component is replaced: its arguments go to a record (an alloca of the caller's entry block), `smith_recurse_call(thunk, record)` runs the callee as `thunk(record)`, and the result is loaded back. The thunk, `<callee>.rec`, is one internal function per callee, and keeps the call's attributes. A cycle of tail calls only keeps its check: with no way out it is still an error outside `main`.
- **A call through a function value** is a possible edge to every function whose address is taken and whose type is the call's (the lead on #2710: "a call through a function value whose target set is not known counts as a possible cycle edge"). It is lowered only when such a target closes a cycle, and has a thunk of its own that calls through the function value stored in the record.
- **The runtime** is `smith_recurse_call` in `lib/handlers.c`, declared in `include/smith/handlers.h`: the object every program already links, which `std::task` is not (the new front end cannot link the standard library yet). It runs `thunk(record)` on the stack in use while it has room, and on a new segment otherwise. A thread-local `limit` is the lowest address a recursive call may still start from: 96 KB below the first recursive call on a stack, 160 KB below the start of a segment. A segment is 256 KB from `malloc`, which reaches the allocator in force, freed when the callee returns. The switch is the C library's `makecontext`/`swapcontext` (looked up with `dlsym(RTLD_NEXT)` on Linux, so AddressSanitizer's interceptor does not warn), announced to AddressSanitizer with its fiber calls. A frame of more than 32 KB between two checks is not covered.
- **Going too deep** is an allocation failure: no block for a segment writes a line to stderr and aborts. The task fails; a handler that fails the allocation sooner (a small arena) stops the recursion sooner.
- **Effects.** `smith_recurse_call` is `alloc | fails` in `front/effects_table.smith` and `shim/effects_table.h`, and the thunk is passed to it, so a recursive function and its callers gain both effects, and a caller whose ceiling lacks `alloc` gets the ceiling error that names the call. Test: `tests/front_effects_pass_test.smith`.
- **The JIT** defines `smith_recurse_call` at its address in the process (`front/emit_jit.smith`).
- **Not yet.** A recursion with a proved `decreases` measure keeps plain frames on the stack and joins `<program>.stack`: `smith prove` does not read what the new front end emits yet, so it is its own ticket. Autodiff, GPU kernels and C callbacks on a cycle are not checked specially. A task that parks in the middle of a recursion on a worker that is not the one that started it shares the thread-local `limit` wrongly. The old front end keeps its "recursion in a module" error.
- **Tests:** `tests/front/e2e/recursion_*.smith` (fib, mutual recursion, a million deep, `defer`, another function type, a function value).
