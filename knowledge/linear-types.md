# Linear types, a plugin linked into smith

**A type marked `[[std::linear]]` has each of its values used exactly once on every path: a second use is a compile error at the second use naming the first, and a way out that leaves a value unused is an error naming the way out and the fix** (issues #189, #438; `shim/linear.cpp`; skill smith-lang-linear). Owner (2026-10-26): "if we made them linear, then it would be easy to remember because if you forget to close using something like defer, it's a compile error". Linear replaces affine and there is one kind; `[[smith::affine]]` and `[[std::affine]]` are gone, with no alias and no special error (owner, 2026-10-28). Valid C23, so a compiler that does not know it ignores it; checked for C and `.smith` alike. `_ = x;` (#413) is the explicit discard and counts as the use.

**One analysis, one host.** The analysis is a plugin in the clang that smith links, with no patch of clang, registered in clang's two static registries:
- A `ParsedAttrInfo` makes `[[std::linear]]` a known attribute everywhere (compile, clang-tidy, clangd), kept as `AnnotateAttr("std::linear")` on a typedef or a tag (before the `typedef`, or after `struct`; after the body is clang's error). `[[clang::annotate("std::linear")]]` is the same mark and needs no plugin to be accepted.
- A `PluginASTAction` of type `AddAfterMainAction` is added by clang to every frontend action with no `-add-plugin` flag, so `smith cc`, `smith build`, `smith run` and clangd run it and `smith lsp` shows the error as you type. There is no clang-tidy check: clang-tidy cannot report a diagnostic it has no id for (it crashes), so `smith_linear_disable()` (called by `smith_tidy_main`) leaves the plugin off in `smith lint`, where every compile fails anyway.

**The analysis** is a forward dataflow over clang's CFG (`setAllAlwaysAdd` and `AddScopes`, so every expression is an element in evaluation order and every variable has a `CFGScopeEnd` on each way out of its block). A walk of each function body comes first, and a function with no variable of a linear type is never given a CFG. The state has two sets of places: `maybe`, the places used on some path with their first use (a join is a union: a second use is an error), and `must`, the places used on every path (a join is an intersection: a variable that goes out of scope without its place in it was not used on some path). A place is a variable, a member path and a constant index or the counter of a plain loop (`for (usize i = 0; i < countof(a); i++)`, found on the `ForStmt`, the counter changed nowhere in the body). A use in a loop of a value from outside it finds itself through the back edge and says so. Any other index is an error. The ways out are the `CFGScopeEnd` elements (block end, `return`, `break`, `continue`, `goto`, and `try`, which lowers to a `return`) and, for the parameters, a `return` or the end of the function; a block that ends in a call that does not return owes nothing.

- **`defer`** is the C2y defer TS's `_Defer`; clang's CFG puts the deferred statement at the `defer` itself, so its uses count from there on for every way out after it and a way out before it still owes the value.
- **An array of linear values** with a constant size owes each element; a slice has no count the check can read, so it is covered only by a plain loop over it (the loop's `i++` turns the elements used on every path of the body into a claim that the whole slice is used; the claim starts true at the loop's init, which is the empty slice, and the first turn takes it back) or by moving it. A whole array or slice passed to a call, returned or bound to another slice moves every element; a `const` element type is a borrow (the callee reads members, cannot use an element up, and the caller still owes the uses). A **tuple** (`struct { Key, Key }`) owes each linear field (its count is in its type).
- **Assigning** a fresh value to a variable makes it usable again, and is an error while the old value was never used. A variable declared with no value holds nothing to use.
- A struct holding a linear member is not linear itself (reading the member is a use).

**Slices** (`Key keys[:]`) are lowered to `*__extension__({ auto smith_s = (keys); size_t smith_i = (index); check; &smith_s.data[smith_i]; })`; the plugin recognises that shape by its structure (a temporary named `smith_s…` copied from the slice, `data` indexed by a temporary), not by a marker from the lowering, so a lowering change that keeps the shape keeps the check. `.smith` locations are the source's (the hook keeps them), and the diagnostics go through the Presenter as any other.

**Robust by construction, because a plugin crash is a compile crash.** It skips templates and their instances, dependent contexts, invalid declarations, functions with an expression that has an error (as clang's own warnings do), deleted functions and everything in a system header; it analyses the project's headers' inline functions too. `FunctionDecl::getName()` is never called on an operator or a constructor. smith's own C and C++ (shims included) and the three test beds compile with it on.

**`random::Key` is linear** (`lib/smith/random.smith`, marked `[[clang::annotate("std::linear")]]`, the annotation `[[std::linear]]` makes, so its generated header compiles warning-free with any other clang, `-Werror` included). random is compiled into smith by the previous release (the lag rule), so marking `Key` needed a release whose compiler has this plugin: older ones refuse the attribute as unknown under `-Werror`; the annotate spelling is accepted by every clang. The library's own code reads a key through one `&key`, since a struct member read is a use.

**The same plugin narrows payload enums** (issue #198, PR 2 of 3; `shim/linear.cpp`, the `NarrowFlow` section). A struct with `__attribute__((annotate("smith::enum")))` (what the lowering of `typedef enum { Circle circle; ... } Shape;` writes) has a member `tag` whose constants are `<struct>_tag_<variant>` and an unnamed union with a member per variant; reading the member `x.circle` or `x->circle` is an error, `smith-enum: 'x.circle' is read where 'x' may not be a circle; test 'x == .circle' or switch on 'x'`, unless on every path the tag was established. The state is a map from a place (variable, members, dereferences) to a variant, forward over the same CFG, joined by intersection; the true edge of `x.tag == K` (also `!=` false, `!`, `&&`, `||`, `?:`, loops' conditions: the CFG splits them) and the edge into a `case K:` of `switch (x.tag)` add a fact; `default:` adds none. A fact ends at an assignment to the place, a part of it or a pointer it is read through, at `&place` and at a call given a pointer to it (not at writes through other aliases, which it does not track). Writing into a payload needs the same narrowing. A function with no such read pays nothing; a struct with no annotation is never looked at, so plain C is unchanged. smith lint turns it off as it does the linear check.

Tests: `tests/linear_test.smith` (each rule and use case in C and `.smith`, as golden files `tests/linear/<file>.expected`, and the editor; the `enum_*` files are the narrowing).
