# Objective-C from .smith

**`import <Framework/Header.h>;` of an Apple framework gives `objc::`** (issue #318; `runtime/lang_objc.c`, `shim/objc_index.cpp`, `SmithHost.objc_index` in `shim/hook.cpp`). The owner's north star is no `.m` file and no generated binding files, and a header that always matches the SDK.

- **Read apart.** AppKit cannot be read as C, and reading the file as Objective-C would change what its C means (`id`, `SEL`, `BOOL`, `YES`, `nil` are names of Objective-C). So the host runs this binary again, `smith cc -x objective-c -fsyntax-only`, on a file with `#import <Header>` and `SMITH_OBJC_INDEX=<folder>`; a plugin (`shim/objc_index.cpp`, like the affine one) writes `types.h` (C: an opaque struct per class and protocol, the records, typedefs, enum constants, functions and globals, all named `objc_<name>`, with Mach-O asm labels) and `methods.idx` (a block per class and protocol, a line per method with C types). The folder is `.smith/objc/<key>/`, a build output (never committed); the key is the header, the SDK, the target, the flags and the binary (under `smith lint` and `smith lsp`, where no driver gave the flags, they are the file's own header lookup flags: `-isysroot`, `-F`, `-I`, `-isystem`, `-iquote`). A framework header whose index has no class is a C header and is imported as before. The editor reads the folder and starts no compile.
- **Lowering.** `objc::X` is `objc_X`. At the last import the lowering includes each `types.h` and writes, in front of the first declaration, a `static inline` typed function for every method of each class whose name the file writes after `objc::` (found in the text, `SmithHost.main_text`), with its superclasses and protocols (`objc_NSWindow_setTitle`): the call is `objc_msgSend` (asm label `_objc_msgSend`, no header of Objective-C is included) cast to the method's exact type. Classes are distinct opaque structs, so a wrong argument is a C error. No `static` cache of the selector: a write would be a `globals` effect; the call through a pointer is `c`.
- **Names.** Parts of a selector are joined with `_`. A class method is renamed `class_<name>` only when an instance method of the same name is visible in the class's chain.
- **Linking.** `.linker_option "-framework", "X"` and `"-lobjc"` in file-scope asm become `LC_LINKER_OPTION`, which lld follows.
- **x86_64.** A method that returns a record over 16 bytes uses `objc_msgSend_stret` and `long double` `_fpret` (flags in the index); arm64 has neither. Only arm64 is tested.
- **Ownership** (part 2). The prelude of `runtime/lang_objc.c` (C text, written once with the types) defines `objc_Pool` (affine: `objc::pool_begin()` and `objc::pool_end(pool)` on `objc_autoreleasePoolPush/Pop`), the token `objc_OwnedToken` (affine) and, for each class the file names, `objc_Owned_X = {objc_X *object; objc_OwnedToken token}` with `objc::retain` (overloaded on the pointer type). A method whose index flag is `o` (the families `alloc`, `new`, `copy`, `mutableCopy` and `ns_returns_retained`) returns `objc::Owned(objc::X)`; the result is `X` of the receiver for `instancetype` and `id`. `objc::Owned(objc::X)` is read in `smith_lang_objc_name`. **Interim:** `{object, token}` stays only until #572 (affine values need a borrow); when it lands, `Owned` becomes one affine value ([#572](https://github.com/adam-r-kowalski/smith/issues/572)). **Why a token:** the affine check counts any read of the value as a use and has no borrow, so an affine `Owned` could not be used after its `defer release`; the object pointer is plain and the token alone is used, by `objc::release`, a macro `release(x)` = `{x.object, x.token}` (a name from C, so it expands). A second release is the affine error; a forgotten one and a copy of `Owned` are not found until linear types (#438).
- **Strings.** `objc::string(s)` copies a `str` (a literal too: `objc_string_literal`) into an owned NSString (`initWithBytes:length:encoding:` UTF-8); `objc::str(ns)` copies `lengthOfBytesUsingEncoding:` bytes plus a NUL through `malloc`, which is the thread's allocator in a smith program, and stops on a refusal. The prelude defines the `str` struct (`smith_array_const_char_n`) itself and tells the slice lowering it is defined. Both are in scope whenever a Foundation class is in the index; NSString's wrappers are written for them.
- **Classes and blocks** (#319; `runtime/lang_objc_class.c`, `lib/smith/objc.smith`). `objc::methods(objc::P, Data)` is the struct `objc_methods_P_Data`: one function pointer for each instance method of `P` and what it inherits (the first of a name, none named like a C keyword), `Data *` first, the index's types after. It is written at the last import for each pair the text names (`Data` is declared there as a struct tag, so it must be a `struct Data {...};` of the file), together with an adapter for each method and `smith_objc_add_P_Data`; a use is the struct's name, and a `(objc::methods(...)){...}` literal whose protocol requires a method it omits (index flag `r`, only the protocol's own methods) is an error of the lowering. `objc::class_define` is an ordinary generic of `smith::objc` that loops over its tables and calls `smith_objc_add_methods`, overloaded by the table's type; `import smith::objc;` and the Objective-C import share the name `objc`. **Storage:** one hidden ivar `smith_data` of `{self, Data}` (8 bytes, or `Data`'s alignment, in front), added before `objc_registerClassPair`; each method is an `imp_implementationWithBlock` of a block `{slot, delta, function}` (Apple's layout, a stack block with a static descriptor) whose invoke stores `self` in the slot and calls the function with the data. Method types come from `class_getInstanceMethod` of the superclass, else `protocol_getMethodDescription` (a protocol of a framework nothing else refers to is found by `dlopen` of the imported frameworks). **Super:** `objc::C::super_m(...)` is `objc_msgSendSuper` with `C`'s class (written when the text has `::super_`). **Blocks:** `objc::block(f, &context)` fills the `objc::Block` that starts the context (a global block, so never copied: the context outlives it) and returns it; the invoke is the user's function, which gets the block's address as its context, so no thunk per signature is needed; lambdas (#316) replace it. **Not here yet:** a smith-defined superclass in `super_`, a destructor for `Data`.
- **Not here yet.** A subclass pointer taking a superclass's parameter without a cast, a forgotten release (#438).
