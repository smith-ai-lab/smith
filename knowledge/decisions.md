# Every decision, in one line each

A decision changes only with the owner. Each line links the concept that holds it, with the owner's words and the date.

- One compiler, upstream LLVM 23.1.3, built by `smith build llvm` and linked into smith; no LLVM install at run time; smith is built by its previous release, never by Homebrew's `llvm`; `.metal` goes to Apple's `metal`. [one-compiler](one-compiler.md), [llvm-build](llvm-build.md), [smith-bootstrap](smith-bootstrap.md)
- smith compiles in its own process (`clang_main`); `SMITH_CLANG` runs an external clang; a change of compiler rebuilds every object. [one-compiler](one-compiler.md)
- The files the driver looks up are embedded and written once to a runtime folder that smith never removes; the programs are clones (never hard links) in a per-binary folder. [embedded-files-and-programs-folders](embedded-files-and-programs-folders.md)
- The linker is lld in smith's process; the system's other tools (`dsymutil`, `libtool`, `xcrun`) stay the system's. [linker](linker.md)
- The SDK is chosen through the environment, never a flag; the caller's own `SDKROOT`, `-isysroot` and `--config` win. [sdk-rule](sdk-rule.md)
- smith itself runs on macOS 26 and newer, built on any newer one: its objects and link have `-mmacosx-version-min=26.0`, and a newer system function is called only where it exists; programs smith builds for users keep the user's own target (owner, 2026-10-29: "Let's make 26 the floor"; #802). [deployment-target](deployment-target.md)
- Sanitized processes start as fast as Apple's, through a two-line compiler-rt patch. [sanitizer-startup](sanitizer-startup.md)
- `smith fmt`, `lint` and `lsp` are clang-format, clang-tidy and clangd from that LLVM, with smith's defaults only where a project has no file, and no `--query-driver` for the editor. [format-lint-and-editor-tools](format-lint-and-editor-tools.md)
- `smith dbg` and `smith dap` are lldb and lldb-dap from the same LLVM, with the system's debugserver, no Python and no curses. [debugger](debugger.md)
- Contracts are calls read by `smith prove` (Alive2, Bitwuzla, Z3), not a clang plugin and not `-fbounds-safety`; the boundary is `smith_trusted()` and there is no list. [contracts](contracts.md), [prover](prover.md)
- Checks run in every build; only a proof removes one (owner, 2026-10-25). [contracts](contracts.md)
- There are no hard time limits: proofs and checks should be fast, and when one gets slow it is shortened again (owner, 2026-10-31: "I don't think we want some hard and fast rule for how long things take. But we do want to make it so it's fast. If we notice it gets to long we want to shorten it again"; #639). A proof, a test and a build are watched, and a slowdown becomes a ticket. [proof-budget](proof-budget.md), [#639](https://github.com/smith-ai-lab/smith/issues/639)
- `smith build`, `check` and `test` draw from a host-wide pool of cores, `SMITH_CORES` (default: the core count): a run takes one core at its first heavy step and one more for each further worker, and gives each back as it ends, so it grows as cores free up; CI (`SMITH_PRIORITY=ci`) goes first, a smith run by a smith rides on its parent's core, and a dead or orphaned holder's cores are reclaimed (owner, 2026-10-27: "it's cheaper to just make the decision and then move on"). [slots](slots.md)
- Enzyme is linked into smith's lld; an autodiff program links with full LTO, and debug has ASan and no UBSan. [autodiff](autodiff.md)
- Adopting smith is incremental from both ends and every step is optional; `smith cc` never changes a default. [adoption-path](adoption-path.md)
- `smith new` writes the program and what agents need, and no configuration: "we have to assume the primary author is going to be Claude or some other agent." [smith-new](smith-new.md)
- smith's top level is only verbs; the bare `smith foo.c` is an error; `smith-cc` and `smith-c++` are links for what needs one program path; `smith++` is gone. [verbs](verbs.md)
- The verbs have fixed meanings and a project's own tasks run with `smith build <task>`; `smith_task` and `smith_alias` refuse a verb's name. [verbs](verbs.md)
- `smith docs` checks `knowledge/` (OKF) and `.agents/skills/`, and `smith new` starts every project with them. [verbs](verbs.md)
- `smith build` runs build.c, then its own executor, with no ninja (`SMITH_NINJA` is the way out). [build-file](build-file.md), [executor](executor.md)
- A Makefile is translated by smith's own reader of GNU make's common subset; no vendored make (GPLv3, no license forced on smith). [makefile-translation](makefile-translation.md)
- Clang modules are implicit, one per header, opt-in; there are two caches; the module cache is per smith (its LC_UUID) and keeps the three most recently used, anything idle a day goes; everything else follows one 31-day rule; packages are a URL and a hash, and smith reads its archives itself. [clang-modules](clang-modules.md), [caches](caches.md), [packages](packages.md), [archives](archives.md)
- smith's own code is `.smith` modules and C23, libc only, no malloc; new logic is `.smith`, and C++ is only the edges to LLVM in `shim/` (owner, 2026-10-27: "we only have to talk to LLVM at the edges through C++, but we get to write nice Smith code most of the time"; #540). [smith-own-code](smith-own-code.md)
- A failure's report is read from its call stack, so checks and contracts are plain functions; a test's signature says what it may touch. [failure-reports-and-tests](failure-reports-and-tests.md)
- `.smith` files are C with modules, lowered to C as clang reads them through a token hook; modules use `::`, never dots. [smith-language](smith-language.md), [smith-lowering-internals](smith-lowering-internals.md)
- In a module a tag is a type name (`struct Point {...};` is the type `Point`); `typedef` stays valid as C's (owner, 2026-10-25). [smith-language](smith-language.md)
- A `.smith` file has no preprocessor; the target's facts are `target::`; `smith-preprocessor` enforces it. [smith-target-facts](smith-target-facts.md), [smith-preprocessor-check](smith-preprocessor-check.md)
- The C rule is retired by [#1112](https://github.com/smith-ai-lab/smith/issues/1112): every `.smith` file is a module, so the old rule (valid C in a `.smith` file without a `module` line means what it means in C) no longer holds. [smith-language](smith-language.md)
- `if constexpr` works at file scope around any declarations, imports included; the branch not taken is never read (owner, 2026-10-25). [smith-target-facts](smith-target-facts.md)
- Smith is C plus compile time: every addition is a C construct evaluated at compile time (`if constexpr`, `for constexpr` as C's own `for`, `countof`, constant indexing) or fills a gap or removes a hazard of C (modules, sized types, `auto x = {...}` lists, which C23 leaves invalid); never user-defined dispatch (no overloading, traits or operator overloading), and every addition lowers to plain C. [smith-language](smith-language.md)
- `Option(T)`, `Result(T, E)` and `Lambda(F)` are part of the language: type functions in smith's library (`Lambda(F)` the parameter type of code to run), in scope in every module with no import, and the only names that are (owner, 2026-10-25: "They should always be in scope"); the rule: a name is in scope with no import exactly when the compiler depends on it (conversions, `try`, zero values), so a library type such as `list(T)` is imported (owner, 2026-10-26); the compiler types a lambda argument through `Lambda(F)`, so it is in scope too (lead, 2026-10-31, #957). [smith-language](smith-language.md)
- A value converts to `Result(T, E)`'s `.ok` and `Option(T)`'s `.some` wherever one is expected; errors and absence stay explicit (owner, 2026-10-25). [smith-language](smith-language.md)
- Generic functions are lowered, not templates; every compile-time parameter is `constexpr`. Struct fields are plain data: an exported type exposes all its fields to every module and to reflection; a type with invariants is opaque (exported by name, used through its functions) or checked by contracts, never by private fields (owner, 2026-10-25). [smith-generics](smith-generics.md)
- Every compile-time parameter is written `constexpr`, type functions included (owner, 2026-11-01: "It's one rule everywhere, because they're really the same thing as generic functions"). [smith-generics](smith-generics.md), [#1339](https://github.com/smith-ai-lab/smith/issues/1339)
- Anything that can be a compile-time error is one (owner, 2026-11-01: "anything that we can possibly make a compile time error, we should make a compile time error"; [#1106](https://github.com/smith-ai-lab/smith/issues/1106)). [smith-language](smith-language.md)
- Compile-time power is ordinary functions, not compiler builtins: what the compiler computes about types and values, a user's function can compute too (owner: "users have as much power as the compiler"); a builtin is added only where no function can express it. [smith-generics](smith-generics.md)
- `smith lsp` and `smith lint` handle `.smith` files as written, with no LLVM change beyond the hooks; clangd has one general hook through which smith's plugins add hover lines and code actions (owner, 2026-10-24: "add a general clangd hook for plugin hover lines (and code actions)"), never a smith feature written into clangd. [smith-names-as-written](smith-names-as-written.md)
- A module's generated header includes exactly what its exports need. [smith-module-headers](smith-module-headers.md)
- In a module there are no warnings: a fixed baseline of diagnostics, each with a written way to say "I meant it", are errors; heuristic ones are opt-in and advisory (owner, 2026-10-26). [module-diagnostics](module-diagnostics.md)
- The idiom checks and `smith-effects` are clang-tidy checks, on in smith's default `.clang-tidy`. [idiom-checks](idiom-checks.md), [effect-inference](effect-inference.md)
- A program calls the C library and smith's direct modules (`files`, `process`, `net`, `clock`, `console`, `env`) from anywhere; effects are inferred from what a function calls (#207), and tests and arenas control them through handlers (#239); no `io` value is passed down from `main` (owner, 2026-10-30; #240). [effect-inference](effect-inference.md)
- Effects are queried only by `static_assert(effects::within(f, mask))`; there is no `effects::of`. [effect-inference](effect-inference.md)
- smith is batteries included: its standard library covers what programs commonly reach for (data formats and serialization, ML, windows, the GPU, HTTP), so a project needs no third-party library; each library does one thing and defines no macros (owner, 2026-10-25). [libraries](libraries.md)
- The protocol code of `smith mcp` is generated, never written by hand, from the schemas vendored in `schemas/`, and is a build output (never committed); `smith mcp` is the debugger as MCP tools. [protocol-generation](protocol-generation.md), [mcp-server](mcp-server.md)
- Neovim support is this repository and enables nothing the user did not ask for. [neovim](neovim.md)
- C's raw memory functions are an error in a module: `memcpy`, `memmove`, `memset` and `memcmp` are reported by `smith-mem` with the typed `mem::` replacement, and a function that implements a wrapper says `contract::trusted()` (owner, 2026-10-26: "I like our type safe APIs on top of unsafe C APIs"). [mem-typed-functions](mem-typed-functions.md)
- Allocation never returns null in .smith: arenas grow from a backing allocator, a fixed arena's budget or the OS refusing is a checked failure; `try_push`/`try_alloc` return option for code that refuses (owner, 2026-10-25). [handlers](handlers.md)
- Prefer inputs to outputs: a function returns what it computes, allocated through the current allocator, instead of filling an out parameter; a pointer parameter that the function updates because updating that thing is the point (an optimizer's step, an arena) is not an out parameter (owner, 2026-10-25). [smith-language](smith-language.md)
- Two values that are logically one travel as one: slices, payload enums, `option`, `result`, lambdas and closures. When code can't make them travel as one, the agent stops and files an issue naming the gap; the language is fixed, not worked around (owner, 2026-10-26).
- A pointer to a slice is `Str *p`, and C's `(*p)[:]` is removed (owner, 2026-11-01; [#1112](https://github.com/smith-ai-lab/smith/issues/1112)). [smith-language](smith-language.md) [smith-language](smith-language.md)
- The standard library's scope is `std::` (module names, `import std::arena;`, and the attributes `[[std::pure]]`, `[[std::effects]]`, `[[std::affine]]`, `[[std::c_name]]`); C names stay `smith_`, headers `<smith/x.h>` (owner, 2026-10-28, #366). The library is `lib/std`. [smith-language](smith-language.md)
- Modules move to a left-to-right syntax after the switch-over to smith's own front end: `fn name(arg: T) -> U`, `let` (constant, the default) and `mut`, parameters constant unless written `mut x: T`, types `*T`, `[]T` (a slice; `[:]` is removed), `[5]T`, `?T` (replacing `Option(T)`), and matrices `[5][3]T` (both sizes known), `[][]T` (both at run time), `[5][]T` (one known); a pointer you write through is `*mut T`; the C spelling still parses in a module but is a compile error that shows the new form, and `smith lint --fix` rewrites it, which ports both renamed C files and existing modules (owner, 2026-11-01: "constant by default, as opposed to mutable by default", "you can just run the autofix, and then boom, everything is in the right version", "I definitely want to have a pointer to a mutable T if you want to have to write something", "parameters are constant by default, you need mut if you want to mutate them", "a slice should be []T and we remove the [:] syntax"; [#1428](https://github.com/smith-ai-lab/smith/issues/1428)). [smith-language](smith-language.md)
- GNU `__attribute__` is removed from `.smith` in favor of `[[std::...]]` (owner, 2026-11-01: "We want to use our own"). [smith-language](smith-language.md)
- Types are capitalized and values lowercase (`I32`, `Str`, `Type`, `Option(T)`, the concepts `Int` and `Num`): smith reads only the capitalized names (`bool` is C23's own keyword, `Bool` the same type), and a lowercase `i32` or `str` is the program's own name (owner, 2026-10-28: "types are always capital so it is clear", #366). [smith-language](smith-language.md)
- The character type is `Char` (owner, 2026-11-01: "we want all uppercase letters"). [smith-language](smith-language.md)
- No compatibility for old forms: smith has no outside users, so a rename rewrites the tree and the test beds once and deletes the old form, with no warning, alias or migration tool (owner, 2026-10-28: "I don't want to maintain tech debt because we have no other consumers"). [smith-language](smith-language.md)
- Names are short where possible; types are capitalized (`I32`, `Str`, `Option(T)`, #366) (owner, 2026-10-31: "I don't want things to be verbose. I actually prefer things to be short where possible."; this replaces the "full word" rule).
- An unsafe C API that smith wraps is called through the typed wrapper; in a module, calling the raw one is a compile error naming the wrapper (#399) (owner, 2026-10-26). In a module `void *` never converts to `T *` without a written cast (#398). [smith-language](smith-language.md)
- Zero is initialization, and `= undefined` opts out ([#415](https://github.com/smith-ai-lab/smith/issues/415), [#743](https://github.com/smith-ai-lab/smith/issues/743)).
- Float casts round without a check, implicit conversions that could round are errors, and float to integer is checked (owner, 2026-11-01; [#1106](https://github.com/smith-ai-lab/smith/issues/1106)).
- Bytes become text with the cast `(Str)bytes` (owner, 2026-11-01; [#1106](https://github.com/smith-ai-lab/smith/issues/1106)).
- Never merge a broken build: every change is a pull request, merged by the queue only when `ci` is green, with no exceptions for known failures (owner, 2026-10-25 and 2026-10-29). [ci](ci.md)
- Generated files are build outputs, never committed (owner, 2026-10-26: "They should never be committed to git"). [smith-module-headers](smith-module-headers.md)
- No new shell files (owner, 2026-10-25: "I want everything to be in Smith. I don't want any shell files"). [smith-own-code](smith-own-code.md)
- Whatever a module rejects and offers instead is one page. [module-in-one-page](module-in-one-page.md)
- Tasks are M:N with one worker per core, started at the first spawn; `main` is a task whose home is the first OS thread; any blocking call parks the task; typed `task::spawn` takes a lambda with `[[std::until(g)]]`; Linux uses io_uring for files and sockets where allowed, epoll and the file pool otherwise (owner, 2026-10-31). [#241](https://github.com/smith-ai-lab/smith/issues/241), [#940](https://github.com/smith-ai-lab/smith/issues/940), [#945](https://github.com/smith-ai-lab/smith/issues/945), [#946](https://github.com/smith-ai-lab/smith/issues/946), [#947](https://github.com/smith-ai-lab/smith/issues/947)
- Lambdas come before the idiom work; a lambda keeps its own type and converts to a function pointer only where one is expected (no captures); there are no init-captures (owner, 2026-10-31). [#316](https://github.com/smith-ai-lab/smith/issues/316), [#955](https://github.com/smith-ai-lab/smith/issues/955), [#958](https://github.com/smith-ai-lab/smith/issues/958)
- Effects: no user-defined effect kinds; Reader is the primitive and Writer a library on it; handlers are typed, one method per C operation, interceptors translate, and `void *` is private to the runtime; every effect has exactly `K::use(&h)` and `K::with(&h) { ... }`; `scratch` is the second allocator effect (owner, 2026-10-31). [#239](https://github.com/smith-ai-lab/smith/issues/239)
- Memory belongs to regions by default; `Owned(T)` is opt-in and linear; resources are linear; arenas are only allocators; a returned pointer is borrowed from an argument, static or the current allocator, or an owned resource (replacing C's four idioms); a struct takes its shortest region; an operation that may move or retype memory ends borrows into it; overflow, bad shifts and division carry `fails` and end the task; C is inferred, and what can't be checked is an error at the boundary until trusted; unrelated pointer casts are errors in a module (owner, 2026-10-31). [#439](https://github.com/smith-ai-lab/smith/issues/439), [#438](https://github.com/smith-ai-lab/smith/issues/438), [#725](https://github.com/smith-ai-lab/smith/issues/725), [#720](https://github.com/smith-ai-lab/smith/issues/720), [#351](https://github.com/smith-ai-lab/smith/issues/351), [#402](https://github.com/smith-ai-lab/smith/issues/402)
- Memory belongs to the allocator in force; a returned pointer is borrowed from argument n, from static (`returns_static`) or from the current allocator, or it is an owned resource, inferred where smith can read the code and declared with `[[std::returns_owned(f)]]`, `returns_borrowed(n)` or `returns_static` where it can't (owner, 2026-10-31; #439, #725). [ownership-idioms](ownership-idioms.md)
- Stack bounds are inferred over the whole program from each build's final frame sizes; ThinLTO stays the release mode; recursion goes through the async trick (owner, 2026-10-31). [#446](https://github.com/smith-ai-lab/smith/issues/446), [#1034](https://github.com/smith-ai-lab/smith/issues/1034)
- Four kinds enter a task: a copy, a move, a shared or exclusive borrow, and a sync handle; a lock body can't wait or fail, and an operation that may move or retype memory ends the borrows into it, across tasks as in one (owner, 2026-10-31). [#436](https://github.com/smith-ai-lab/smith/issues/436), [#439](https://github.com/smith-ai-lab/smith/issues/439)
- CI runs the neovim tests on Linux (owner, 2026-10-31). [#1017](https://github.com/smith-ai-lab/smith/issues/1017)
- Proofs are ordinary smith functions, Lean-level and purely inside smith: lemmas, induction by recursion with `contract::decreases`, and proof-only code (reached only from contracts and proofs) erased once every contract that uses it is proved; until then the check runs and the function stays (owner, 2026-10-31: "If we can write everything in Smith that would be great"). [#1052](https://github.com/smith-ai-lab/smith/issues/1052), [#1055](https://github.com/smith-ai-lab/smith/issues/1055)
- Concepts are the mathematical structures and concrete types satisfy them: short names are machine concepts (`Int`, `Unsigned`, `Signed`, `Float`, `Num`), full words the ideal mathematical ones (`Integer`, `Natural`, `Real`, `Seq(T)`, `Set(T)`, `Map(K, V)`); every `Int` type is an `Integer` and every `Unsigned` type a `Natural`; floats do not inherit `Real`'s theorems (rounding is silent, so float code proves an error bound); `BigInt` is the one new concrete type; a set of values is a `Bool` function (owner, 2026-10-31: "Concepts are sets. They're literally functions that return true or false." and "I like those names that you're using and the separation between the Platonic ideal and the machine concrete."). [#1052](https://github.com/smith-ai-lab/smith/issues/1052), [#193](https://github.com/smith-ai-lab/smith/issues/193)
- Solvers: Bitwuzla decides machine-type queries, Z3 decides `Integer`, `Natural` and `Real` queries (owner, 2026-10-31). [#193](https://github.com/smith-ai-lab/smith/issues/193), [#1057](https://github.com/smith-ai-lab/smith/issues/1057), [prover](prover.md)
- Design only the language's foundation now: "anything that is not foundational we should postpone design. We only want design the language foundation, things that effect everything else" (owner, 2026-10-31); postponed issues carry the `later` label.
- Nothing depends on the owner's Mac: "It should use it if there, otherwise, use the GitHub workers. And if the Mac ones are busy it should also use GitHub" (owner, 2026-10-31). [#1064](https://github.com/smith-ai-lab/smith/issues/1064)
- Program exit: `abort` stays, as a `fails`; `exit`, `_Exit` and `quick_exit` are compile errors in a module ("return from main"); `va_list` and C variadics are compile errors (use `auto...`); `setjmp` and `longjmp` are compile errors; the default handlers call libSystem on macOS and libc on Linux (owner, 2026-10-31: "We can keep abort, and then we can make exit a compile error. We can make the VA list compile errors as well."). [#924](https://github.com/smith-ai-lab/smith/issues/924)
- `if constexpr` may call another module's exported function: exported bodies are available to the evaluator, limited by effects (no io at compile time) (owner, 2026-10-31). [#280](https://github.com/smith-ai-lab/smith/issues/280)
- The factory runs until the owner says stop; there is no daily budget to track (owner, 2026-10-31: "I can just tell you when to stop, if we even want to stop").
- Orchestrators message the lead only when they need the lead, and the lead reads progress from GitHub on its own schedule (owner, 2026-10-31: "they should only message you when they need you").
- The issues hold the context: what a worker, an orchestrator or a fresh lead needs is written on its ticket when it is decided, never left in a conversation (owner, 2026-10-31: "This chat is just for planning ... we want the context externalized to a stable source").
- smith's own checks replace a sanitizer once they are better, and the ticket that does it says so explicitly: UBSan's arithmetic checks are off in modules now (#351); ASan stays in debug until ownership and regions are proved (#439) (owner, 2026-10-31: "once we have our own replacement that's better, then we can probably remove the other ones, as long as that's explicitly defined inside of the ticket").
- Foundational work that conflicts with everything (a rename of the tree, a change every module sees) runs first and alone, with the lanes paused, never in parallel with them (owner, 2026-10-31: "if there's a set of issues that we know have to come first, we should prioritize those as soon as possible"). [#366](https://github.com/smith-ai-lab/smith/issues/366)
- Workers run on the cheapest model the ticket needs: Haiku for docs, a README or a change spelled out line by line, Sonnet for code; orchestrators run on Sonnet (owner, 2026-10-31: "If it's like a documentation change, why are we using Sonnet, right? Or like an update to a README? That seems crazy.").
- An orchestrator is replaced by draining: it starts nothing new, hands over when its running workers finish, and only then is archived (owner, 2026-10-31: "tell them to just not start anything new, but then once the current batch is done, then we replace them").
