# Effect inference (issue #207, first step)

What a function does to the world, as a set of effects (`alloc`, `files`, `net`, `console`, `clock`, `process`, `env`,
`entropy`, `globals`, `unknown`, `fails`: one bit each, `shim/effects_table.h`), computed by `shim/effects_infer.cpp`, a second plugin of the
kind [affine-types](affine-types.md) is (an AddAfterMainAction that reads the translation unit when it is complete, and
a ParsedAttrInfo for the attributes; `smith_effects_disable()` turns it off in clang-tidy, which cannot report a
diagnostic it has no id for). Skill `smith-lang-effects`.

- **Inference.** Each function with a body gets the union of the effects of its calls, to a fixed point through the
  functions of the file and the headers it includes. A call the file cannot see into is a leaf: a function of libc or
  libSystem has the set `effects_table.h` gives it (pure ones, `malloc` is `alloc`, `read` is `files` and `net`, `printf` is
  `console`...), a declaration with an attribute and no body has the attribute's set (a promise), any other is `unknown`, as is a
  call through a function pointer, inline assembly and an Objective-C message. Writing a global or a function-local
  static is `globals`. Failing is the effect `fails` (issue #325, owner: effects are never a bad thing, what matters is knowing and controlling them): a call of `abort`, `__builtin_trap` or `smith_failure*` (the table has them as `fails`) is a failure point, which a checked slice index, a contract and an arena budget lower to, and every caller inherits it, in the file and across files through the summaries. A check that `smith prove` proved adds no `fails` in any build (the lowering reads `.smith/proved/<source>.pts`; an optimized build leaves it out, debug keeps it under a name that is no failure point). `smith prove`'s own compile does not judge `fails` ceilings (`SMITH_PROVING`): it must keep every check as a point to prove, so a ceiling would reject the function before it could be proved; nothing escapes, because every build's compile judges the ceiling after the proofs are known, with the proved checks no longer failure points.
- **Annotations are ceilings.** `[[smith::pure]]` is the empty set and `[[smith::effects(alloc, net)]]` lists what the
  function may do (the same spelling in C, in a module and on a declaration with no source, where it is a promise). It
  reaches the plugin's handler with its arguments through LLVM's `patches/clang-plugin-attr-args.patch` (r9): clang's
  parser read the arguments of a scoped C23 attribute only for an attribute it knew without the plugins, and a bare
  identifier after the first as an expression. Still accepted and not taught: one attribute for each effect
  (`[[smith::alloc, smith::files]]`) and `__attribute__((smith_effects("alloc", "net")))`; tests/effects/effects_internal.c.
  The declared set, not the inferred one, is what a caller sees.
- **The error** is at the first call that adds an effect beyond the ceiling and names the chain, `bad -> log_it (log.c:12) ->
  printf`; it is reported wherever a function carries an attribute (module, `.smith` without a module line, C) and in
  the editor.
- **Across files** (207b). Every compile that writes an object (bitcode under `-flto`, ThinLTO's release profile included) leaves a summary of it (`.smith/effects/<the object's path>.fx` in a project, `<object>.fx` beside it otherwise; the plugin, written whole and
  renamed): a line for each function (its linkage name, its declared set or -1, what its own body reaches, where) and for
  each thing it calls (a leaf with its effects, or a call by linkage name). The link of objects that have one, in
  `smith cc` (`smith_check_effects`, smith.c, so `smith build` too, `smith cc --smith-effects x.fx...` by hand; the place is `smith_effects_summary_path` in smith.c and the same rule in runtime/build_runtime.c, which declares it an output of each compile smith's own clang makes and an input of the link, so a summary that changed reruns the check),
  merges them, solves the sets again with the calls that cross files and reports a function whose ceiling is passed only
  through another file, with the chain; a symbol no summary defines is `unknown`. Why at the link and not at the compile: the
  compiles of a build are parallel and a callee's set may not exist when its caller compiles, so a compile-time read would
  differ between a clean and an incremental build; a module's header already carries the declared sets (its exports'
  attributes), which the importer treats as promises. A project function with no body in the file is *unresolved* at
  compile time (no effect, no error) where a system function the table does not know is `unknown`.
- **No recursion in a module** (207c): `checkRecursion` finds the strongly connected components of the call graph of the
  functions the module's file defines (a work list, no recursion) and reports a call that sits on a cycle, once for each
  cycle, with the way round (`a -> b (a.smith:4) -> a (b.smith:9)`); a call of `[[clang::musttail]] return f(...)` (an
  AttributedStmt with MustTailAttr over a return of the call) is a jump and does not count, so a cycle of jumps is a
  loop. Imports are acyclic, so a cycle is always inside one file; calls through a pointer and into code with no body are
  not followed. Only a file with a `module` line (it begins a line), so plain `.smith` and C say nothing. A survey on
  scratch copies of the three test beds (a name-based call-graph scan) found no cycle in any module; learner's C tool
  `tools/fetch/h5strings.c` has two tree walkers that recurse, outside modules. Tests: `tests/effects/recursion*`.
- **Proof-only functions** (#1055, `pruneProofOnly`). A function with internal linkage whose address is never taken and whose every call is inside the argument of a *proved* check (`smith_proved(f(n))` in an optimized build, `smith_contract_proved_<kind>(f(n))` in one that keeps the check, both written by the lowering from `.smith/proved/`), or inside another proof-only function, is proof code: its calls are dropped from the graph before the sets are solved, so it has no effects on the caller and a cycle of proof-only functions is no recursion error. No name marks it. A check that is not proved runs, so the function it calls is running with its effects and its recursion stays an error, as does a function that running code also calls. `SMITH_EFFECTS_PROOF_ONLY=<file>` appends `proof-only <symbol>` for each one found. The analysis is the same in every build; erasing the function from the binary of an optimized build is not done yet. Tests: `tests/effects/proof_only*`.
- **Not yet** (issue #207, later steps): hover, and `effects::of`.
- **The stack is solved at the link, from the same summaries.** Each compile to an object asks the backend for frame sizes (`-fstack-usage`, added by `smith_clang_main`, so no LLVM change; for one command that compiles and links the `.su` the driver names after the program is read after each job); the plugin copies them into the object's `.fx` (`S` lines, an `H` line with the opt level and sanitizers; a frame is `dynamic` when the body has a variable-length array or `alloca`, not by the backend's word, which a sanitizer's realigned arrays also earn) and removes the `.su`. The link solves `stack(f) = frame(f) + max stack(callee)` over the merged graph and writes `<program>.stack`: musttail back edges add nothing, other cycles and dynamic frames are `unbounded`, and code with no source is `at least N + unknown (calls: ...)`, never a guessed number (the task runtime, #241, decides what an unknown is). The file records the build's flags because a frame at `-O0` with sanitizers is larger than at `-O2`.
- **`tasks` is the effect of starting a task** (#935, bit `1u << 12`, `effects::tasks`): its handler is the scheduler (#241), and a `[[smith::pure]]` function can't spawn. Only a declaration carries it (`[[smith::effects(tasks)]]` on the task runtime's private entry), so a spawner and every caller up the chain has it; `pthread_create`, `thrd_create` and `fork` keep `process`. It is not `wait` (#436).
- **The editor uses the same solver** (#246): in clangd's parse the plugin builds the file's summary, merges it with the `.fx` files on disk (its own stale one loses) and reports the link's violations of the file's own functions at their calls. `shim/lsp.cpp` is the layer that tells the plugin the object of each source (`.smith/compile_commands.json`), that a file was saved (its parse then writes the summary) and, when one is written, has the other open files parsed again with a `didChange` that carries `forceRebuild` and no changes. A background pass compiles each stale source with `-fsyntax-only` and `SMITH_EFFECTS_OBJECT` naming the object whose summary it makes.
- **A query is a deferred `static_assert`** (`effects::within(f, mask)` in `lib/smith/effects.smith`, owner decision on #207): the call is an ordinary function that says yes, because an inferred set does not exist while the file is parsed; the plugin reads the `static_assert` after inference and judges it (at once for a function of the file, as a `W` line of the summary for one of another file, judged by the link and the editor's solve), reporting at the assertion with the message and the chain, and a note at the instantiating call. There is no `effects::of` (a value that is an error anywhere but a `static_assert`) and no `effects::pure`; add `of` only when a real use needs it.
- **libc's hidden state is `globals`, and the table records what a returned pointer means** (#724; `shim/effects_table.h`). A libc function that keeps state across calls or holds allocator memory has `globals` beside its other bits: `strtok`, `localtime`, `getenv`, `setlocale`, `atexit`, `rand`, `getpwnam`, `dlopen` and all of stdio (the buffers), so a caller that swaps the allocator for an arena and calls one is judged by the #439 arena check, not by a heuristic. The printf family (`printf`, `fprintf`, `sprintf`, `snprintf`, `v*`, `dprintf`, `asprintf`) is judged per call in `shim/effects_infer.cpp`: a format that is a literal with a float conversion (`%f %e %g %a`, any case, flags, width, precision and length allowed) or is not a literal adds `globals` at that call (the dtoa cache); a literal without one keeps the table's bits. A second list, `ownership_functions`, gives each libc function that returns an object pointer its idiom in the text form of #720's `.fx` records: `owned:<free function>` (`strdup`: `owned:free`; `fopen`: `owned:fclose`; `mmap`: `owned:munmap`), `borrowed:<n>` (argument `n`, 1-based: `strchr`, `memcpy`, `fgets`, `realpath` is 2) or `internal` (the function's own memory, never freed: `strerror`, `getenv`, `localtime`); where it depends on the arguments (`realloc`, `getcwd`, `fgets`) the entry is the documented common case. `smith_effects::idiom(name, out)` reads it. In a module, a call to a function of a system header that returns a pointer and has no idiom there is `error: smith-ownership: 'f' returns a pointer and the C library table gives it no idiom; add it to shim/effects_table.h` (a `.c` file is left alone). `SMITH_EFFECTS_IDIOMS=missing` makes a compile list the table's pointer-returning functions that a system header declares and that have no idiom (`smith-ownership-missing: f`, to stderr), `=list` the ones that have (`smith-ownership: f owned:free`); `tests/effects_infer_test.smith` fails on a missing one.
- **Null-keyed idioms and `owned:<f>:<n>`** (#724). An `Ownership` entry may carry a second idiom for when argument `n` is a null pointer constant: `getcwd` is `borrowed:1`, and `owned:free` when argument 1 is null; `realpath` the same with argument 2; `tmpnam`, `ctermid` and `cuserid` are `internal` when argument 1 is null. `owned:<f>:<n>[,<n>...]` calls `f` with the pointer and then those arguments of the allocating call (`mmap`: `owned:munmap:2`). In a module a call picks its form by the argument (`smith_effects::null_idiom`): a null constant (`nullptr`) picks the null form, an array, `&x` or a string literal the buffer form, and anything else is `error: smith-ownership: 'getcwd' allocates when its argument 1 is null and returns it otherwise; pass an array as the buffer, or NULL to allocate`. C files are not checked.
- **Promises are listed, not checked.** An effects attribute on a declaration with no source and a function that calls `smith_trusted()` are trusted. The plugin writes each as a `P` line of the summary (kind `e` or `t`, symbol, place, name; a header's declaration once per file); `smith check` runs the default build after its parts (a no-op when fresh), reads the `.smith/effects/*.fx` it left, drops duplicates by place and name and files under `.smith/`, and prints `promises: N`, each one with `-v` (`runtime/verbs.c`, `smith_check_promises`). No count means no promise in the built sources.
- **Inline assembly is read, not assumed `unknown`** (#396; `shim/effects_asm.h`). The template of a GCC-style `asm` is split by clang, each operand replaced by a register of the target (a constant operand by its value; an explicit register by its own, so `register long x8 asm("x8") = 64` and x86's `"a"` carry their constant), and parsed by LLVM's own assembler (MC, already linked for `.s` files; the host target's asm parser only, so a cross-compile is `unknown`) into a stream that keeps the instructions. The reading follows the constants moved into registers (`mov`, `movz`, `xor r,r`) and records each system-call instruction (`svc`, `syscall`) with its number and third argument, each call or jump to a symbol the block does not define, and each indirect one. The plugin turns them into edges: a system call is the libc function its number names (`shim/effects_asm.h` has the Linux x86-64, Linux AArch64 and macOS arm64 tables) with that function's table effects, `unknown` for an unknown number; a named symbol is a function of the file, the table's or `unknown`; an indirect call is `unknown`; a block that does none of these is no effect. `code` is the effect of making memory executable (`mmap`/`mprotect` with a constant protection with PROT_EXEC, as a call or a system call); only a constant protection is read, so an unknown protection stays `alloc`. The x86-64 side is written from the instruction names and is not yet run by a test (the host that runs the tests is AArch64).
- **Function pointers, report-only** (#396, the rule is not built): the owner's spelling puts the effects after the parameter list of the function type, `void (*log)(const char *) [[smith::effects(console)]]` (`[[smith::pure]]` there means none; a pointer type without one stays `unknown`). clang's plugin hook has no type attributes (`'smith::effects' attribute cannot be applied to types`), but `[[clang::annotate_type("smith::effects:console")]]` in that place is kept through a typedef, a field, a parameter and a call, so the plugin can read it from the callee's type until the spelling is lowered to it. Meanwhile `SMITH_EFFECTS_POINTERS=<file>` makes every compile append one line for each call through a pointer (`call`) and each named function made into a pointer (`make`, with the effects it has: the set the pointer's type would have to state), in function bodies and in initializers of globals; a `call` line ends with the effects its function type states by `[[clang::annotate_type("smith::effects:...")]]` (`pure` for none, `-` for a type that states nothing, which is `unknown`); it changes no diagnostic.
- A program calls the C library and smith's direct modules from anywhere; effects are inferred, and tests and arenas control them through handlers; no `io` value is passed down from `main` (owner, 2026-10-30; #240, #207, #239). There is no check of capabilities: `smith-effects`, the clang-tidy check, is gone (#892).
