# smith::task

`lib/smith/task.smith` is the first step of issue #241: smith manages lifetimes as scopes, an arena for memory, a group for tasks. Decided there: `main` is always the first task, `wait` and `pause` work in `main`, there is no `task::run`. This page is what exists; the plan (the typed `spawn`, parking I/O, a simulation scheduler) stays in the issue.

- **A task is a fiber.** One `mmap` holds a guard page (`PROT_NONE`, one page), 256 KB of stack, and at its top the task's own record, so no allocator is involved and a refusal by the system is a checked failure. The mapping is released when the task has ended. Each task is two mappings, so a process holds about 32,000 live tasks under Linux's default `vm.max_map_count` of 65530; a later ticket decides how to go past it.
- **The switch is assembly in the module**: file-scope `__asm__` under `if constexpr` on `target::arch` and `target::os` (arm64 macOS, arm64 Linux, x86-64 Linux; any other target is a `static_assert`). It saves the callee-saved registers on the old stack, stores the stack pointer and loads the new one; a new task's stack holds a frame that returns into a boot stub, which calls the entry with the task. Under AddressSanitizer each switch calls `__sanitizer_start_switch_fiber` and `finish`, and an ended task's mapping is unpoisoned before it is unmapped, so the next stack at that address starts clean.
- **The scheduler is a handler.** `task::Scheduler` is the runtime's `SmithScheduler` (spawn, pause, wait, io), kept in each task's handler table like the allocator. `task::use(&s)` installs it and returns the previous one (null: none); restoring is the caller's, with `defer`. `spawn`, `pause` and `wait` call the current scheduler; none set is the default one, `task::default_scheduler()`. A task copies its spawner's table, so a task spawned under a scheduler, and the tasks it spawns, run under it. A group records the scheduler that spawned into it, and `wait` goes there even after a swap. Both schedulers have `io` null, so a call reaches the real function. `Group` is the runtime's `struct SmithTaskGroup`.
- **The default scheduler is M:N: one worker per core.** `task::default_scheduler()` runs when none is set. The workers are OS threads (`pthread_create`, on mappings of our own so the C library keeps nothing of them), `sysconf(_SC_NPROCESSORS_ONLN)` of them (at most 64), each with its own run queue and a sleep on its own condition variable; one mutex guards the queues, the counts and the waiters. **They start at the first `spawn`**: a program that never spawns starts no thread. **`main` is worker 0**: the thread that spawned first, the first thread of a program; `main` never moves (owner, 2026-10-31, #940), and while it waits or pauses that thread runs the tasks queued for it. **Placement**: a new task goes to the worker with the fewest live tasks (ties to the spawner's own) and stays there for its whole life: no migration, no work stealing, so a task ends on the thread it began on and its thread-locals stay right. A task ending wakes the tasks waiting for its group on their own workers; a task that waits parks (its worker runs others), `main` runs its worker's queue and sleeps when it is empty. A wait that no task can end is a checked failure. **They end with the last task**: when `main`'s `wait` leaves with no task alive the workers exit and are joined, and their stacks and records are unmapped, so a later program step is single-threaded again and the leak checker sees nothing.
- **Records and stacks.** A task that has not run is a record (about 0.5 KB) from chunks of a global pool; its stack is mapped when its worker first runs it, from that worker's cache of up to 16 finished stacks or `mmap`, so 100,000 queued tasks cost their records, not 100,000 mappings. A task that pauses or waits keeps its stack, which bounds the tasks alive at once at about 32,000 under Linux's `vm.max_map_count`. Under AddressSanitizer a cached stack keeps its fake stack for the next task on it (ASan would otherwise map and unmap one per task, which made 100,000 tasks cost 18 s of system time).
- **The inline scheduler is for debugging**: `task::inline_scheduler()`, set with `use`, runs a spawned task at once on the spawner's thread, so the order repeats; the tests that assert an order set it.
- **Exports are `Group`, `Scheduler`, `default_scheduler`, `inline_scheduler`, `use`, `wait`, `pause` and `spawn`.** `pause` is the cooperative yield (not called `yield`, which is #436's generator statement). `spawn(&group, f, &arg)` is a generic over `T`: `f` is `void (*)(T *)` and `arg` a `T *`, checked by a `static_assert`, so no `void *` reaches a user; it wraps a private `spawn_raw`. It stands until the lambda form of #945, which replaces it (the old form is deleted, not kept).
- **Each task has its own handlers and its own `errno`.** A task holds a `SmithHandlers` table: at `spawn` it is a copy of the spawner's current table (`*smith_handlers_table()`), so a new task starts with its spawner's handlers and what it sets afterwards stays its own. At every switch `transfer` calls `smith_handlers_set_table` with the entered task's table (`main`, the first task, keeps the thread's own, null): the swap is one store, and the per-kind counters of #885 stay right because they are not touched here. `errno` is saved into the leaving task and restored from the entered one at each switch (`__error()` on macOS, `__errno_location()` on Linux). This module is the only caller of `smith_handlers_set_table`.
- **Not here:** parking I/O, cancellation, work stealing (later, when measured), and more than about 32,000 live tasks that have started on Linux (two mappings each against `vm.max_map_count`).

Tests: `lib/smith/task_test.smith`.
