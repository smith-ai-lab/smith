# std::task

`lib/std/task.smith` is the first step of issue #241: smith manages lifetimes as scopes, an arena for memory, a group for tasks. Decided there: `main` is always the first task, `wait` and `pause` work in `main`, there is no `task::run`. This page is what exists; the plan (the typed `spawn`, parking I/O, a simulation scheduler) stays in the issue.

- **A task is a fiber.** One `mmap` holds a guard page (`PROT_NONE`, one page), 256 KB of stack, and at its top the task's own record, so no allocator is involved and a refusal by the system is a checked failure. The mapping is released when the task has ended. Under Linux 6.13 and later the guard is installed as a marker inside the mapping (`madvise` `MADV_GUARD_INSTALL`), so a task is one VMA and adjacent stacks merge: `vm.max_map_count` does not cap the live tasks. An older kernel refuses it and the guard is an `mprotect`, two mappings per task, about 32,000 live tasks under the default `vm.max_map_count` of 65530.
- **The switch is assembly in the module**: file-scope `__asm__` under `if constexpr` on `target::arch` and `target::os` (arm64 macOS, arm64 Linux, x86-64 Linux; any other target is a `static_assert`). It saves the callee-saved registers on the old stack, stores the stack pointer and loads the new one; a new task's stack holds a frame that returns into a boot stub, which calls the entry with the task. Under AddressSanitizer each switch calls `__sanitizer_start_switch_fiber` and `finish`, and an ended task's mapping is unpoisoned before it is unmapped, so the next stack at that address starts clean.
- **The scheduler is a handler.** `task::Scheduler` is the runtime's `SmithScheduler` (spawn, pause, wait, io), kept in each task's handler table like the allocator. `task::use(&s)` installs it and returns the previous one (null: none); restoring is the caller's, with `defer`. `spawn`, `pause` and `wait` call the current scheduler; none set is the default one, `task::default_scheduler()`. A task copies its spawner's table, so a task spawned under a scheduler, and the tasks it spawns, run under it. A group records the scheduler that spawned into it, and `wait` goes there even after a swap. The inline scheduler has `io` null, so a call reaches the real function; the default one has `io` on macOS only. `Group` is the runtime's `struct SmithTaskGroup`.
- **The default scheduler is M:N: one worker per core.** `task::default_scheduler()` runs when none is set. The workers are OS threads (`pthread_create`, on mappings of our own so the C library keeps nothing of them), `sysconf(_SC_NPROCESSORS_ONLN)` of them (at most 64), each with its own run queue and a sleep on its own condition variable; one mutex guards the queues, the counts and the waiters. **They start at the first `spawn`**: a program that never spawns starts no thread. **`main` is worker 0**: the thread that spawned first, the first thread of a program; `main` never moves (owner, 2026-10-31, #940), and while it waits or pauses that thread runs the tasks queued for it. **Placement**: a new task goes to the worker with the fewest live tasks (ties to the spawner's own) and stays there for its whole life: no migration, no work stealing, so a task ends on the thread it began on and its thread-locals stay right. A task ending wakes the tasks waiting for its group on their own workers; a task that waits parks (its worker runs others), `main` runs its worker's queue and sleeps when it is empty. A wait that no task can end is a checked failure. **They end with the last task**: when `main`'s `wait` leaves with no task alive the workers exit and are joined, and their stacks and records are unmapped, so a later program step is single-threaded again and the leak checker sees nothing. `task::workers_running()` is the number of worker threads started and not yet joined (0 once the last `wait` has returned); the system's own thread list can still show a joined thread for a moment on Linux (#1172), so a test asks the library.
- **Records and stacks.** A task that has not run is a record (about 0.5 KB) from chunks of a global pool; its stack is mapped when its worker first runs it, from that worker's cache of up to 16 finished stacks or `mmap`, so 100,000 queued tasks cost their records, not 100,000 mappings. A task that pauses or waits keeps its stack, which bounds the tasks alive at once at about 32,000 under Linux's `vm.max_map_count` on a kernel before 6.13. Under AddressSanitizer a cached stack keeps its fake stack for the next task on it (ASan would otherwise map and unmap one per task, which made 100,000 tasks cost 18 s of system time).
- **The inline scheduler is for debugging**: `task::inline_scheduler()`, set with `use`, runs a spawned task at once on the spawner's thread, so the order repeats; the tests that assert an order set it.
- **Exports are `Group`, `Scheduler`, `default_scheduler`, `inline_scheduler`, `use`, `wait`, `pause` and `spawn`, and for std::stream the five fiber calls `fiber_start`, `fiber_resume`, `fiber_suspend`, `fiber_finish` and `fiber_release`.** `pause` is the cooperative yield (not called `yield`, which is #436's generator statement). `spawn(&group, f, &arg)` is a generic over `T`: `f` is `void (*)(T *)` and `arg` a `T *`, checked by a `static_assert`, so no `void *` reaches a user; it wraps a private `spawn_raw`. It stands until the lambda form of #945, which replaces it (the old form is deleted, not kept).
- **Each task has its own handlers and its own `errno`.** A task holds a `SmithHandlers` table: at `spawn` it is a copy of the spawner's current table (`*smith_handlers_table()`), so a new task starts with its spawner's handlers and what it sets afterwards stays its own. At every switch `transfer` calls `smith_handlers_set_table` with the entered task's table (`main`, the first task, keeps the thread's own, null): the swap is one store, and the per-kind counters of #885 stay right because they are not touched here. `errno` is saved into the leaving task and restored from the entered one at each switch (`__error()` on macOS, `__errno_location()` on Linux). This module is the only caller of `smith_handlers_set_table`.
- **Waiting on sockets and pipes (macOS kqueue #941, Linux epoll #942).** Each worker has its own kqueue (macOS) or epoll instance plus an `eventfd` (Linux), made at `start_workers` and closed at `stop_workers`. The default scheduler's `io` (`default_io`; installed by `default_scheduler()`, and every task it spawns has it in its table, so a plain `read` reaches it) takes `Read`, `Write`, `Readv`, `Writev`, `Send`, `Recv`, `Accept` and `Connect` on a socket or a pipe: it makes the descriptor non-blocking (the flag stays; it reads `F_GETFL` at each call, because a closed descriptor's number is reused), tries the call under a table with no scheduler (`empty_handlers`, so the real call is not routed again), and on `EAGAIN` (or `EINPROGRESS` for `connect`) registers the descriptor with `EV_ONESHOT` for read or write, parks the task and tries again when woken. A `connect` ends with `SO_ERROR` after the write event. The result and `errno` are what the blocking call would give. **Parking**: a task sets `io_waiting` and switches out; its worker's loop leaves it in the kqueue (counted in `io_parked` and `io_total`, so a wait that only parked tasks can end is not a deadlock) and the event queues it on that same worker, the only thread that reads the kqueue. **`main` parks too**: it has no stack to leave, so it runs its worker's ready tasks, or sleeps in `kevent`, until its descriptor is ready. **An idle worker blocks in `kevent` (macOS) or `epoll_wait` (Linux)**; another thread wakes it with an `EVFILT_USER` event or a write to the worker's `eventfd` (`wake_worker`), which replaces the condition variable on both. **Linux epoll**: a descriptor is registered with `EPOLLIN` or `EPOLLOUT` plus `EPOLLONESHOT` and the task in the event's data pointer (`epoll_ctl` ADD, or MOD when an earlier wait left it registered); the `eventfd` is registered with a null data pointer and read to quiet it. The same tests run on both backends. io_uring is the first choice on Linux later (#947), and epoll the fallback. **Fairness**: `task::pause()` and each run of a ready task poll the worker's kqueue with a zero timeout, so a task that never parks does not starve the ones that wait. **Not parked**: a terminal (its flags are shared with the shell), a `pread`/`pwrite` on a non-file and a bad descriptor go to the real call on the worker's thread. **A regular file (`fstat` says `S_ISREG`) goes to the file pool (#943)**: a small pool of threads (4, fewer on a machine with fewer cores) started at the first file call and joined with the workers. The task parks as for a socket, a pool thread does the real call (with no scheduler set, so it is not routed again) and puts the task on its worker's list of finished calls, which only that worker reads (in `poll_io`, beside the kqueue), so a task is never queued while it is still switching out; the call counts in `io_parked` and `io_total`. Cost measured on macOS in a debug build with ASan: a cached 4 KB `pread` takes about 0.4 µs inline and 6.4 µs through the pool, so the pool adds about 6 µs per call; in a release build (`-O2`, no sanitizers) about 0.3 µs inline and 4.4 to 4.7 µs through the pool. A call a files handler answers (fd 3 and up while one is set) is not routed to `io` at all, so a fake files handler runs on the task's worker. io_uring (#947) comes later and the pool stays as the fallback. One task waits for a given descriptor and direction at a time on a worker (a second registration replaces the first). `task::limit_workers(n)` starts at most `n` workers the next time they start; the tests use 1 so a call that blocked the thread instead of parking the task would hang them.
- **Not here:** io_uring, cancellation, work stealing (later, when measured), and more than about 32,000 live tasks that have started on a Linux kernel before 6.13 (two mappings each against `vm.max_map_count`).

A fiber of std::stream is the inline scheduler's mapping (`make_task`) without a scheduler: only its reader resumes it, it keeps a copy of its creator's handlers, and `fiber_release` unpoisons its whole stack for AddressSanitizer because a stream's last frames are never unwound ([stream](stream.md)).
