# parser (`front/parser.smith`, #1219)

`parser::parse_file(file, source)` reads a file into a `Parsed` (the `ast::Module` and the error list): tokenize, make a `Parser`, install the four hooks, call `parse_decl::file`. It never aborts.
- `parser::parse_new(file, source)` is the same for smith's own syntax (`tokenize_new`, `new_syntax`) and also returns the warnings.
- Blocks are `:` and indentation (#1845, split into #1856 to #1859). `parser::parse_new` always goes through `lex::layout` and sets `Parser.layout` (a statement ends with `newline`, a block is `:` then `indent` ... `dedent`); the per-file choice `takes_layout` is gone (#1870), so a brace block of the new syntax is an error. Only `parser::parse_new_braces` keeps reading braces, for the fixer's own output between passes (`fix::parse_for_fix` tries it after `parse_new`). `parse_stmt` reads `if c:`, `else:`, `else if`, `while c:`, `for x in xs:`, `match s:` with `.a: v` arms, `if let`, `defer:` and `defer f` on the layout path, in an indented block or on the same line (`if a: x else: y`); `parse_decl` (#1857) reads `struct Name:` (fields indented, one to a line; `struct Name` alone is opaque, a `:` with no block is empty), `enum Name:` and `enum Name(u8):` (members indented) and `fn f(...) -> r:` (an indented block, one statement on the line, or nothing for an empty body) on the layout path, skipping the `newline`s between declarations and after an attribute on its own line; `parse_expr` (#1858) still reads braces, so a whole file takes the layout path only once it does. The programs under `tests/front/e2e/` are written in `:` blocks (#1859, first piece); a statement or binding whose last piece is an indented block (`f(x):`, `let r = do:`) ends at that block's `dedent`.
- `parse_expr` reads the same layout path (#1858): `fn(x): x * 2` and `fn(x) -> R:` with an indented block, `do:` as a block value (its last line is the value), the trailing block `f(x):` with an indented block under it, and the trailing lambda `f(xs) fn(a, b): ...` on the line of the `)`. A bare `name:` block call and a trailing block with its body on the same line are not read yet. After a `dedent` no postfix operator continues the operand, so `.b` starts the next match arm. `parse_type` has no block of its own.
- `smith lint --fix` writes blocks as `:` and indentation (#2014): its passes still read their own output with braces (`parser::parse_new_braces`, the brace path of `parse_new` without the per-file choice), and `fix_text` ends with `front/fix_blocks.smith` (`fix_blocks::convert`, tokens only), which writes every brace block as `:` and an indented body once the text reads cleanly: `header {` becomes `header:` and the `}` line goes, `} else {` becomes `else:`, a body on the header's line moves down (one field to a line for a `struct`, `enum` or `union`), and a block in a value (`let c = if a { b } else { d }`, a lambda in a call) stays on its line (`if a: b else: d`, `fn(x): x`, a `return` in such a body is dropped, its value being the lambda's). A `}` that ends the last statement's line goes without a line of its own; a C three-part `for` the range fix did not take becomes `mut i: T = a` and `while c:` with the step as the body's last line (an assignment when the scope already declared the name; a `continue` that starts its line gets the step written before it; a loop with a comma, a body on the header's line or a `continue` that does not start its line is left); adjacent string literals on several lines are wrapped in parentheses; a function whose signature is still C's (`void f(auto x) {`) is left with all its braces (#2225). Before it reads the blocks, `fix_blocks` makes the text plain: a `}` that follows the last statement of a multi-line block on the same line (`g(i) } }`, `low = m } else {`) goes to its own line, and a line that starts with `.name` after a `)`, `]` or a name joins the line before it; after them, an `if` value written on the lines after an `=` (`x =` then `if a:` ... `else:`) moves to the line of the `=` with its lines one step out, since the parser does not read it otherwise; a `{` after a `case .a:` label becomes nothing, not a second `:`. Left to other passes: a value `if` written with `{ }` on lines of its own after the condition (from a `?:`), `typedef struct` and attributes (#2224), and an empty function (`fn f():` with nothing after it).
- `compile::file` picks by the first token: the keyword `module` means today's syntax (`parse`, its warnings not shown), any other file is smith's own (`parse_new`).
- A lexer error is the one error, with an empty module.
- The corpus run, `tests/front_parser_test.smith`, parses every `.smith` file of `tests/smith-lang/cases` and checks one outcome per file against `tests/front/parser/cases/<case>.txt` (#1352).
- An outcome is `ok`, `error: <message> (line:column) [class]`, `C, out of scope` or `skipped: <issue>`; classes (`gap_a1`, `removed_b`, ...) are described at the top of the test.
- A rejected file with no class fails the test. `FRONT_UPDATE=1` rewrites only the case files whose text changed and keeps each class on disk.
