# Fix-its and `smith lint --fix` (`front/fix.smith`, #1442, #1516)

`smith lint --fix FILE.smith...` (`runtime/front_flag.c`, no `--` among the arguments) mends files in place and prints `path: N fixes applied`.
- `fix::apply_fixes(source, errors, warnings)` applies the fixes of the errors, then of the warnings; a fix is all its edits or none, taken when no edit overlaps one already taken.
- `fix::fix_text(file, source)` parses and applies until a pass applies nothing (at most 8); `fix::fix_file(path)` does it on a file; `fix::fix_run` is what the driver calls.
- Type forms of `lib/std` (#2106): `Type Option(Type T) {` is `fn Option(T: type) -> type {` (a `Type` parameter without `constexpr` is `T: type` too); a parameter named `type` is `ty`, with its uses in the body (`type` is reserved like `i32`, #1901); `auto (*xs)[:]` is moved to `auto[:] *xs` and then mended as any pointer to a slice. `parse_for_fix` reads a text that today's lexer refuses (it has `#` comments) with the own syntax's parser, so the old forms left in it (a function-pointer field) are still mended and a struct does not stay with its `};`.
- The parse fixes are F2 (declarations), F3 (statements) and F4 (expressions) above, each with its goldens `old_*.txt`; F1's are the warnings those record.
- The checker's fixes (M1, #1516): `fix_text` runs `types_decl::check_module` when the parse has no error that is not a warning; a `types::Error` has a `fix` too (`types::fail_fix`).
- A discarded value (#1915): a cast to `Void` (`(void)x;`) is refused with the fix `_ := x` (`discard_fix` in `front/types_decl.smith`: the cast's head, up to its operand, becomes `_ := `); a bare `_ = x` stays an error that says to write `_ := x`.
- Assigning to a name declared without `mut` inserts `mut ` before its name (a local or parameter, not `const`, not after an attribute).
- Writing through a `*T` turns the declaration's `*T` into `*mut T`; when that pointer is `p := &x` of a constant `x`, the fix adds `mut` to `x`.
- No fix removes a `mut`. In smith's own syntax `*T` is read-only (`pointee_const`) and `*mut T` writable.
- A slice field keeps C's mutability (#3073, `writable_dims` in `front/parse_decl.smith`): `T xs[:];` in a record is `xs: []mut T` and `const T xs[:];` is `xs: []T`, since today's two are different structs (`smith_array_T_n`, `smith_array_const_T_n`) and a field is shared by every function, so no checker fix reaches it. A parameter or a local stays `[]T`: C never made a slice's elements const through a `const` record, so a writable one refuses the field of a `*T` record (`args: []mut ExprRef = call.args`); the checker's fixes widen a parameter that needs it. Test: `tests/front_parse_decl_test.smith`.
- A top-level `if constexpr (c) { A } else if constexpr (d) { B } else { C }` of the old syntax (#2142, `parse_decl::parse_one`) carries one warning whose fix writes `@when(c)` before each declaration and import of `A`, `@when(!c && d)` before `B` and `@when(!c && !d)` before `C`, and removes the block's lines (and `import target;`, since `target` is built in). `target::os == target::macos` is written `target.os == .macos`; only conditions made of `target.os`, `.macos`, `.linux`, `true`, `false`, `!`, `&&`, `||` are mended (a constant or `target.arch` keeps the block as it is), as is not a nested block. In a file in smith's own syntax `if constexpr (c) {` at the top level is a parser error (`if c:` is the form there, #2191).
- Preprocessor lines (#1748, `front/fix_directive.smith`): the error of the first `#` carries one fix for every simple line in the file: `#define N 4` becomes `const N = 4` and `#include <h.h>` becomes `import c <h.h>`. `#if defined(__APPLE__)` / `defined(__linux__)` (also `#ifdef`, `#ifndef`, `!`, `#elif`, `#else`) around whole top-level declarations becomes `@when(target.os == .macos)` (`.linux`, `!=` for the `#else`) on each declaration, the `#if`/`#else`/`#endif` lines removed (#1801); `#include "h"` becomes `import c "h"` (#3027). `#if 0` and `#if 1` (with `#else`, at any depth, in a function too) keep the live branch and drop the dead one with the directive lines, when each branch has balanced braces (#3027). An `#if` about anything else (a macro of the file's own), nested or around another directive keeps the error with no fix, as do `#pragma`, `#error`, `#undef` and a function-like `#define`.
- `==` on slices and `str` (#2540, owner 2026-11-06: "== should be the way to compare things"): `a == b` and `a != b` on two slices of one scalar element type, or two `str`, compare the counts, then the elements (a `memcmp` for integers and pointers, a loop with `fcmp` for floats, so `0.0 == -0.0` and `NaN != NaN`). `front/types_expr.smith` accepts it; `front/emit_control.smith` emits it; `front/fix_equal.smith` rewrites `mem::equal(a, b)` to `a == b` and `!mem::equal(a, b)` to `a != b`. Slices of records, slices and tuples wait for #2514. `mem.equal` stays until #1631 converts its callers. Tested by `tests/front_emit_slice_equal_test.smith` and `tests/front_fix_equal_test.smith`.
- Method calls (#1797, `front/fix_method.smith`, skill `smith-lang-methods`): after a clean check, `fix::checker_fixes` makes one fix for each call `m.f(a, ...)` where `m` is an imported module, `a` has a record type `m` defines and `f` is a `pub` function of `m` taking that type first; it writes `a.f(...)` (the receiver of `&x` is `x`). It needs the modules read, so `fix_run` sets a loader over `src/` and `lib/`; without a loader (`fix::set_loader`) nothing is rewritten. Tested by `tests/front_fix_method_test.smith`.
- `{}` of a struct (#2224, decided on #1406, `front/fix_zero.smith`): `fix::checker_fixes` resolves the declared type of `let x: T = {}` and writes every field with its zero value (`T(a = 0, p = nullptr)`: numbers, `Bool`, pointers, arrays of those up to 64 elements, and structs of those one level down), or `= undefined` when the statements right after the declaration, in the same block, assign every field by name without reading the variable. A struct with any other field, `struct smith_array_T_n` and `typeof(xs) r = {}` keep the parser's warning (listed as gaps). Tested by `tests/front_fix_zero_test.smith`.
- A struct declared twice (#2224, `front/fix_opaque.smith`): `typedef struct Tag Name;` is read as the opaque `@c_name("Tag") pub struct Name`, and a plain `struct Name {...}` later in the file completes it. `fix_text` removes the opaque line and writes its attributes and `pub` before the definition (the fields stay private). It runs on every parse, even while the file still has other forms to mend. Tested by `tests/front_fix_opaque_test.smith`.
- `typeof` of a slice parameter (#2340, `front/fix_typeof.smith`): `fn realloc(auto xs, ...)` whose body reads `xs.data` or `xs.count` and names `typeof(xs)`, `typeof(xs.data)` or `typeof(xs.data.*)` becomes `realloc[T](xs: []mut T, ...)` with `[]mut T`, `*mut T` and `T` (`[]T` and `*T` when the body never writes through `xs` or builds a value of its type). A function with two `auto` parameters, an `auto` that is not a slice, or a `typeof` of another expression is left alone. `typeof([]u8)`, a `typeof` of a type written out, is that type. Tested by `tests/front_fix_typeof_test.smith`.
- More `fix_typeof` rules (#2668, fixer B; decided on #1406). A `typeof(x)` that is compared (`==`, `!=`) with a C pointer or slice struct written out is that type in smith's spelling: `char *` is `*mut char`, `const char *` is `*char`, `struct smith_array_char_n` is `[]mut char` and `struct smith_array_const_char_n` is `[]char` (a bare `*char` in an expression would read as the dereference `char.*`). An `auto` parameter whose `typeof` is compared like that stays `auto`: it is not a slice. A pointer to a slice of `auto`, `const auto (*xs)[:]`, is generic in the element (`fn f[T](xs: *mut []T, ...)`, `typeof((xs.*)[0])` is `T`, `typeof((xs.*)[0:0])` is `[]T`). A built-in concept as the element of a parameter's type (`Num xs[:]`, `Int *p`, `Float grid[:][:]`) is an inferred parameter of that concept, one letter each (`fn find[T: num](xs: []T, ...)`); a module that declares a type of that name has no concept of it. Tests: `tests/front_fix_typeof_test.smith`.
- Generic bodies the checker cannot reach (#2668, `front/fix_generic_mut.smith`; the checker's `mut` fix does not reach a generic instantiated from another module, #2386): a pointer parameter that is written through, or handed to a `*mut` parameter or field, is `*mut T`; a pointer local passed whole to a `*mut` parameter is `*mut T` and a value local whose `&x` is passed to one is `mut x` (#2992); a parameter that is assigned is `mut`; a function generic over `T: type` (smith's spelling, which sets no `constexpr` flag) is read as generic too, so `std.arena`'s `push(arena: *Arena, T: type)` that hands `arena` to `push_raw(arena: *mut Arena)` is `*mut Arena` (#3078); `return {.some = v}` in a generic whose result is `Option(...)` is `return .some(v)`, as `{.ok = v}` and `{.error = e}` of a `Result(...)` are (#3078: `mem.try_alloc`, `arena.try_push`); a `for constexpr (Usize i = 0; i < countof(P); i++)` over `fields(T)` or over a pack whose body uses `i` only as `P[i]` is `for f in P:` (the name bound by a first line `constexpr Field f = P[i]` is kept and the line removed), and a loop that uses `i` otherwise is left (a pack read at a run-time index is an error: `std.format.write` waits for D20). Tests: `tests/front_fix_generic_mut_test.smith`.
- An `auto` parameter is typed by the concept its body uses it as (#2668, `front/fix_concept.smith`): arithmetic only is `num`, a read through `p.*` is `pointer`, a call used as a test (`while pred(xs[n])`) in a function that already has `[T]` is `fn(T) -> bool` (`fn(T, T) -> bool` for two arguments); an `xs: []auto` is `[T](xs: []T)` whatever the body does (`front/fix_typeof.smith`), and the plain `auto` beside it is a concept. An `auto` whose type the signature names again (`sqrt(x: auto) -> typeof(x)`, `pow(x: auto, y: typeof(x))`) is an inferred parameter: `sqrt[T](x: T) -> T`, `pow[T](x: T, y: T)` (`same_type_fix` in `front/fix_typeof.smith`, a letter each for up to four; `typeof(x)` in the body stays). A use as `x.to(..)`, `xs[i]` or `p += 1` leaves the `auto`. Written later, when the checker has them: `any` (reflected on or handed on; waits for `std.prelude`, #2669) and `int` (integer operations only; while a file is mended `types::c_type_fix` reads `int` as the C type and writes `i32`). Any other use (indexed, compared, a field) stays `auto` and is listed for a hand fix. Tests: `tests/front_fix_concept_test.smith`.
- The zero value of a type known only at compile time (#2668, `front/fix_alloc.smith`, D10 decided on #1406): `(typeof(a)){0}`, `(typeof(a)){}` and `(T){0}` for a `constexpr Type T` parameter are `mem.zeroed(typeof(a))` / `mem.zeroed(T)`, with `import std.mem` added once. It runs on the text before the parse, like the other `fix_alloc` rules. Tested by `tests/front_fix_alloc_test.smith`.
- Read-only and pointer `auto` (#2668, `front/fix_typeof.smith`): `xs: []auto` (from `const auto xs[:]`), `p: *auto` / `*mut auto` and `m: [][]auto` that a later parameter or the result spells with `typeof(xs[0])`, `typeof(p.*)` or `typeof(m[0][0])` make the function generic in `T`: `fn find[T](xs: []T, v: T)`, `fn bump[T](p: *mut T, by: T)`. A function that compares `typeof(x)` or asks `is_slice(typeof(x))` (any `is_*` predicate) of the parameter takes more than one kind of argument, and is left alone (`mem::zero`, `format::make_padded`). `format::write` walks its pieces by recursion (`write_pieces` with `Slot`, `char[n]` for the n-th piece), not by an index, so the fixer needs no number for a pack element. Tested by `tests/front_fix_typeof_test.smith`.
- Tuple index (#2668, `front/fix_method.smith`): `t[0]` over a tuple is written `t.0` (an index with a literal number whose base the checker typed as a tuple; the checker rejects the index, so `fix_method::tuple_edits` reads it off a module that has errors). `fix::checker_fixes` must call it beside `fix_method::edits`, which runs only for a module with no errors. Tested by `tests/front_fix_method_test.smith`.
- Today's magic slice struct of a type parameter (#3078, `front/fix_typeof.smith`, `magic_slice_locals`): in a function generic over `T: type`, `struct smith_array_T_n result = {};` is the slice the instance builds and returns (`std.mem.view`), which the fixer read as the C struct `c.smith_array_T_n` that no header declares; it is `mut result: <the function's result type> = undefined`, and its `data` and `count` are written as before, except that when the result is a read-only `[]T` the line `result.data = x.cast(*mut T)` (today's `(T *)x`) is `x.cast(*T)` (`readonly_data_casts`): a cast to `*mut` of read-only bytes is refused, and the slice's pointer is read-only anyway. The old pipeline needs the struct in a generic body (it neither slices a pointer nor takes `countof` of a slice there), so the library keeps it. Tested by `tests/front_fix_typeof_test.smith`, `tests/front/e2e/std_generic_instances.smith` (two types) and `tests/front/e2e/std_view_read_only.smith` (a write through the pointer of the `[]T` it returns, `words.data[0] = 0`, is refused; the cases spell the fixed form inline, since the e2e corpus imports only std modules already in smith's own syntax).
- A C pointer type compared with `==` or `!=` in the passes before a file reads as smith's own syntax (#3078, `front/parse_type.smith`, `compared_type`): the parser's old-type warning writes it as it writes a cast, `typeof(piece) == char *` is `*mut char` and `const char *` is `*char`, so `std.format.put`'s two tests stay apart (both were `*char`, and the second instance had no rule). Tested by `tests/front_fix_typeof_test.smith`.
- Empty string (#2648, `fix_zero::empty_strings`): C's `Str none = {};` reaches the checker as `none: str = {}`, which it refuses ("a `{...}` list makes a struct ... not a `Str`") without a fix; the fixer writes `""` for that `{}`. Tested by `tests/front_fix_empty_str_test.smith`.
- Field named `type` (#2648, `rename_type_names` in `front/fix.smith`; `f(x)->type = v` is a field too, not a function head's `-> type`): a field declared `type;` in a `struct` or `union` body is `ty` like every use after `.` or `->`, even when the text has a `ty` of its own (any other `type` there is `ty_`). Before, `Signature.type` became `ty_` while `sig->type` in the same file became `ty`, so the checker said "`Signature` has no field `ty`". Tested by `tests/front_fix_decl_forms_test.smith`.
- Option parameter (#2648, `front/fix_optional.smith`, called by `fix_zero::edits`): a function of the same module that tests a pointer parameter against `nullptr` and is called with an option (`list.default_value`, a field that is `?*T`) takes `?*T`; the fix inserts the `?`, and the checker's option guard writes the `.none` tests on the next pass. The checker poisons the refused argument, so the option is read off the field's declaration. An option parameter that the body assigns (`mut old: ?*T`, which a `mut` name cannot narrow) loses its `mut`, and after the guard `if old == .none: return ...` a local `mut old_some: *T = old` takes its place for the rest of the body (`fix_optional::reassigned`). Tested by `tests/front_fix_optional_test.smith`.
- Enum variants (#2098, `front/fix_variants.smith`): `smith lint --fix` with several files fixes each, then renames the variants of every enum they declare to lowercase in all of them together, since a variant is declared in one file and used in others (`files.NotFound`, `return NotFound`). A declaration or a name after `.` or `::` becomes `snake_case` (`NotFound` is `not_found`), any other use `.snake_case`; a result that is a keyword gets a `_`; a variant named like a struct, enum or union of the files is left as written; an attribute written before a variant (`@c_name`) stays. The module-level C names (`SmithFilesError_NotFound`) come from the old lowering and are not emitted by the new front end. Tested by `tests/front_fix_variants_test.smith`.
- The std core modules (#2224, part of #2053): `smith lint --fix` mends five more forms of `lib/std/{mem,contract,arena,format,option,result,slice,console,test}`. A payload written type first (`T some;` in an enum) no longer makes `T` a variant, so a type parameter is not renamed to `.t` (`front/fix_variants.smith`). A group of attributes, `[[gnu::always_inline, maybe_unused]]`, is mapped member by member (`@inline`; `maybe_unused` on a function is dropped). An `extern` prototype, `extern void f(A a);`, is `extern fn f(a: A)` with the `;` removed, and `auto x` is `x: auto`. `sizeof(T *)` is read as a type, so the fixer writes `sizeof(*T)` and not the dereference `T.*` (`typeof_new_type_at` in `front/parse_type.smith`). `struct Pair p` and `struct c::stat st` drop the keyword, and a lowercase C tag gets its `c::`. Test: `tests/front_fix_std_core_test.smith`, `tests/front_fix_variants_test.smith`. Second slice (#2224): a type ends at its line break in smith's own syntax, so a `const` on the next line (after a comment line) is no qualifier of the type before it (`pub let LR = Result(Line, Error)`, a comment, `const x = 1` joined into one line, `suffixes` in `front/parse_type.smith`); an `if c: a else: b` in an argument list ends at the `,` or `)` (`end_statement` in `front/parse_stmt.smith`). With these `console` and `contract` parse; the first error of `contract` is now in the checker (`c.` names of an imported header, `_`, `target`), of `mem` a `{}` of a C struct, a C `for` over a pointer and `__asm__`, of `slice` a `restrict` slice (no spelling, asked on #1406). Third slice (#2224): a global array literal followed by a line that starts with a name (`let a = [1, 2]` then `let b`) is no longer read as an array type `[2]b` (`starts_new_type` in `front/parse_type.smith`); `extern T f(A a) __asm__("sym");` is `extern @c_name("sym") fn f(a: A) -> T` (`asm_label_end` in `front/parse_decl.smith`).
- Fixer ordering (#2648): `mend_passes` merges the checker's fixes (`types_decl`) with the parser's in the same pass, so two rules can meet. (1) A checker insert at the first byte of a text the parser replaces in that pass would land before the new text (`?e: *T = x`); `inserts_at_replaced_start` holds it for the next pass, which reads the mended text (`e: ?*T = x`). Test: `tests/front_fix_zero_test.smith`. (2) In pass 0 of a file that still has old forms and tests a `Result` (`Result(` and `.error` in the text) the checker waits one pass, so its `try` guard is made from the mended declaration (`ok := try ...`) and not dropped one edit at a time. Test: `tests/front_fix_decl_forms_test.smith`. (3) `T` after the colon of an enum payload (`Type T` below `name: (a: T)`) is a type, not a variant to write `.t` (`body_start` in `front/fix_variants.smith`); a `str` struct field of another module gets `""` in a zeroed construction (`scalar_zero`). Open, owned by the checker (#2647): a leaving `.error` test whose body builds a value and returns (not an error to propagate) has no `try` form; a function that returns `nullptr` in some paths and a pointer field read in others stays `-> TypeRef` (no `-> ?TypeRef` rule yet).
- Tests: `tests/front_fix_test.smith`, `tests/front_fix_mut_test.smith`.
