# Return types and function names (`front/parse_type.smith`, `front/parse_decl.smith`, #1959)

- A function's return type may be any type the type grammar reads, including a call of a type function (`Option(T)`) and one through a module in smith's own syntax (`-> arena.slice_of(T, countof(dims))`: `parse_type::qualified_type_function` joins `.name(` to the path and reads the arguments as an applied type). A `.` after a type that is not followed by `name(` still ends the type.
- A type function (`-> type`) whose last line is an unnamed `enum:` or `struct:` block declares the type each call returns (`Option(T)`, `Pair(T)`); the checker does not walk such a body (`types_decl::declares_type`), and `Option`/`Result` are the checker's own types, so `lib/std/option.smith` and `result.smith` pass (#2251). The fixer writes the old `return enum { T some; none; };` as that block (`parse_decl::fix_returned_tag`). A user type function other than those still stops at `not yet typed: the applied type` (instances and their C names are open).
- `type` is a keyword where a type is expected, and a function may be named `type` (`pub fn type(p: *parser) -> *node:`). Tests: `tests/front_parse_type_call_test.smith`.
- Generic functions are emitted per instance (#1909): `emit::declare_all` skips a template (a function with a `T: type` or `const n` parameter) and declares one internal function per `types::Checked.instances` entry, named `pick.i32` or `table.64` (`module::pick.i32`), typed from the instance's signature. The checker records each call of a generic function with its instance (`types::use_instance`, `instance_called`); `emit_call` calls that instance and drops the type and constant arguments. The constants of an instance (`n`) are locals holding the value. Not yet: a type written in an instance's body (`let x: T`), and instances of an imported template.
- `rest...` (#1821, piece 1): a function with a positional pack as its last parameter is a template like one with an `auto` parameter. `types_expr::pack_before` rewrites each call (recorded with `types::set_method`): the arguments after the fixed parameters become one tuple literal, passed as the last argument; the instance for that tuple type is the call's, so each list of argument types is its own instance. Inside the body the pack is that tuple: `rest.0`, `countof(rest)`. A named argument to a pack is an error. Typed packs (#1821, piece 3): `nums: i32...` expects a tuple of `i32`, so each leftover argument is checked against `i32` like any argument (an implicit conversion, else an error at that argument; `types_expr::pack_expected` gives the tuple its expected type and `tuple_after` converts each element to its expected one). A concept pack `nums: int...` keeps each argument's own type and `pack_satisfies` rejects one outside the concept (`types::written_concept`, `concept_holds`). `rest: ...` is a parse error whose fix writes `rest...`. `for x in rest:` unrolls (#2293, piece 2): `types::instance_of` clones the template with `ast_clone::clone_decl_unrolling`, which replaces the loop by a block of one copy of the body per element of the tuple, each beginning `let x = rest.i` (distinct nodes, so each copy is typed with its own element type; an empty pack runs no body). `rest...` in a call spreads the tuple into positions, `rest.0, rest.1, ...` (`types_expr::spread_positions`, the same stage as the named spread); a value that is not a tuple gets an error that says to pass a slice `[]T`. An index past the pack is the tuple's own out-of-range error. `fields(T)` and `parameters(F)` are piece 4 (below). Test: `tests/front_pack_test.smith`.
- `fields(T)` and `parameters(F)` (#2295, piece 4 of #1821): compile-time lists, expanded in the tree before a body is checked (`ast_clone::expand_reflection_lists`, called by `types::expand_reflection` for each function in `types::check` and for each instance right after its compile-time parameters are bound in `types::instance_of`, so `T` is known). `for f in fields(T):` becomes a block with one rewritten copy of the body per entry (`clone_stmt_rewriting` with a statement and an expression chooser; `ast_clone` puts the outer choosers back, so nesting works); in a copy `f.name` and `f.doc` are string literals, `f.default` is the field's default expression (`Slot.default_value`; on a field with none, the error "`y` has no default", #2543), `f.type` is a type value of the field's type written in smith's own syntax (`i32`, lowercase builtins, `types::written_name`; `sizeof(f.type)` and the like become a query of that type), `value.[f]` is `value.<field>`, `fields(T)[2]` and `countof(fields(T))` take a compile-time index (a number literal) and the count, `let first = fields(T)[0]` makes `first` stand for the entry (no code), and `if let .some(a) = f.attr(X): ... else: ...` is decided at compile time: the `then` branch with `let a = X(args)` when the field has the attribute `X`, else the `else` branch (`.attr(X)` is supported in that `if let` form only). `types.smith` supplies the entries (`Slot.doc` and `Slot.attributes` come from `FieldDecl`; `types::field_visible` hides the private fields of a record from another module, #1787). A subject that is not known at that point (a generic function's own `T`, a name that is neither a struct nor a function) leaves the expression alone, and the checker reports it as an unknown name. A field's `##` comment is read by `parse_decl::doc_above` (the comment lines directly above the field, attribute lines between skipped). `parameters(F)` lists the parameters of a function named `F` (a plain function, not a template): `.name`, `.type`, `.attr(X)`. Not here: `parameters(F)` defaults and `methods(T)`. Tests: `tests/front_reflect_test.smith`, e2e `tests/front/e2e/reflect.smith`.
- `; kw...` (#1985, part of #1914): a function with a gather parameter is a template like one with an `auto` parameter. `types_expr::gather_before` rewrites each call (recorded with `types::set_method`, as a spread is): the named arguments no parameter has become one named tuple, `(count = n, ms = ms)` (`()` with none), passed as the last argument by the gather parameter's name; the instance for that tuple type is the call's (`info.(count = i32, ms = i32)`-style key), and `emit_call::callee_of` finds it through the rewritten call. A name given twice, a missing parameter or too many arguments is an error; without `; kw...` an unknown name is still one. `fn f(x: str, xs...; kw...)` is not supported yet (a pack and a gather together). Test: `tests/front_kw_gather_test.smith`, e2e `tests/front/e2e/kw_gather.smith`.
- A braced list of an option or a Result (#2563): `{.some = v}`, `{.ok = v}`, `{.error = e}` is refused where the checker knows the type, with a fix-it that writes `.some(v)`, `.ok(v)`, `.error(e)` (`types_expr::refuse_variant_list`; no fix when the list is written with a type, `(T){...}`). A struct with a field named `ok` is a construction and never reaches this rule. Test: `tests/front_fix_option_literal_test.smith`. The last line of a body counts too (#2575): the statement parser reads a line that starts `{.name =` as a list, not a block, so `{.ok = n}` in tail position gets the same fix-it; `fix_blocks` joins a `.name` line to the line before only when it is indented under its statement, so the `.ok(n)` it writes stays on its own line after a nested block.
- Constants and headers in the fixer (#2625): `literal_of` (`front/types_decl.smith`) folds two integer literals joined by `<<`, `*`, `+` or `|` (`1U << 22`, `64 * 1024`) into a constant, so the argument converts like a literal when it fits (`test.memory(1U << 22)` no longer says `expected Usize, found U32`: 75 first errors in `tests/*.smith`). The fixer's checker always has the header loader (`front/fix.smith`): a module that imports `std.arena` sees `c::SmithAllocator`, so `&allocator.base` handed to `mem.set_allocator` gets `mut allocator` (32 first errors, `expected c::SmithAllocator *, found const c::SmithAllocator *`); before, the fixer's check saw no error there and the final check did.
- `==` and `!=` over two `?*T` of one type compare as the pointers they are (null for `.none`, #2205, #2647); `<` and the like stay refused. Test: `tests/front_types_method_test.smith`.
- A variable of an anonymous struct type (`static struct { alignas(16) U8 bytes[8]; } memory;`, #2649) is mended in two steps: `hoist_record` (`front/parse_decl.smith`) writes `struct Memory {...};` at the end of the file and `Memory memory;` in place (a struct declared inside a function is not typed), and the next round mends both as usual, so `alignas` stays `@align` on the field. The name is the variable's in PascalCase, with `Storage` added while the file uses it. Test: `tests/front_parse_decl_test.smith`.
- A call in tail position is a guaranteed tail call (#2709): `emit::return_finish` calls `emit_call::mark_tail_call`, which sets LLVM `musttail` when the call is the last instruction of the block (no `defer` pending) and the caller and callee have the same function type and calling convention; `emit_call::check_recursion` runs on the module before it is verified and reports the first call that is not a tail call on a cycle of the module's functions (`recursion in a module: a -> b -> a`, with the reason when the callee's function type differs from the caller's); a last-line `if` or `match` has each arm written as a `return` (`emit::returning_if`, `returning_match`) so a call ending an arm is a tail call; a call that closes a cycle and is not a tail call is lowered by `front/emit_recursion.smith` (#2710, knowledge/recursion.md), and a call through a `fn` value is a possible edge to every address-taken function of its type. The fixer deletes `[[clang::musttail]]` before a `return` (`parse_stmt::drop_musttail`). Tests: `tests/front/e2e/tail_call*.smith`, `recursion_*.smith`.
- A struct or array of more than 64 bytes is never a first-class LLVM value (#3058): `front/emit_aggregate.smith` runs on the finished module, after `emit_call::check_recursion` and before it is verified, and gives every such value a home in memory (a slot of the entry block, a private constant, or the pointer of a parameter), so a load, store, `ret`, `extractvalue`, `insertvalue`, `phi` or `select` of one is a `memcpy` or a GEP. A function whose result is one takes a hidden first `sret` pointer and returns void; a parameter that is one is a pointer: `byval` on x86-64 System V, a pointer to a copy the caller made elsewhere (AArch64, Windows). That is each C ABI's own rule for a struct this size, so C callers and callees keep the C ABI, and smith-to-smith calls use the same rule; a `musttail` call with such an argument becomes an ordinary call. Small aggregates keep their first-class value. Before it, LLVM's code generator split the value into one load or store per element and clustered the loads in worse than linear time: a struct with a `[16384]char` field returned by value took 27 s to compile, `lib/std/console_test.smith` more than 30 minutes. Tests: `tests/front_emit_aggregate_test.smith` (the IR, the C ABI both ways through the JIT), `tests/front/e2e/big_aggregate.smith`.
