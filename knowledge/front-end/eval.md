# front::eval (`front/eval.smith`, #3039)

The value of an expression known at compile time: one evaluator, asked by every place that needs a constant. It is an interpreter over the checked tree, not the JIT (the JIT would give the host's answers when cross-compiling and has no limits), and it replaced the six places that each folded their own subset (`types::constant_length` and `constant_case`, `types_attr::is_constant`'s names, `types_decl::query_answer`, the emitter's `static_assert_finish` and `constant_if`).

- `eval::value(r, e)` gives an `Outcome`: `known` with a `Value`, or not known with the reason and the place (`why`, `at`), or `failed`, an error of the computation itself. A `Value` is an integer (sign and 64-bit magnitude, with the type an operand gave it, or none for bare literals), a Bool, a float, an enumerator, a type, or a fact of the target that is one of a set of names (`target.os`). Structs, arrays, strings and pointers are step 3.
- What it computes (step 1): literals; names of constants (read through modules and C headers: `const`, a `let` that is not `mut`, a compile-time parameter bound in an instance); `+ - * / % << >> & | ^ ~`, comparisons, `and`, `or` and `not` (the right side of `and`/`or` is read only when the left does not decide); `x.to(T)` and `x.wrap(T)`; `sizeof`, `alignof`, `countof` of an array, a pack and `fields(T)`; types as values (`u8 != T`, `typeof(x) == []u8`); the built-in questions and concepts (`is_integer(T)`, `num(T)`); a call of a concept function (every parameter a `type`, the result `bool`, the body one expression), answered by its body with the parameters bound; `if c: a else: b` as a value; and `target.<fact>`.
- Errors of the computation: an integer result that does not fit its type ("this overflows `I32` at compile time: 2147483647 + 1"), a division by zero, a shift by the width or more, `x.to(T)` of a value `T` cannot hold. Arithmetic on bare literals is exact in 64 bits; past that the value is not known.
- No recursion (the old front end builds this file): an explicit stack of steps and one of values. Limits (one function each: `step_limit`, `depth_limit`): 1,048,576 steps and 512 names or calls deep; the error says which.
- Which functions run is one function, `eval::may_run`: in step 1 only a concept function. Any other call is not known, with the reason ("`sq(...)` is a call, and a function is not run at compile time yet; write the value"). Step 2 makes it any function over scalars and types.
- The target's facts are one function, `eval::target_fact`: `os` and `arch` (names: `.macos`, `.linux`; `.aarch64`, `.x86_64`), `f32_mantissa_bits`, `f64_mantissa_bits`, `float_radix`, `float_eval_method`, `fast_math`, `static_analyzer`, the sanitizers and `assertions`. They describe the system smith runs on and smith's own build, as before, until a compile names another target. `types_expr::fold_target` writes a number or a Bool fact into its node as a literal; `target.os == .linux` is computed whole.
- Who asks. `front::types` cannot import the evaluator (which reads the checker's tables), so it asks through `types::Options`: `length` (an array length, `slice_of`'s count) and `constant` (the type of a constant written without one). `types_decl`: an `if` whose condition has a known Bool keeps one branch (`set_decided`; the other is neither checked nor emitted), in any body, an instance's included, so `if sizeof(T) == 4:` and `if target.arch == .aarch64 and small(T):` choose per instance; a condition that names `target` and is not known is an error with the reason. `static_assert` is computed by the checker, at module level and in a body (per instance): false is the message, not known is "static_assert needs a condition known at compile time: " and the reason; the emitter emits nothing for it. `types_expr`: a `match` pattern's value (`eval::bits`); a comparison of types or of a named fact, and a call of a concept, where a value is wanted (`x := small(u8)`): the Bool is recorded for the node per instance (`types::set_value`) and the emitter writes the constant (`value_in`). `emit::fold_constant` asks for a global's number or Bool before it builds and folds the initializer with LLVM, which stays for the values step 3 brings.
- Tests: `tests/front_eval_test.smith` (values and reasons), and the corpus cases `tests/front/e2e/eval_*.smith`.
