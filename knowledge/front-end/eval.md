# front::eval (`front/eval.smith`, #3039)

The value of an expression known at compile time: one evaluator, asked by every place that needs a constant. It is an interpreter over the checked tree, not the JIT (the JIT would give the host's answers when cross-compiling and has no limits), and it replaced the six places that each folded their own subset (`types::constant_length` and `constant_case`, `types_attr::is_constant`'s names, `types_decl::query_answer`, the emitter's `static_assert_finish` and `constant_if`).

- `eval::value(r, e)` gives an `Outcome`: `known` with a `Value`, or not known with the reason and the place (`why`, `at`), or `failed`, an error of the computation itself. A `Value` is an integer (sign and 64-bit magnitude, with the type an operand gave it, or none for bare literals), a Bool, a float, an enumerator, a type, or a fact of the target that is one of a set of names (`target.os`). A statement with no value is `nothing`. Structs, arrays and strings are values with memory (below); pointers are not yet.
- What it computes (step 1): literals; names of constants (read through modules and C headers: `const`, a `let` that is not `mut`, a compile-time parameter bound in an instance); `+ - * / % << >> & | ^ ~`, comparisons, `and`, `or` and `not` (the right side of `and`/`or` is read only when the left does not decide); `x.to(T)` and `x.wrap(T)`; `sizeof`, `alignof`, `countof` of an array, a pack and `fields(T)`; types as values (`u8 != T`, `typeof(x) == []u8`); the built-in questions and concepts (`is_integer(T)`, `num(T)`); a call of a concept function (every parameter a `type`, the result `bool`, the body one expression), answered by its body with the parameters bound; `if c: a else: b` as a value; and `target.<fact>`.
- Errors of the computation: an integer result that does not fit its type ("this overflows `I32` at compile time: 2147483647 + 1"), a division by zero, a shift by the width or more, `x.to(T)` of a value `T` cannot hold. Arithmetic on bare literals is exact in 64 bits; past that the value is not known.
- No recursion (the old front end builds this file): an explicit stack of steps and one of values. Limits (one function each: `step_limit`, `depth_limit`): 1,048,576 steps and 512 names or calls deep; the error says which and names the call.
- Functions run (step 2). A call of a smith function with a body runs: its arguments are computed and coerced to the parameters' types (`[T]` names are bound from the arguments, defaults are read in the function's module), and the body's statements run: declarations, assignment (`=`, `+=` and the others) to a `mut` local, `if`, `while`, `for i in range(a, b)` (and `a..b`), `match` on a number, Bool, enumerator or type, `break`, `continue`, `return`, `assert`, `static_assert`, and a block's last line as its value. Every statement leaves one value on the stack (`nothing` when it has none). A call is refused with the reason, wrapped as "`f(1)` cannot run at compile time: why": a C or `extern` function ("`strlen` is a C function; only smith functions run at compile time"), a `mut` global read, named, spread or packed arguments, and a value with memory (an array, a slice, a string, a struct or a pointer: step 3). `contract.requires`, `assert` and `invariant` are checked ("`contract.requires` fails at compile time"); `ensures` and `modifies` are skipped. An error inside a call names the chain: "this divides by zero at compile time (in `divide(0)`, called from `through(2)`)". The limits' errors: "`deep(0)` is 512 calls deep at compile time; the recursion does not end" and "`spin(1)` ran 1048576 steps at compile time without finishing; a loop here does not end, or the work belongs at run time".
- Type functions (step 2). A function whose result is `type` runs like any other and its value is a type: `fn widen(T: type) -> type: if sizeof(T) < 4: i32 else: T`. It is called where a type is written (a parameter, a result `-> widen(T)`, a local `x: widen(T)`, `sizeof(widen(i16))`), as a value (`widen(u8) == i32`), and as an alias (`W := widen(T)` in a body, `IntPair := pair(i32)` at module level, where the function is declared above the alias). A body that is the one unnamed `struct:` or `enum:` makes a type named after the call (`m::pair(I32)`), one per set of arguments (`types::unnamed_type`, memoised in `Checked.made`); it is built with `pair(i32)(1, 2)` or through its alias. The checker asks through `types::Options.applied` (a written type that is a call: `eval::applied_for`) and `held` (an initializer that is a call of a type function: `eval::held_for`); the type of each such place is recorded per instance (`types::applied_type`, `types::held_type`), which is what the emitter reads (`records::from_made`, `matching::enum_from_checked`, `emit_call::made_record`). A function whose result is `type` is never emitted.
- `slice.with_dims(T, k)` of std.slice is built in (a function over types cannot write `[,]T`): the slice of `k` run-time dimensions over `T`, so `slice.with_dims(f32, 2)` is `[,]f32` and `slice.with_dims(f32, 1)` is `[]mut f32` (the memory an allocator hands out is written). A count of 0 or one not known at compile time is an error. std.arena's `slice_of` is the same function under its old name: std.arena and std.mem keep it until the old front end can read `slice::with_dims` from them (it defines a function over types only in a module that imports its module directly). `types::is_with_dims` is the one place that names both.
- An `if` that no rule requires to be decided still runs its condition's functions, leniently (`eval::tried`): known keeps one branch, not known or failed inside a call leaves the `if` to run time.
- The target's facts are one function, `eval::target_fact`: `os` and `arch` (names: `.macos`, `.linux`; `.aarch64`, `.x86_64`), `f32_mantissa_bits`, `f64_mantissa_bits`, `float_radix`, `float_eval_method`, `fast_math`, `static_analyzer`, the sanitizers and `assertions`. They describe the system smith runs on and smith's own build, as before, until a compile names another target. `types_expr::fold_target` writes a number or a Bool fact into its node as a literal; `target.os == .linux` is computed whole.
- Who asks. `front::types` cannot import the evaluator (which reads the checker's tables), so it asks through `types::Options`: `length` (an array length, `slice_of`'s count) and `constant` (the type of a constant written without one). `types_decl`: an `if` whose condition has a known Bool keeps one branch (`set_decided`; the other is neither checked nor emitted), in any body, an instance's included, so `if sizeof(T) == 4:` and `if target.arch == .aarch64 and small(T):` choose per instance; a condition that names `target` and is not known is an error with the reason. `static_assert` is computed by the checker, at module level and in a body (per instance): false is the message, not known is "static_assert needs a condition known at compile time: " and the reason; the emitter emits nothing for it. `types_expr`: a `match` pattern's value (`eval::bits`); a comparison of types or of a named fact, and a call of a concept, where a value is wanted (`x := small(u8)`): the Bool is recorded for the node per instance (`types::set_value`) and the emitter writes the constant (`value_in`). `emit::fold_constant` asks for a global's number or Bool before it builds and folds the initializer with LLVM, which stays for the values step 3 brings.
- Values with memory (step 3). A struct, an array and a string live in a compile-time heap of cells (`Heap`, `Object`; 4,194,304 cells at most, `memory_limit`), reset when the outermost evaluation starts, so an `Outcome`'s objects are valid only until the next evaluation. A `Value` is then also an `aggregate` (object and type) or a `slice` (object, range, type; `str` is a slice of bytes) or `unset` (`undefined`). Aggregates are copied when bound to a local, stored in a cell or passed as an argument (`copied`); slices share cells. It computes: array literals, string literals, struct construction by position or by name with field defaults, `p.x`, `xs[i]` (out of range is an error of the computation), `countof(xs)`, structural `==` on arrays, and writes into places: `x = v`, `x.f op= v`, `xs[i] = v` (the root must be `mut`, unless it holds a slice). Still refused with the reason: `xs[a:b]`, tuple literals, `&x`, and the store behind `mem.alloc` (next). Corpus case: `tests/front/e2e/eval_memory.smith`.
- Tests: `tests/front_eval_test.smith` (values and reasons), and the corpus cases `tests/front/e2e/eval_*.smith`.
