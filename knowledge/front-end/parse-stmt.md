# parse_stmt (`front/parse_stmt.smith`, A4)

`parse_stmt::statement(p)` is the `statement` hook. Goldens: `tests/front/parse_stmt/`; tests: `tests/front_parse_stmt_test.smith` with stub hooks.
- It reads every statement form (blocks, `if`, `if constexpr`, loops, `switch`, jumps, labels, `defer`, `errdefer`, `static_assert`) and a declaration-or-expression with no symbol table.
- Nesting is an explicit stack of frames; after an error the rest of the statement is skipped and an `empty` placeholder stands in, so one mistake gives one error.
- New syntax (S4, #1445): a statement ends at `;`, at the end of its line or before `}`; `return` at the end of a line has no value.
- `if c { } else if d { } else { }` and `while c { }` take no parentheses and require braces; `for x in xs { }`; `for (i, x) in e { }`.
- `if x := opt:` unwraps an option (the pattern `.some(x)`), `if .circle(c) := shape:` tests a variant (its leading `.` kept, as in a `match` arm) and `while item := it.next():` loops while it binds (#2316, `binding_head` in `parse_stmt`); the `while` is read as `while true:` around `if item := it.next(): body else: break`, with `while_stmt.binds` set so the bounded-loop lint lets it be. The old `if let x = o:` and `if let .some(x) = o:` read the same, with a warning whose fix removes `let ` and writes `:=`.
- A pattern may start an `&&` chain in an `if` or a `while` (D12): `if .function(f) := d.kind && f.name == name:` and `while .pointer(p) := base.kind && p.element != .none:`. Any conjunct after the first may be a pattern too (owner, 2026-11-06): `if .call(call) := k && .name(name) := call.callee.kind && name.n > 1:`; each name is in scope in the conjuncts to its right and in the body (`Frame.links`, `chain_if`: the chain is read left to right, folded into nested `if` and `if` with a pattern, all with the one `else`), and a test next to a test stays one `&&` expression. A chain may also start with tests (`ok && .v(x) := k`, lead answer on #2649, 2026-11-07): `lead_ahead` finds a top-level `&&` followed by a binding before the head ends (and no top-level `||`), `read_lead` reads the tests, `Frame.lead` keeps them, and `pattern_if` wraps the pattern's `if` as `if ok: (if .v(x) := k: ...) else: E` (`binding_loop`: `else: break`); the lead tests run first, so the pattern's name is not in scope in them. A function written with no result has no value line (#2669): `Parser.void_body` is set around its body (lambdas reset it), so a refutable binding's last line stays a statement, not `return value`. The parser (`front/parse_stmt.smith`) reads the pattern's value with `Parser.stop_and` set, so the value ends at the first top-level `&&`, and reads the rest of the chain as an expression (`Frame.chain`). It builds `if PATTERN := value: (if chain: then else: E) else: E` (for a `while`, both `else` are `break`), so the checker and the emitter need nothing new: the name is in scope in the chain and the body, not in `E`. The fixer (`types_decl::note_chain_guard`) writes `k == .v && ... k.v ...` this way when the variant test is the first conjunct. Tested in `tests/front_types_payload_test.smith` and `tests/front_check_bind_fix_test.smith`. A function type written first is a local declaration (`parse_type::fn_type_declaration`: `fn(A) -> R name = v`, a `=` after a name before any `:`; a lambda has its `:` first), as an earlier pass leaves it, and an old lambda header may be followed by the new `: body` (`[](../I32 a): a`, a pass mended the body first), so two function-pointer locals set to lambdas in a row are mended whole (`tests/front_fix_fn_alias_test.smith`). The logic words (D19, lead, 2026-11-07): `and`, `or` and `not` replace `&&`, `||` and `!` in the new syntax; the lexer (`identifier_kind`, new syntax only) gives them the kinds `ampersand_ampersand`, `pipe_pipe` and `bang`, so the parser needs nothing else, and the old signs are still read but `parse::advance` records a warning with a fix (`symbolic_logic`: `&&`→`and`, `||`→`or`, `!`→`not `), a warning and not an error so `fix::parse_for_fix` still takes the text as the new syntax. The formatter spaces `not` as a word, and the language server colours the words as keywords.
- `match s { .a => v }` is one arm per line, patterns joined by `,`. Old and new forms are told apart by fixed lookahead (`new_header`, `new_for`).
- Declarations (#2316, which replaced `let` of #1810): `x := 5`, `mut n := 0`, `count: usize = 0`, `mut buf: [4096]u8 = undefined`, `_ := f()` and `const X = v` go through `parse_decl`'s `starts_binding`; `:=` is one token (`lex::colon_equal`), so `x : = 5` is not one. `x = e` always assigns and `:=` always declares: a name already in scope is the shadowing error, which says to assign with `=`. A statement that starts `name:` is a typed declaration when an `=` follows on its line outside brackets (`assigns_on_line`, only with `Parser.new_syntax`; else a label), never a block call: a block call always takes `()` (`html():`). A bare `html:` with an indented block is still read as `html()` with a warning whose fix writes the `()` (`bare_block_statement`). `mut x = 5` is an error whose fix writes `:=`. A binding with no value is an error that says to give one or write `= undefined` (an `extern` one has none: `extern mut errno: i32`); `(q, mut r) := g()` is `destructure`, `mut` marking one name (`Identifier.is_mut`). The old `let` (the name `let` read in context, `let_at`) still parses, with a warning whose fix removes `let ` and writes `:=` where no type is written; the sweep that removes it is a later ticket. The variable node keeps where its name starts (`variable.name_at`), where the checker's fix writes `mut `.
- `yield x` (#1544) is `ast::yield_stmt`, dumped `(yield <value>)`; whether it stands in a generator is the checker's (#1545).
- `errdefer <statement>` is `errdefer_stmt` (A7l, #1356), read like `defer`; that it needs a function returning a `result` or `option` is the checker's rule.
- Old statement forms are warnings with fixes (F3, #1508): a `;` before a line break or `}` is removed; `if (c) s` and `while (c) s` lose parentheses and gain braces.
- C's three-part `for (init; cond; step) { body }` that is not a counting loop is `{ init; while cond { body step; } }` (#1768): the whole `for` is one edit, so the init's own fix runs in the next pass. A body with a `continue` (the step would be skipped), a body without braces and `for constexpr` get a warning with no edits.
- `for (T i = a; i < b; i++)` becomes `for i in range(a, b)`, `for (T x : xs)` becomes `for x in xs`; a fix's edits all apply or none.
- A `switch` with no fall-through becomes `match` (#1569, #2328): each label is `.name`, a constant (`1`, `limit`) or `default`, each body is one expression with `break`, a `return` or `continue`, or several statements ending in `break`, `return` or `continue` (written `label => {` ... `}` until `fix_blocks` makes it `label:` and an indented body; `fix_blocks` also indents the arms of a `match` and writes their `=>` as `:`). A body that falls into the next case, a `break` inside it other than the last statement, or a `default` stacked with another label keeps a warning with no fix; so do `goto` and labels. `match` patterns are variants, constants (`ast::Pattern.constant`) or `_` (`wildcard`).
- `impl`, `&mut` and Rust's `?` at the start of a statement are warnings naming the smith form. A postfix `.` that starts a line after a finished statement does not continue it.
- A type used by its tag is a type name: `struct Pair a = {...};` is a variable of type `Pair`; a lone lowercase tag (`struct stat`) is C's and the error says `struct c::stat`.
- A range `for (T x : xs)` is read with `parse_decl`'s help: `for_stmt.range` holds `xs`, `init` the element and `index` the index declaration.
- A tagged literal, `` asm`...` `` (D7, #2636): the lexer makes one `tagged` token of a name and a backtick text that may span lines, with nothing escaped (`scan_tagged` in `front/lex.smith`); `${` and an unclosed backtick are errors. `parse_decl` reads one at module level as an `asm_decl` (`asm` is the only tag; others say they wait for #2633), the emitter appends the texts of the live `asm_decl`s to the module with `LLVMAppendModuleInlineAsm`, and `@when` chooses among them like any declaration. The old `__asm__("...");` at file scope is fixed to the literal, and the label of an `extern` prototype is consumed by the function. The tree-sitter grammar has `tagged_literal` and an injection keyed on the tag. Test: `tests/front_asm_literal_test.smith`.
- GNU spellings are errors (#1363): extended `__asm__` says to use `optimize::opaque(x)`; a type used as a value, `name name` at a statement start, is a declaration (A7o, #1360).
