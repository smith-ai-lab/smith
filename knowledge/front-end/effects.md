# Effect inference (`front/effects_*.smith`, #1939)

## front::effects_table (`front/effects_table.smith`, #1965, piece 1 of #1939)

- The 13 effect bits and the libc leaf table of `shim/effects_table.h` as data: `describe(set)`, `leaf(name, &set)` (bisection over a sorted table; false for a name the table lacks, which the checker reads as `unknown`). The header stays the source until the plugin is deleted (#1632); `tests/front_effects_table_test.smith` reads it as text and fails when a name or its bits differ. Inference is the IR pass below; ceilings come in #2019.
- `@when(cond)` (#1801, `front/when.smith`) on a top-level declaration or a struct field: `cond` is `target.os == .macos` / `.linux` or `target.arch == .aarch64` / `.x86_64` (or `!=`; the processor is the one smith runs on, #2142), `true`, `false`, `!`, `&&`, `||`. `types_decl::check_module_headers` (and `check_module_with`) checks a module that has one as it is on the system that builds, and only that: a variant whose `@when` does not hold there is neither checked nor emitted, the same rule as a compile-time `if` in a body (#2283, #2323), so an unguarded `import <dlfcn.h>` plus a macOS-only `Dl_info` is no error on Linux (the CI of each system compiles its own variant); a use of a name that is gone there says `` `f` is not declared on linux: it is declared only when <cond> ``. `@when` on an import (#2142) is read like one on a declaration: a header under a `@when` that holds only on the other system is never read, (the same rule, now for every `@when`); on an enumerator, a parameter or anything else it is an error pointing at `if constexpr`; a statement takes no attribute, so a local is a parse error. The generated C header writes each condition as `#if` (`defined(__APPLE__)`, `defined(__linux__)`; a field's `#if` is inside the struct). A file-scope `if cond:` (indented declarations, then `else:` or `else if`; #2191, `parse_decl::parse_one`) is read as an `if_constexpr` declaration, and `when::live_module` replaces it by the branch its condition (the same forms) picks on each system, so the checker sees plain declarations; a condition it cannot read stays and is reported `not yet typed: if constexpr`. Tests: `tests/front_when_test.smith`, `tests/front_header_test.smith`, `tests/front_fix_test.smith`. An `import c` under `@when` has its `#include` in the same `#if` of the header (`length_includes` in `compile.smith`, #2142). The fixer reads `target::arch == target::aarch64` as `target.arch == .aarch64`; a condition on a named constant stays unmended. A condition may also name a boolean constant of the module (`const wide: bool = true`, `constexpr Bool wide = true;`): `holds` reads it from the module's own declarations (`read_constants`, at most 16), a header's `#if` writes its value, and the fixer writes a top-level `if constexpr (wide)` as `@when(wide)` and the `else` as `@when(!(wide))` (#2142); a condition with a call (`sizeof(int)`) is still left.

## front::effects_pass and front::effects_cache (`front/effects_pass.smith`, `front/effects_cache.smith`, #2018, piece 1 of #1939)

- Effect inference is one pass over the unoptimized LLVM IR of the whole build (#1939), the same for smith, C, C++ and Objective-C; `knowledge/effect-inference.md` has the design. `effects_pass::make()` gives a `Graph`; `add_module(&g, ir, &cache)` adds the functions a module defines (internal linkage is named `<module>:<name>`); `solve(&g)` resolves each called name that nothing defines to a leaf (`front::effects_table::leaf`; an `llvm.*` intrinsic is pure but `llvm.trap` and `llvm.debugtrap` are `fails`; any other is `unknown`) and takes the union of the calls' sets to a fixed point. A function adds `globals` itself by a store, `atomicrmw` or `cmpxchg` through a global variable (a function-local static is one in IR), and `unknown` by inline assembly; a call through a pointer is traced as `### front::effects_pass, function values` below (#2020). `set_of(&g, name)` is the set; `cause_of(&g, index, bit)` is the call and source line that first added a bit (the chain of #2019); `find` gives the index.
- `effects_cache::Cache` keeps each function's summary (its own bits and the direct calls, by name and line) by a hash of the IR the pass reads (opcode and line of every instruction, callee and global names), so a function with the same hash is not scanned again. Printing the function to hash it cost most of the pass, so it is not done. Measured in the test build (-O0, ASan) on the IR of `front/emit.smith`, `front/types_expr.smith` and `front/compile.smith` (176 to 382 functions, 1.4 to 3.5 MB of IR text): adding a module 25 to 72 ms, solving 8 to 30 ms. Wiring it into `smith lsp` follows with the ceiling errors (#2019), which is what the editor shows.
- Tests: `tests/front_effects_pass_test.smith` (the sets of the chain functions from IR text, the chain of causes with its line, the cache).

## front::effects_pass, function values (`front/effects_pass.smith`, #2020, piece 3 of #1939)

- A call through a pointer is no longer `unknown`. A call through a **parameter** is "calls parameter k": the function's set leaves it out, and every call site that passes a function there (`pass_function` in the summary) takes that function's set; passing a parameter on to a function that calls it (`pass_param`) passes the obligation on to the callers. Each generic instantiation is its own IR function, so `map` with a pure function is pure and with `print_it` has `console` with no extra rule.
- A parameter may carry a ceiling (`effects_ceiling::write_param(function, slot, mask)`, the attribute `smith-effects` on the parameter; `f: fn(f32) -> f32 @pure` is mask 0): inside the function a call through it counts as the ceiling, and `effects_ceiling::check` makes a `Violation` at each call that passes a function whose set is beyond it (`` `kernel` passes `print_it` to `map`, whose parameter 1 is [[std::pure]], but it has the effects console: print_it -> printf (f:8) ``).
- A pointer that went through memory (a load: a field, a variable) cannot be traced: a call through it, or a loaded pointer passed to a function that calls it, takes the union of the sets of every function of the build whose address is taken and whose function type is the same text, and `unknown` when there is none. A function passed to a callee the build does not define counts as called by it. `dlopen` and generated code are `unknown` as calls of `dlopen`. The Objective-C `objc_msgSend` family of `effects_c` calls an undefined name, so it stays `unknown`.
- Not done yet: a ceiling on a struct field of function type (only parameters carry one in the IR), and the checker writing `write_param` from the source (`fn(f32) -> f32 @pure` in `front/types_fn.smith`).
- Tests: `tests/front_effects_pointers_test.smith` (IR text).

## front::effects_c (`front/effects_c.smith`, #2021, piece 4 of #1939)

- C, C++ and Objective-C through the same pass. `add_source(&g, context, path, &cache)` compiles the file with `smith cc` (`smith c++`, and `-x objective-c` or `objective-c++`, chosen by `language_of`) to unoptimized IR with line tables (`-O0 -gline-tables-only`, `-o -`) and adds its functions to the graph, so a smith function that calls a C function takes its set and the chain names the C line (`caller -> helper (util.c:9) -> printf`). It is false, with the graph unchanged, when the compiler stops. C++ names are the mangled ones (`_Z4makei`).
- `add_runtime(&g, context, &cache)` defines the entry points the libc table lacks, by what they do: `operator new`/`new[]` (all size, alignment and nothrow forms) and `__cxa_allocate_exception` are `alloc`; `operator delete`/`delete[]` are `alloc` (as `free` is in the table); `__cxa_throw`, `__cxa_rethrow` and `std::terminate` are `fails`; `objc_msgSend` and its super, stret and fpret forms are `unknown` (the target is not known; the plugin says the same for a message); `objc_alloc`, `objc_alloc_init`, `objc_allocWithZone` and `objc_opt_new` are `alloc`; retain, release and the autorelease family are pure. The plugin sees none of the C++ ones (it does not look at `new`, `delete` or `throw`), so these are new sets.
- Tests: `tests/front_effects_c_test.smith` with the fixtures `tests/effects_c/` (a smith caller of a pure and of a printing C function, C++ new, delete and throw, Objective-C as IR text, a file that does not compile). Piece 5 adds these cases to the parity run.

## front::effects_ceiling (`front/effects_ceiling.smith`, #2019, piece 2 of #1939)

- `@pure` and `@effects(...)` are ceilings over the graph of `front::effects_pass`, never declarations. `types_attr::ceiling_of(attributes, &mask)` reads one from a list of attributes (`@pure` is the empty set, `@effects(.alloc, .net)` or `[[std::effects(alloc)]]` the listed effects; no attribute is no ceiling). `effects_ceiling::write(function, mask)` puts it in the IR as the function attribute `smith-effects` (the mask in decimal) and `read` gets it back.
- After `effects_pass::solve`, `effects_ceiling::check(&graph, module, &report)` makes one `Violation` for each function of the module whose set goes past its ceiling: the message is the old plugin's (`` `bad` is [[std::pure]], but it has the effects console, globals: bad -> log_it (f.smith:16) -> printf (f.smith:8) ``, `limited to alloc` with a ceiling), at the line of the call that first added an effect beyond it (the earliest among the bits; 0 when the function adds the effect itself, by a write to a global), and `render` adds the note when more than one effect is beyond. A function with no ceiling has no error. A hop's file is the checked module's source file (`LLVMGetSourceFileName`).
- Tests: `tests/front_effects_ceiling_test.smith`.
