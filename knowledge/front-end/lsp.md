# The language server (`front/lsp_server.smith`, #1887)

`smith lsp --smith` is a language server for `.smith` written in `.smith` on this front end (the plan: #1887, with #1377's zero patches). Plain `smith lsp` stays clangd; an editor registers the server per file type, so there is no proxy.
- JSON-RPC 2.0 over stdio with `Content-Length` framing; `lsp_server::handle(body)` is one message in, the framed replies out, which the tests drive with no pipe (`tests/front_lsp_server_test.smith`); `run` (C: `front_lsp_run`) is the loop, one arena reset per message.
- Slice 1 serves `initialize` (full sync), `shutdown`, `exit`, `didOpen`, `didChange` and `didClose`; each open or change answers with `textDocument/publishDiagnostics` from `compile::diagnose(path, source, roots)`: the parser's errors (and, in smith's own syntax, its warnings as severity 2), or the checker's errors when it parsed. Any other request gets -32601.
- Columns are bytes in the line (LSP counts UTF-16 units). Hover (#1892, `front/lsp_hover.smith`): `textDocument/hover` returns the type of the innermost checked expression under the position (`ast::expr_at`, `compile::hover_at`) as markdown with its range; the server keeps the open documents' text by uri (fixed slots) for it. Definition and symbols (#1893, `front/lsp_definition.smith`, `front/lsp_symbols.smith`): `textDocument/definition` finds the declaration of the name under the position in the file, through `q.name` / `q::name` imports (a module, or a C header at the place clang records, #1941) and `from ... import` names (`compile::definition_at`; locals and parameters are not resolved yet), and `textDocument/documentSymbol` lists the file's named declarations flat (`compile::symbols`). Completion (#1894, `front/lsp_completion.smith`, `compile::completion_at`): `textDocument/completion` drops the word being typed (and a `.` before it) from the text so it parses; after a `.` it offers the receiver's visible fields and its methods (the functions of #1793 whose first parameter is the receiver, through one pointer), or the names of a C header when the receiver is `c` or a header alias (with the comment above each, #1941); elsewhere the names `ast::symbols` finds whose scope covers the position (a local only after its declaration). The next slices add methods to the table in `lsp_server::handle`; #1895 makes plain `smith lsp` clangd without patches. Semantic tokens (#2008, `front/lsp_semantic.smith`): `textDocument/semanticTokens/full` and `/range`. The lexer gives keywords, literals and comments (found in the text between tokens), and `ast::symbols` lists what the file declares (functions, types, parameters, locals, fields, variants, modules) with the bytes where each is in scope; a name takes the narrowest scope that covers it, a name after `.` or `::` is a field, variant or method, and a name that nothing declares is a function when called, a type when written with a capital or built in, else a variable. The legend (standard type names, modifiers `declaration`, `readonly`, `defaultLibrary`) is in `initialize`. A file that fails to parse still gets the lexer's tokens, and a lexer error leaves the tokens before it, so highlighting does not flicker while typing. The tokens come from the parsed tree and not the checked one: a name's type is not needed to colour it, and the checker is not run on every keystroke. tree-sitter stays for what editors do without a server (#1977).
