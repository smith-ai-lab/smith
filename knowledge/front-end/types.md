# front::types (`front/types.smith`, #1220 J1a)

The types of the front end and the checker's entry point; the API is the top comment of the file.
- `Ty` is interned in a `Table`: two types are the same exactly when their `TypeRef`s are equal. A record and an enumeration are nominal; every other type is equal by structure. `Ty.kind` is a payload enum (`types::TyKind`, #2673): each kind holds only its own fields (`integer`: `bits`, `is_signed`, `name`; `pointer`, `slice`: `element`, `pointee_const`; `record`: `name`, `owner`, `c_name`, `slots`, `is_union`, `complete`, `affine`; ...), and a reader tests the kind first (`t->kind == .pointer && t->kind.pointer.element`). A read that is the same across kinds (`element_of`, `slots_of`, `bits_of`, `name_of`, `count_of`, ...) is one accessor in `front/types.smith` that has the guard once; it answers a null, an empty list or zero for a kind that has no such field, and a new reader that needs the difference tests the kind itself. A record's fields are set after it is made (`set_fields`, in place: `made->kind.record.owner = ...` under `if (made->kind == .record)`).
- `const` on a pointee, array element or slice element is part of the type; `const` on a variable is `Symbol.is_const`.
- Sizes belong to the target: `layout(&target, t)` takes a `Target`, never the host. `Usize` and `Isize` are the pointer's width.
- `Scopes` is a stack of `Symbol`s (`declare`, `lookup`, `lookup_path`); a name from a C header is declared as `c::name`.
- Records and enumerations are declared first, then typedefs, then fields, signatures and variables, so use before declaration works for records only.
- `types::check(module, options)` returns a `Checked`: the table, the scope, the errors and a side table of expression types (`set_type`, `type_of`), not a field of the ast.
- `options.bodies` is the hook that checks function bodies (`types_decl` fills it). A construct not typed is reported as `not yet typed: <kind>`.
- `typeof` (#1747): `typeof(x)` is the type of the parameter or variable `x` in scope, and a function's parameters are in scope for the ones after them and for its result (`fn larger(a: num, b: typeof(a)) -> typeof(a)`); `typeof(T)` is `T` for a plain type name. Any other operand (`typeof(a + b)`) is typed by `Options.expression`, which `types_decl::options` sets to `types_expr::infer` (types.smith cannot import the expression checker, #1918); without it the operand is `not yet typed`.
- Tuples (#1557): the kind `tuple` is interned by its elements (`tuple_of`), shown `(I32, Bool)`, its slots named `0`, `1`, so `t.0` is a `member`. Named tuples (#1912, piece 1 of #1820): `(count: i32, ms: f64)` is a tuple type whose slots carry the written names (`tuple.names`), `(count = 3, ms = 1.5)` is a `tuple_lit` whose items are `named_arg` nodes; the name is part of the type's identity (names and types in order), `t.count` is a `member`, and the emitter finds its index in the checker's slots. Naming some elements and not others is a parse error.
- `stream::Stream(T)` (#1613) is the type kind `Kind.stream`, interned by `types::stream_of`, shown `stream::Stream(i32)`, one pointer in layout.
- Smith's own syntax (#1512, C5): `Checked.new_syntax` is set around types written there (`Param.is_new`, `variable.is_new`, `FieldDecl.is_new`).
- There the lowercase built-ins (`i8`..`usize`, `f32`, `f64`, `bool`, `char`, `str`, `void`, `type`) equal `I8`..`Usize`, `F32`, `F64`, `Bool`, `Char`, `Str`, `Void`.
- In a function with smith's own syntax the same names are also types inside its expressions: `x.to(bool)`, `sizeof(char)`, a lambda's `fn(q: bool) -> bool: q` (#1960).
- The concepts `int float num signed unsigned pointer` are `concept_type` types (an error as a field type). In today's syntax `char`, `bool` and C type names are errors.
- `[5,3]T` equals `[5][3]T`, `[,3]T` is a slice of `[3]T`, `[,]T` is a `block`, `?T` is the option type, and `Line := []u8` is an alias by substitution.
- A module-level `a := 3` takes `i32` (`f64` for a float literal) from a literal initializer. A field's `is_new` is not read yet (#1531): a field always counts as new.
- A compile-time `if` in a body keeps one branch (#2277), in two places: the target-only form described here, decided before the checker so that a module is checked for each system, and any other condition the compiler computes (`if sizeof(T) == 4:`, a concept, a constant), decided by the checker through `front::eval` (below). The first: an `if` whose condition is about the target (`target.os == .macos`, `target.os != .linux`, `target.static_analyzer`, with `!`, `&&`, `||`, `true` and `false`: what `when::holds` reads, so `target.arch` once #2142 adds it; today's `if constexpr (target::static_analyzer)` too) is replaced by the branch it keeps (an empty block for a missing `else`) before the checker, in `when::live_module`, which copies each function that has one (`ast_clone::clone_decl_choosing`). The branch not kept is neither checked nor emitted, so it may call `__builtin_assume` or name what another system has. Such a module is checked once for each system, as a `@when` is, and an error found on one only says which. `target.static_analyzer` is `false`: the new front end never runs under clang's analyzer. The checker gives the module it checked for the system smith runs on (`Checked.module`), and the driver emits it, and the language server's hover and completion read it. A condition that names `target` and cannot be decided (`target.os == .windows`, `target.static_analyzer || n > 0`) is an error that lists the forms, never a run-time `if`; a local named `target` is not one. A condition of literals alone (`if true:`) is left to the checker. `target.X` outside such a condition, and the facts `assertions`, the sanitizers and the float facts of [the target's facts](../smith-target-facts.md), are values `front::eval` gives (#3039); they are those of smith's own build until a compile's flags reach the front end. One loss against today's front end: there, clang-tidy's analyzer reads `std.contract`'s checks as assumptions (`__clang_analyzer__`); code the new front end compiles never runs under that analyzer, so a contract is no longer an assumption for it.
- Not yet typed: a bit-field, a compile-time or rest parameter. An array length is any integer the compiler computes that is not negative (#3039): `front::types` reads a literal itself and asks `front::eval` for anything else through `Options.length` (a constant, `sizeof(T)`, `target.f32_mantissa_bits`, `countof(fields(T))`, arithmetic on them, `k.SIDE` of a C header); one that is not known is an error that says why ("an array length must be known at compile time: `n` is a variable that can change"). The checker records the value (`types::length_of`) and the emitter and the header writer (`[SIDE * SIDE]`, with the `#include`) use it; the header writer spells one operand or two joined by `+ - * /`.
- No recursion: `resolve`, `layout` and `show` use explicit stacks. Tests: `tests/front_types_test.smith`, golden `tests/front/types/`.

- An applied type's argument written as a value path that names a type (`Result(c.LLVMModuleRef, state.Error)`: the parser reads a lower-case argument as a value) is read as that type (`types::typed_arguments`, #3026); this was the `not yet typed: the applied type` of `front/emit.smith`'s `ModuleResult` that about 74 front files import.
- A C header an imported module binds (`import c <stdio.h>` in `fmt`, read as `stdio.printf`) is seen by that module's generics wherever they are instantiated, and only by them: each `HeaderBinding` keeps the prefix of the module that wrote it (`owner`), and `header_binding_in`, `c_member_name_in` and `binding_declares` look up a name in a scope (the checker's `r->prefix`, the emitter's `instance_scope`) (#3026).
- `format.write` and `format.put` take a C array piece (`char name[64]` is written up to its first zero; another element type as `[a, b]`), #3026.
