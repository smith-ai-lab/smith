# parse_decl (`front/parse_decl.smith`, #1147)

`parse_decl::declaration(p)` reads one declaration and consumes its own trailing `;`; it gives null after an error, with the parser past the bad declaration. `parse_decl::file(p, file)` reads a whole file.
- Reads: prefixes (attributes, `export static extern inline constexpr thread_local`), variables, functions (`constexpr Type T`, `auto... rest`, `...`), `struct`, `union` (bit-fields), plain and payload `enum`, `typedef`.
- Also `import` in three forms, `static_assert`, and `if constexpr (c) { decls } else { decls }` read with an explicit stack of open blocks.
- Anonymous records: an unnamed field `union { I32 a; F32 b; };` is read by `parse_fields` with an explicit stack of open records (16 deep, then an error, #1286).
- An enumerator that is a name alone is a plain value; a variant is a payload only when a type comes before its name (`Circle circle;`, #1267).
- Import alias (A7k, #1353): `import lib::text as tx;` keeps `alias`; `as` is a keyword only right after an import path (`parse_decl::at_as`).
- Imports (#1809): `import a.b.c` / `import a.b.c as x` (and `pub import ...`) are one-line statements that read into an `import_module` declaration, `alias` being `x` (empty when absent) and the path joined by `.` (`parse_import`); `import c <h.h>` / `import cpp <h>` / `import objc <h>` (`as name` optional) read into `import_c` with `language` and `alias`, the default name being the header's file name without the extension (`as` is required when that is not a name); `from a.b import x, y` and `from c <h.h> import x` read into `import_from`, and the checker binds each name in the module (`declare_from_names`; nested imported modules do not bind theirs yet). An `as` that repeats the default name is a warning whose fix removes it. The old `m := import a.b` is gone. `import a::b;` and `import a::b as m;` still read and record a warning that writes `import a.b` / `import a.b as m`; every `::` in a path (`parse_type::path`, an `@a::b` attribute) records `parse::warn_separator`, whose fix writes `.`. `.` before a type name continues a type path after a lowercase name (`build.Build`); `Color.Red` stays a member. `import(a.b).f(1)` as an expression waits for the checker ticket that reads modules as values.
- `Type T` without `constexpr` (A7m, #1357) parses as an ordinary parameter; the checker reports it (N1, #1339: write `constexpr Type T`).
- Globals (#1956): the fixer writes `export T x = v;` as `pub mut x: T = v`, a `constexpr` one as `pub const x: T = v` and a global with no `export` with no `pub` (`mut x: T = v`); a local is a constant (`x: T = v`, `x := v` with no type). After each pass `fix_text` writes the `//` comments as `#` once the text lexes as smith's own syntax, so the next pass does not read fixed text with the old parser (which dropped the `const` of `pub const x: T = v // c`). Test: `tests/front_fix_global_test.smith`.
- C names (#2209): `smith lint --fix` sets `SMITH_FRONT_CIMPORT_FLAGS` the way `smith cc` does (`smith_front_cimport_flags` in `runtime/front_flag.c`: the compiler's resource directory), so the fixer can read the headers a file imports; the checker's fix then writes `c::strlen` (first `c.strlen`) as the namespace of the header that declares it, `string.strlen`. Without the flags clang could not read `<string.h>` (`stddef.h` not found) and the `c.` stayed. Test: `tests/lint_fix_header_test.smith`. A file compiled with `smith cc --front-end=new` also gets the `-I`, `-isystem`, `-D` and `-std=` its entry in `compile_commands.json` (the working folder's, `build/` or `.smith/`) gives it, so `<llvm-c/Core.h>` is read with the `-I<llvm>/include` of the build (#2313; `smith build frontend-coverage` copies the database into its scratch tree). Test: `tests/cc_database_test.smith`.
- C headers through a library and C names no import declares (#2627): the fixer loads the header loader whenever a file imports a module (`imports_header` in `front/fix.smith`), since the library may import the header its types come from; without it `&b.base` of a library struct whose field is a C type had no type, so the checker's `mut b` fix was never made. A name written `c.name` that no imported header declares (C reached it through another header's includes) gets `import c <h>` added before the first import, from a short list of libc headers (`string.h`, `stdlib.h`, `stdio.h`, `unistd.h`, ...) whose declarations hold it, and the next pass writes `h.name`; a name none of them declares keeps the error. Tests: `tests/front_fix_c_headers_test.smith`, `tests/lint_fix_header_test.smith`. The fixer also reads the `-I`, `-isystem`, `-D` and `-isysroot` flags of the file's entry in `compile_commands.json` (`database_flags` in `front/fix.smith`, root, `build/` or `.smith/`), so `<llvm-c/Core.h>` is read and the checker's fixes for `c::LLVM*` calls are made (#2648); a `#if` or `#include` left in a `.smith` source is still an error (`there is no preprocessor`).
- Type-driven fixes (#2648): `front/fix_payload.smith` rewrites a one-field named tuple the checker expected as a payload enum (`kind = .vector((count = c))` for `.kind = {.vector = {.count = c}}`: `(name = ` becomes `.name(`) only when the expected type is a payload enum with that enumerator; `front/fix_array.smith` writes `&xs[0]` for a name or member chain given to a C pointer parameter ("a fixed array never converts to a bare pointer"). `front/fix_bool.smith` writes `1`/`0` for `true`/`false` and `.to(i32)` for a Bool expression given where a C function wants an integer (`LLVMBool`). All three run in `fix::checker_fixes` beside `fix_method`. Tests: `tests/front_fix_payload_test.smith`, `tests/front_fix_array_address_test.smith`, `tests/front_fix_bool_test.smith`. A braced list with no type, one designator and a value, `return {.some = v}`, that the checker types from where it stands as a payload enum with that variant is `.some(v)` (`fix_payload::list_edits`, #3027).
- Text fixes of #2648, run in `fix::typed_fixes` beside the type-driven ones: `front/fix_const.smith` writes `mut ` for a local `name: T = undefined` whose `&name` is taken later in the function (C fills it; a name is constant unless `mut`). `front/fix_chain.smith` (D16) rewrites a one-line `return` or `name := ...` whose top-level `&&` chain has `A == .v` followed by reads of `A.v` into the pattern conjunct (`.v(v) := A && v.f`). A test inside an `if`, `else if` or `while` chain is the checker's when it starts the chain and stays when a conjunct comes before it; a chain with a top-level `||`, a read left of the test, or a local named like the variant stays. `front/fix_guard.smith` writes the binding `.ok(ok) := r else:` for `if r == .error:` whose body leaves (`return`, `continue`, `break`) and never mentions `r`, and `ok` for each later `r.ok` of the block; a name `ok` in the function, or a second guard in it, leaves the site. D19 (`and`, `or`, `not`) is the parser's own warning fix (`symbolic_logic`). The last three write forms the parser may not read yet, so `fix.smith` tries each on a snippet once (`values_take_patterns`, `bindings_take_else`, `places_are_bound`) and writes them only when it parses. `front/fix_place.smith` (D21) writes `if .v(v) := &k:` for `if k == .v:` whose block writes through `k.v.f` (every `k.v` followed by `.field`), and `v.f` for the reads; gated by `places_are_bound`. Tests: `tests/front_fix_const_test.smith`, `tests/front_fix_chain_test.smith`, `tests/front_fix_place_test.smith`, `tests/front_fix_guard_test.smith`.
- What the fixer keeps between processes (#2889): an import that does not parse is mended by its parse errors' fixes alone (`mended_import`, #2561) and its field masks are kept by `fix_zero`, both in the folder `SMITH_FIX_IMPORT_CACHE` names, keyed by the hash of the path and the text. `smith lint --fix` sets that variable itself when the caller has not (`smith_lint_fix_import_cache`, `runtime/front_flag.c`) to `$XDG_CACHE_HOME/smith/fix-imports/<16 hex of smith_self_digest>`, so a second `lint --fix` of a file that imports old-syntax modules reuses their mended text, and a smith with other code reads none of it. The fixer fixes no import (it never writes one), so there is no per-module fixed result to keep. A cache entry never changes a fixed file: a cold and a warm `lint --fix` of the same file write the same bytes. The count sets its own folder per smith (#2586) and is unchanged.
- What the fixer keeps across its passes and files (#2913): each imported module is parsed once per `fix_run` (`read_import_once`), and each C header once per process, in `front::header_table` (#2888's table, shared with `front::compile`), keyed by the header, how it is written, the importer's folder for a quoted header and the flags (the fixer's add `-Iinclude`, `-I.smith/include` and the file's compile-database flags). One `fix_run` is one generation of the table; a lone `fix_text` starts a new one, so a header whose files changed since it was read is read again (test: `tests/front_fix_passes_test.smith`). Before #2913, `fix::load_header` read every header through clang on every checker pass. The checker still declares the import closure again on each pass. That costs about 55 ms per pass in a dev build, because a pass can change the closure: a fix writes `import c <h>` or `import std.x`, the file's own headers are declared before the closure, and a declaration error carries a span in the file. Measured on 4 cores, release build, `smith lint --fix`: `tests/front_fix_test.smith` 13.6 s cold and 6.0 s warm before, 8.6 s and 1.2 s after; `lib/std/text_test.smith` 11.7 s and 4.5 s before, 8.2 s and 1.2 s after.
- Count B (#3027): `/* ... */` comments become `#` lines and `/** ... */` and `///` become `##` doc lines (the ` *` frame dropped). `x := Pair(i32)(a = 1, b = 2)`: a named list after an applied type is its construction. An array of tuples, `T xs[2] = {{1, 1.5f}, {2, 2.5f}}` with `T` a tuple type, is `[(1, 1.5f), (2, 2.5f)]`. A tuple index in parentheses, `(t)[0]`, keeps its `)` (`fix_method::tuple_index_of` ends the edit at the `]`). `if c: T else: U` reads a type before `else` as a value (`ends_value`). In a C `for`, `*c::dirent entry = v` (a qualified type an earlier pass wrote in smith's form) is a declaration, not the dereference `c.dirent.*`: the next pass reads it with smith's own parser once the comments are `#` (`new_pointer_init` in `front/parse_stmt.smith`). Tests: `tests/front_fix_test.smith`, `tests/front_fix_payload_test.smith`, `tests/front_fix_method_test.smith`, `tests/front_parse_concept_name_test.smith`.
- Count B (#3027), later roots: an enumerator of an imported module in today's syntax (`.Closed`) gets its variant list when `tokenize_new` fails (`fix_variants::collect` falls back to `lex::tokenize`), and `smith lint --fix` renames it with the imports the checker read (`fix_variants::rename_all_with`). `countof(try f())` keeps the parentheses of the query (`inside_parentheses` in `front/parse_expr.smith`). A local or parameter named like an imported module (the last segment, or the `as` name) is a shadowing error (owner's decision), so the fixer renames it with a trailing `_` until the name is free in the file (`fix_variants::rename_shadows`, first in `fix_text`): `arena::push(arena, 1)` is `arena.push(arena_, 1)`; fields, globals and the module's own uses stay. The `in` -> `in_` rename leaves an import line alone (`<netinet/in.h>`). A type compared with `==` or `!=` is read as in a cast, so `typeof(x) == char *` is `*mut char` and `const char *` is `*char`. After `name:` (a parameter, a field, a binding) a lowercase type function applied is a type, `o: maybe(usize)`, as in a result (`parse_type::declared`). Tests: `tests/front_fix_shadow_test.smith`, `tests/front_fix_variants_test.smith`, `tests/front_fix_decl_forms_test.smith`, `tests/front_parse_type_call_test.smith`.
- One `--fix` reaches the fixpoint (#2224): the variants are renamed after each file's passes, and a text with an uppercase variant does not parse until then, so the checker's fixes (`mut`, `*mut`) found nothing in the first run and a second `smith lint --fix` gave `std.format` 32 more. `fix_run` now fixes a file again after the rename changed it (`front/fix.smith`), so the second run applies nothing.
- Arrays with no length (#2092): `T xs[_] = {a, b};` is `xs: [2]T = [a, b]`: smith has no `[_]` length (not settled), so the fixer counts the elements of a flat list (`list_length` in `front/parse_decl.smith`); a designated, nested or empty list, or any other `{...}` list on an array, stays a warning with no edit. Test: `tests/front_fix_array_test.smith`.
- Declarations in smith's own syntax (S3, #1444; `:=` since #2316): `a := v`, `a: T = v`, `mut a: T = v`, `const X = v`, `pub mut`, `extern mut`, `pub`, `@attr`, `fn name(a: T, mut b: T, const n: usize, T: type, rest...) -> R { }`.
- Also `struct Name { field: T }` and `enum Name: u8 { low = 2 }`, one member per line with no `;` or `,`. New is told from old by the first one or two tokens.
- Keywords as names (#1770): after `.` a keyword is a member name (`x.module`, `t.type`) and in a struct body a field may be named with one (`module: str`); both positions are unambiguous. A local or parameter named with a keyword is still an error, and `int : 3` stays an unnamed C bit-field.
- A declaration ends with its line; a `;` or `,` there is an error with a fix that deletes it. After an error the parse skips to the end of the line (`recover_line`).
- `parse_decl::at_destructure(p)` and `destructure(p)` read `(q, mut r) := f()` (and the old `let (q, r) = f()`) for the statement parser; `declaration` on one is an error.
- Old declaration forms are warnings with fixes (F2, #1507): `module a::b;` removed, `export` to `pub`, `I32 a = 3;` to `a: I32 = 3`, `R f(A a) {...}` to `fn f(a: A) -> R {...}`.
- Likewise fields and enum members to one per line, `typedef struct {...} N;` to `struct N {...}`, and `[[gnu::x]]` or `[[std::x]]` attributes to `@name`.
- No mechanical fix, so a warning with no edits: a prototype, a parameter with no name, an array suffix of `[]` or `[const :]`, a file-level array with no value or a `{...}` list (#1898), a bit-field, `extern`, a typedef whose tag has another name. An array suffix on a variable, field, parameter or alias moves in front of the type (`I32 xs[3]` is `xs: [3]i32`).
- Errors that name the fix: several names in one declaration, a function-pointer declarator, K&R parameters, implicit `int`, an array with no size, a C keyword that names a parameter (A7q, #1361).
- `__attribute__` is an error at each name (#1348, A7j): `[[std::x]]` where the std set has one (`gnu_to_std`), else "there is no Smith spelling of `format` yet".
- `[[std::inline]]`, `[[std::noinline]]`, `[[std::cold]]` (#1420) are ordinary attributes; `emit` turns them into `alwaysinline`, `noinline` and `cold`.
