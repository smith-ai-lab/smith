# C import (`front/cimport.smith`, `front/cimport_cache.smith`)

Declarations read from C headers become `front::ast` nodes with `from_c` set; the design is [c-header-import](../c-header-import.md).
- `cimport::read` parses a header through clang's C++ libraries at the edge file `shim/cimport.cpp`; what it cannot express is listed with a reason in `not_imported`.
- Each declaration the import builds (function, struct, typedef, enum, constant) carries `Decl.place` (file, line and column: clang's presumed location, the header as written after `#line`) and `Decl.doc` (the comment above it with its `//`, `///` and `/** */` markers taken off, empty when there is none); a struct field and a named enum's item carry the same on `FieldDecl` and `Enumerator`. A comment counts only when it ends on the line above the declaration or on its line (clang gives an enumerator the comment of the one before it). A macro constant's comment is read from the lines above its `#define`. A declaration with no location (a builtin) has none, never an invented one. This is the data hover (#1892), go-to-definition (#1893) and completion (#1894) read; a comment after the declaration on the same line is not kept. The cache stores both and its format version went up for them.
- `cimport_cache` caches the result and is not linked into smith (it needs `std::process`, which `smith prove` would then prove); tests: `tests/front_cimport_test.smith`, `tests/front_cimport_cache_test.smith`. `compile` calls `cimport::read` directly for now: the cache's dependency pass (`shim/cimport_deps.cpp`) crashes in the smith binary (a null vtable in clang's `EndOfMainFile` callback), so it is not used there yet.
- A C struct tag and a function of one name (`struct stat` and `stat()`, #2610): a header binding keeps both under `c::stat` (`types::declare_beside`, a symbol of each kind), and `types::lookup_as(scopes, name, want_type)` picks by position: a type position (`info: stat.stat`, `mem.alloc(stat.stat, 1)`, a field, a pointer) is the struct, a call (`stat.stat(path, &info)`) is the function (`types_expr::named_type` refuses to read a C struct as a construction when a function has its name). The emitter makes a struct held by value inside another C struct first (`st_atim` of `struct stat`) with a stack, and a C union as an array of integers of its size and alignment (`struct sigaction`). The fixer writes `mut info: stat.stat = undefined` for a local `= {}` whose first mention is `&info` as an argument of a C call (`fix_zero::filled_by_call`); with a read before the call it writes `mem.zeroed(stat.stat)` (D10, #2627: `std.mem.zeroed(T)`, a zeroed value of `T`; the fixer adds `import std.mem`), since the construction `stat.stat(st_dev = 0, ...)` would read as the call. Tests: `tests/front_e2e_test.smith`, `tests/front_fix_zero_test.smith`.
- `c::` names (#1762): `import <h>;` or `import "h";` makes `compile` read the header (flags from `$SMITH_FRONT_CIMPORT_FLAGS`, which `smith cc --front-end=new` sets to the resource directory and the SDK) and the checker (`types::Options.headers`, `types_decl::check_module_headers`) declares each declaration as `c::name`, a type of the header naming another by `c::` too. A declaration the checker cannot type is left out, so its use says `` `c::x` is not declared by any C header this file imports``. The enumerators of an enumeration are constants `c::red` of the enumeration's type. The emitter calls a `c::` function through the checker's type of it (`emit_call::c_function`; variadic calls pass their extra arguments after C's default promotions), emits a constant by its initializer, makes a record the first time a type names it (fields the emitter has no type for leave it opaque), and a string literal given to `const char *` is the address of its bytes. After `import c <h>` the header is a namespace (#1678): it binds its file name (`stdio`, or the `as` name), and `stdio.f(x)`, `stdio.CONST` and a type `*stdio.FILE` are the header's `c::name`, so one entity however many bindings reach it (`types::HeaderBinding`, `types::c_member`, the emitter's `c_callee`, `c_constant` and `type_of`); a name the header does not declare, or `c.f` with no binding `c`, is an error, and `smith lint --fix` mends the second to the binding that declares the name (`fix::checker_fixes` reads the headers). `import cpp` and `import objc` say they are not imported yet; a lowercase type after the dot (`stdio.size_t`) waits for the type parser, which takes only a capitalized name after `.`. Not yet: a typedef or enum no declaration uses (cimport reads the types the declarations name), a union, a bit-field, a function pointer, a struct that holds another by value.
