# smith::net

`lib/smith/net.smith` (skill smith-net) is `io::Io`'s net part without the `Io` value (issue #240, phase 1), and adds what io had no call for: `listen` and `accept`. It is additive: `io` is unchanged until the migration phases. A child's stdio pipes belong to smith::process (#483); `net` is TCP and TLS only.

- **A handler of its own.** `SmithNetHandler` (`include/smith/handlers.h`) has `connect`, `listen`, `port`, `accept`, `read`, `write`, `close` and `read_within` (a read with a deadline: -1 with `ETIMEDOUT`; a handler that leaves it null gets `read`). No libc function is interposed (a socket is a descriptor the files handler would take): the module calls the members itself, so a thread with a handler never opens a socket, and none set is the real network. A connection or listener is an id the handler chooses; the module's `Connection` keeps the descriptor of a real one. The setter returns the previous handler.
- **The real network.** Plain TCP is POSIX sockets, blocking, on both systems (`getaddrinfo`, every address tried; SIGPIPE never reaches the program). TLS is the platform's stack, loaded with `dlopen` on the first TLS connect so a program that never connects pays nothing: Network.framework on macOS (its callbacks run on a serial queue and signal a semaphore the call waits on) and OpenSSL 3 on Linux (over the blocking socket). The system's trust decides and nothing turns the check off. A failed certificate is its own `Error` (`Expired`, `NotYetValid`, `WrongHost`, `Untrusted`, `BadCertificate`); Network.framework's TLS-domain status names only an expired or not-yet-valid certificate (checked by hand: wrong.host.badssl.com gives the generic -9808 rejection), so every other rejection is `BadCertificate` there; a finer cause would need a `sec_protocol_options_set_verify_block` running `SecTrustEvaluateWithError`, not built. A TLS server is out of scope here: it is the HTTP server's decision (#334).
- **Errors.** What the world answers is a `net::Error` value. A bug is a checked failure (the panic-line audit of #240): a connection closed twice or used after its close (EBADF), a read into an empty buffer, and a fake that would block for ever. The ECANCELED of a send after close (io) is a use after close here.
- **Memory.** The calls take the caller's buffers and allocate nothing, except that a macOS TLS connection keeps a small block from `mem::alloc` for its callbacks (the caller's region, never freed one object at a time, #439) and the fake's recordings. A test installs an arena.
- **The fake** (`net::fake()`, `fake_add`) replaces io's fake servers: a script answers the first connect to its host and port that no connection has used, and a `fake` also listens, pairing a client with the connection `accept` returns through in-memory buffers, so server and client run in one test. Id spaces: connections below 100, listeners from 101.
- **Names.** The C functions are `smith_network_*` and the types `SmithNetwork*` while io owns `smith_net_*` and `SmithNet*`; the rename belongs to the deletion of io.
- **Completion-shaped.** A connection is a descriptor or handle in the module's struct, and each call is one step (start, then wait) of an operation, so the async forms of #241 can be added beside the blocking ones without changing them.
- **Not here.** Async connect, send and receive (`io::Op`, `io::run`) wait for the task runtime (#241); a TLS server (certificates and keys) is not in io either and is not built; the Linux backend was written from io's and is not run in this change (no Linux machine).
