# smith test --changed runs the tests a change can reach

Every red batch on the train was a fault in a test the author did not know to run. `smith test --changed [--base <ref>] [--dry-run]` (`runtime/changed.c`, issue #441) names the tests a diff can reach by walking the **reverse dependency graph** from the changed files. No test declares anything: what a test depends on is found from the sources.

**The diff.** The files that differ from `<ref>` (default: where the branch left `origin/main`, else `main`), the working tree and untracked files included. `--dry-run` prints each selected test file with the reason and the `--test` list it would run, and runs nothing. `--list [<base> [<head>]]` (issue #506) prints the selection alone on stdout, one entry per line (a test name, `module::`, or `*` for every test), for a script that asks what a pull request would select; with a `<head>` the changed paths are those of `git diff base head`, untracked files left out, while the sources and records are still read from the working tree. A run passes `--test a::,b::` to the runner, which takes comma-separated substrings (`lib/smith/test.smith`); smith's own `test-units` forwards the arguments of `smith test` to its runner (`build.c`, `smith_args`). It prints the tests it selected, so a miss (a test the train rejected that `--changed` left out) can be counted.

**The graph.** Every `.smith`, `.c`, `.h`, `.cpp`, `.hpp` and `.m` file is scanned for `module`, `import` and `#include` lines; each names a project file by the end of its path (`a::b` is `a/b.smith`, `<smith/x.h>` is `smith/x.h`), and the files that import a changed file, transitively, are changed too. No build is needed, so a replay over old commits needs none. A `*_test.smith` or `*_test.c` file is selected when it is changed or reached this way, or when it runs smith (`scratch::`, `SMITH_SELF`) and a source of smith changed (smith.c, `runtime/`, `lib/`, `include/`, `templates/`, `scripts/`, ...): a test that starts smith depends on all that is compiled into it, the flags of module files and the build conventions included.

**Unknown means run it.** A changed path the graph does not know (not a test, not part of smith, and no file imports or includes it: a new `.c` nothing includes, a fixture read as data, a text file) selects every test, so a change the graph cannot follow is never skipped. The files that select every test too: `patches/`, `shim/` and `tests/units/`, except `shim/hook.cpp`, which a run that records counts like `smith.c` and `runtime/lang*`: those are judged by the functions the records say ran (#638), and print why when no record names them (a new file, or one no test ran). Conservative is fine.

**Data a test names (#456).** A changed path that is data (not a test, not part of smith, not Markdown, imported by nobody: a workflow, a corpus, a fixture, a prove input) selects the test files whose source names its file name (when it has an extension) or a folder it is in (`.github/workflows`, `tests/smith-fmt`), like the Markdown rule; `.github/` is no longer on the whole-suite list: a workflow no test names is CI's own configuration (CI running it is its test) and selects no test, as does a `.profraw` or `.profdata`. Any other data file no test names runs every test.

**Inside one file (#456).** Two files are read by function. (1) A file another file `#embed`s (`runtime/build_runtime.c`, embedded into `smith.c`) reaches the functions of the includer that use the embedded array (`smith_build_prepare`): the records that ran one are stale, the rest are not, so it selects the tests that build a project, not every test. A use outside a function keeps the file unplaced (every test runs). (2) `build.c`, which every record has as an input (the input alone no longer makes a record stale): its `git diff -U0` is mapped to the functions it touches. A change outside any function, in a function registration calls (`build`, `build_programs`, `build_units`) or in a task's `.test` step selects every test. A change only in functions that run when a task of no `smith test` runs (a step `.run = F` without `.test` or `.outputs`, whose task name appears once in the file, and what only those functions call) selects the tests whose source names the function or the task: no test can run that task unless it says so.

**No size turns a selection into `*`.** The filter and each file's names grow in memory mapped from the OS (`SmithChangedBuffer`). Only when the names are longer than one runner argument (12000 bytes: a verb's arguments travel to build.c as -DSMITH_ARGS in 16384 bytes, and a longer one used to stop the run with "the arguments are too long") does a run say so and run every test; `--list` prints them all. `--list` and `--dry-run` print without `-v`, with a summary line on stderr, and a file the records select shows how many of its tests.

**Cheapest first (#506).** `--cheapest-first` writes `.smith/costs.tsv` from the `cpu` line of each record and passes it as the runner's `--costs` with `--cheapest` (the runner's own order for `--costs` is the heaviest first): the selected tests start unknown first, then by cpu seconds, so a wide selection under `--fail-fast` and a time limit still meets the cheap breakage first.

**Markdown is placed.** A changed `.md` file (a skill, a concept, the README) is not unknown: it selects the test files whose source names `.md` (skills, readme and docs tests, goldens of Markdown), "it reads Markdown", and no more (#506).

**Records first.** When per-test records exist (`.smith/records`), a test that runs smith is selected when its record is stale instead of by the graph's "all of smith" edge, and the graph decides whatever no record names: [coverage-selection](coverage-selection.md).

**What it weighs.** The runner's `--stats` ends with a line `cpu<TAB>seconds<TAB>name` for each test, its CPU time with the processes it waited for, then `wall<TAB>start<TAB>seconds<TAB>name` (when it started and its wall time, for the busy workers over time); the train's full run can publish them, so the share of CPU a selection runs is measured, not guessed. Recording what tests read at run time is not built; it becomes an issue if misses are more than rare.
