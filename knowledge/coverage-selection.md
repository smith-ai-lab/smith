# Records select the tests a change reaches

The build graph of [changed-tests](changed-tests.md) sees a test that runs smith (`scratch::`) as depending on all of smith, so `--changed` selected 83% of the tests on average. The same is true of a user's end-to-end tests (a CLI's tests run the CLI). A record of what each test actually executed answers it, with no git and no commit keys (issue #456, owner 2026-10-26: "fully general and not coupled to the compiler").

**The record** is `.smith/records/<test>.rec` (or `$SMITH_RECORDS_DIR`), one file per test, rewritten whenever the test runs under coverage (`runtime/record.c`). Text, a tab between fields: `result pass|fail`; `fn <file> <name> <lines> <hash> <first line hash>` for each function the test executed (the hash is 64-bit FNV-1a of the function's lines, and the function is found again by its first line, so moving it changes nothing); `outside <file> <hash>` (the file's code at brace depth 0 that is not a function's opening line: globals, macros, declarations; the lines inside a global's braces are not seen); `input <path> <hash>` (a header the executed files include, and `build.c`); `read <path> <hash>` (files read, see below).

**A test reruns** when its last result failed, a function it executed is not found as it was, an outside or input or read hash differs or the file is gone, or it has no record (a new test). Otherwise it is unchanged. A record from anywhere is valid wherever its hashes match, so shared records are just files in the folder.

**Selecting.** `smith test --changed` reads the records (the folder, else the project's task `coverage-fetch` if its `build.c` defines one: smith itself never runs `gh`), and for a test file that runs smith selects the tests with a stale record or none, with their exact names in `--test`; a test file that imports a changed module is still selected by the graph. **A changed file no record names** is placed by the build graph: the tests whose recorded program (the files they executed, children included) imports or includes it, transitively, are selected, with the reason. **If the graph does not place it either (nothing imports it), every test runs:** unknown means run it. Nothing here is specific to smith: smith's own tests fall out of it because their records name the files of the smith program they ran. `build.c` and the other whole-suite files select every test as before. With no records the graph decides, and the message says so.

**Collecting (the train only, for now).** `COVERAGE=1 smith build` compiles `smith.c` and the linked `.smith` libraries with `-fprofile-instr-generate -fcoverage-mapping`. With `COVERAGE=1`, `test-units` gives the runner `SMITH_COVERAGE_DIR` (`.smith/coverage`), `SMITH_COVERAGE_TOOLS` (the LLVM's `bin`) and `SMITH_COVERAGE_BINARY`. The runner (`lib/smith/test.smith`, `coverage_begin` and `coverage_end`) sets `LLVM_PROFILE_FILE=<dir>/raw/<test>/%p.profraw` before each test, so every process the test starts, `scratch::` ones included, writes there; when the test ends it runs `smith test --coverage merge <test> <pass|fail>` (`runtime/coverage.c`): `llvm-profdata merge -sparse`, `llvm-cov export -format=lcov`, the record, and the raw files are deleted (a full run is 11 GB raw). A local plain `smith test` records nothing and is unchanged. Recording under `--changed` for any project needs the driver to instrument the project's own programs and is not built yet.

**The table and the report (CI).** `smith test --coverage join <dir> <commit> <table>` makes `coverage.tsv` (a bit per function for each test, and the lines counted and run), and `report <table> <base> <out>` writes `coverage-report.txt`, tab separated: first `coverage`, the commit, `lines`, covered, counted, `functions`, ran, total; then one `uncovered`, file, line, function for each line of `git diff <base>..HEAD` that coverage counts and no test ran; last `changed`, the counted lines changed, how many are uncovered. It flags; it never rejects. The train's check uploads `coverage-<sha>` (table and report) and `smith-records` (the records, 7 days); a clone brings the records in with its `coverage-fetch` task.

**Reads.** The files a test reads (fixtures, read by its children through libc or io) are not recorded yet: `io::Io` is going away (#240), so the recording will go through the files module or an effect handler the runner installs (#239), after it lands. Until then the conservative rule above covers a changed file no record names; a fixture a record does name through no executed function is missed.
